# 仓库APP-打包复核简易需求文档

> 版本范围说明：本文档覆盖打包人员在仓库APP中查看待打包复核任务、按订单合并多张揽货单、扫码复核实际已揽商品、完成打包并流转至待发货的流程。不涉及揽货作业本身、退货/换货处理、订单拦截处理任务详情、物流发货交接。

---

## 1. 基础信息

| 项目 | 内容 |
| ---- | ---- |
| 功能名称 | 打包复核 |
| 所属模块 | 仓库APP > 打包复核 |
| 页面定位 | 打包人员对揽货员放置到打包台的商品进行订单级扫码复核并完成打包 |
| 页面编码 | `WMS-APP-003` |
| 适用端 | 仓库APP（仓库作业端） |
| 适用角色 | 仓库打包人员 |

---

## 2. 业务说明

揽货员完成揽货后，将商品放置到打包台。打包人员进入「打包复核」任务，按订单对实际已揽商品进行扫码复核。复核完成后点击「完成打包」，订单状态流转至「待发货」。

当前打包支持**合单发货**模式：一张订单可能因履约库房多个而拆分成多张揽货指令。打包复核以订单为单位，将该订单下多张已完成揽货的揽货单汇总到同一个打包任务中，由打包人员统一复核、统一完成打包。

若订单存在多张揽货单，揽货员每完成一张揽货指令后即可将商品放置打包台；但只有当该订单所有揽货指令均完成揽货后，打包人员才可进行订单级扫码复核并完成打包。

---

## 3. 功能描述

- 支持在仓库APP进入「打包复核」页面，查看待复核打包任务。
- 支持按订单号 / 联系人 / 任务ID 搜索打包任务。
- 支持按配送类型切换任务：即时配送 / 物流发货。
- 支持按时间排序，优先处理更早下单或更早到台的订单。
- 支持点击任务卡片或「复核详情」进入打包复核详情页。
- 支持从列表底部「打包复核」扫码入口直接扫码进入对应订单复核任务。
- 打包复核详情页按订单展示基础信息、收货人信息、揽货单切换区、复核商品列表。
- 复核商品列表只展示实际已揽货商品，不展示退货、换货、未揽货或取消商品。
- 商品按揽货指令分组展示，可切换「全部」或指定「揽货#N」查看。
- 打包人员可直接扫商品条码复核；每扫一次，匹配商品的复核数量 +1。
- 当某商品复核数量达到已揽货数量时，系统自动标记该商品复核完成。
- 所有商品均复核完成后，点击「完成打包」提交。
- 完成打包时若订单已被拦截，系统禁止提交并提示：「订单已拦截，无法继续打包，请前往拦截订单处理任务」。

## 7. 扫码复核规则

| 场景 | 系统表现 |
| ---- | ---- |
| 扫到列表内商品条码 | 对应商品复核数量 +1 |
| 复核数量达到揽货数量 | 商品自动打勾，状态变为「已完成」 |
| 多个揽货单存在相同商品条码 | 优先匹配当前选中的揽货单；在「全部」页签下按未完成复核数量从前到后匹配 |
| 扫码次数超过揽货数量 | 不再累加，提示「该商品已完成复核」 |
| 扫到不属于当前订单的商品 | 不累加，提示「商品不在当前打包复核任务中」 |
| 扫到订单号 / 任务ID | 若在列表页扫码，进入对应打包复核详情；若在详情页扫码，校验是否为当前订单 |

> 复核数量不得超过揽货数量。打包复核只核对实际已揽货商品，不新增退货、换货或替代商品。

## 9. 完成打包校验与提交

| 场景 | 系统表现 |
| ---- | ---- |
| 所有揽货单均完成、所有商品均复核完成、订单未拦截 | 提交成功，任务状态变为「已打包」，订单流转至「待发货」 |
| 存在揽货单未完成揽货 | 禁止完成打包，提示「订单仍有揽货单未完成，请等待全部揽货完成后再打包」 |
| 存在商品未完成复核 | 禁止完成打包，提示「还有商品未完成复核，请核对后再完成打包」 |
| 订单已被拦截 | 禁止完成打包，提示「订单已拦截，无法继续打包，请前往拦截订单处理任务」 |
| 网络异常或提交失败 | 保留当前复核进度，提示失败原因并支持重试 |

## 10. 任务状态流转

| 状态 | 触发条件 | 说明 |
| ---- | ---- | ---- |
| 待打包复核 | 订单所有揽货指令完成揽货，生成打包复核任务 | 进入打包复核任务池 |
| 复核中 | 打包人员首次扫码或手动调整任一商品复核数量 | 表示打包复核已开始 |
| 已打包 | 点击「完成打包」且校验通过 | 订单进入待发货 |
| 拦截处理中 | 完成打包时订单已被拦截 | 打包复核不可继续，需转拦截订单处理任务 |

状态流转：`已揽货` → `待打包复核` → （首次扫码/操作） → `复核中` → （完成打包） → `已打包` → `待发货`

## 11. 关键业务规则

1. **订单级合单打包**：打包复核以订单为单位，不以单张揽货单为最终提交单位。
2. **多揽货单到齐后复核**：订单存在多张揽货单时，必须等待所有揽货单完成揽货后，才可完成打包。
3. **只复核实际已揽商品**：商品列表仅展示实际已揽货商品，不展示退货、换货、未揽货或取消商品。
4. **复核数量上限**：复核数量不得超过揽货数量；超出时提示商品已完成复核。
5. **扫码自动完成**：每扫一次商品条码，复核数量 +1；达到揽货数量后自动标记完成。
6. **同条码分配规则**：同一订单多张揽货单存在相同条码时，优先当前揽货单，其次按未完成复核数量顺序分配。
7. **完成打包强校验**：存在未完成揽货单或未完成复核商品时，不允许完成打包。
8. **拦截订单优先**：完成打包提交时实时校验订单拦截状态；若已拦截，禁止提交并引导前往拦截订单处理任务。
