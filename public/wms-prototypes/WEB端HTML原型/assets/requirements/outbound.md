# WMB-出库管理简易需求

## 1. 基本信息

- 功能名称：出库管理
- 所属系统：WMS\_WEB端 / 揽货 APP
- 页面编号：`WMS-WEB-OUT01`
- 所属模块：出库管理
- 文档定位：1.0 简化版 · 自营业务
- 适用范围：销售出库（揽货 APP 发货）、调拨出库、报损出库、其他出库（WEB 手动出库）
- 版本说明：1.0 版本中，**出库单不再驱动揽货全流程**。揽货、复核、打包等仓内作业在揽货 APP 中完成，揽货 APP「完成发货」时由系统**自动生成出库单**，同时解冻原锁定库存并真实扣减实物库存。WEB 端额外提供「新建出库单」功能，用于覆盖无 APP 作业流程的其他手动出库场景。

> 本文档仅说明三件事：**出库单的新建规则**、**出库单详情**、**出库库存扣减需求**。完整出库作业流程（揽货接单、库存锁定、揽货、复核、发货等）见《00 出库管理简易需求-自营版》，本版本不再重复。

***

## 2. 核心结论

### 2.1 出库单的两种生成方式

| 生成方式         | 触发点             | 适用场景                         | 库存动作                   |
| ------------ | --------------- | ---------------------------- | ---------------------- |
| **APP 自动生成** | 揽货 APP「完成发货」    | 销售出库等已走揽货/复核/发货作业的订单         | 解冻原锁定库存 + 真实扣减实物库存     |
| **WEB 手动新建** | WEB 端「新建出库单」并提交 | 调拨、报损、样品、赠品、盘亏等无 APP 作业流程的出库 | 直接扣减可用库存与实物库存（一般无前置锁定） |

### 2.2 WMS 管理对象

| 对象   | 主键/编码      | 管理口径   | 作用                           |
| ---- | ---------- | ------ | ---------------------------- |
| 出库单  | 出库单号       | 出库业务主单 | 出库结果的记录凭证，承接销售、调拨、报损、其他等出库来源 |
| 出库明细 | 出库单号 + SKU | 出库商品明细 | 记录每个 SKU 的出库数量、批次、效期及实际扣减数量  |
| 出库流水 | 流水号        | 库存变动记录 | 出库单生成后为每条明细生成「解冻」「扣减」库存流水    |

### 2.3 核心规则

1. **出库单是出库结果的记录单**，不是揽货作业的驱动单。揽货、复核、打包、发货在揽货 APP 中完成。
2. 揽货 APP「完成发货」时，系统自动生成出库单，并将明细数量真实扣减实物库存。
3. APP 发货生成的出库单，针对**原已锁定库存**先解冻、再扣减实物库存，净效果为实物与锁定同步减少。
4. WEB 端「新建出库单」用于覆盖其他手动出库场景，提交后直接扣减库存。
5. 出库扣减后不允许出现负库存；可用 / 实物库存不足时阻断提交。
6. 出库单一经生成即为已完成结果单，明细与流水不可撤销，仅支持通过反向出/入库单据修正。
7. 库存口径统一为：**可用 = 实物 − 锁定 − 冻结**（与库存中心一致）。

***

## 3. 业务目标

1.0 版本出库管理以「**结果记录 + 库存准确**」为核心目标。一方面把揽货 APP 的发货动作沉淀为标准出库单并真实扣减库存，保证账实一致；另一方面通过 WEB 端「新建出库单」补齐调拨、报损、样品、赠品、盘亏等没有走 APP 揽货流程的手动出库需求，使所有出库行为都有单据和流水可追溯。

## 6. 状态流程

### 6.1 出库单状态

| 状态   | 含义                | 适用来源      | 规则            |
| ---- | ----------------- | --------- | ------------- |
| 草稿   | WEB 端已创建、尚未提交     | 仅 WEB 手动单 | 可编辑全部字段、可取消   |
| 提交中  | 已提交 / 已发货，系统处理库存中 | APP + WEB | 短暂过渡态，前端展示加载态 |
| 已完成  | 库存扣减成功            | APP + WEB | 只读，可查看明细和流水   |
| 已取消  | 草稿主动取消            | 仅 WEB 手动单 | 保留记录，不参与库存操作  |
| 出库失败 | 提交后库存写入异常         | APP + WEB | 记录失败原因，可重试    |

> APP 自动生成的出库单不经过「草稿」，发货成功即直接进入「提交中 → 已完成」。

### 6.2 状态流转图

```
【APP 发货】完成发货 ──→ 提交中 ──→ 已完成
                              └──→ 出库失败（可重试）

【WEB 手动】新建
   └─→ 草稿 ──→ 提交中 ──→ 已完成
         │           └──→ 出库失败（可重试）
         └─→ 已取消
```

## 7. 关键流程

### 7.1 揽货 APP 完成发货 → 自动生成出库单

1. 销售订单/发货指令在前置环节已对相关库存执行**锁定**（可用 ↓、锁定 ↑、实物不变）。
2. 揽货员在揽货 APP 完成揽货、复核、打包后，点击「完成发货」。
3. 系统以本次实际发货的 SKU、批次、数量为准，**自动生成一张出库单**（出库类型默认销售出库），并带入来源单号、仓库、揽货人、发货时间。
4. 系统对出库明细逐行执行库存动作：
   - **解冻锁定**：释放该明细前置锁定的库存（锁定 ↓）。
   - **扣减实物**：按实际发货数量扣减实物库存（实物 ↓）。
   - 净效果：实物库存与锁定库存同步减少，可用库存不变（因可用在锁定时已扣减）。
5. 为每条明细生成「解冻」和「扣减」两类出库流水。
6. 全部明细处理成功后，出库单状态置为「已完成」。
7. 若实际发货数量与锁定数量不一致（少发/多发），按第 10.3 节规则处理剩余锁定或补扣库存。

### 7.2 WEB 端「新建出库单」→ 手动出库

1. 仓库管理员在出库单列表点击「新建出库单」，进入新建表单页。
2. 填写基本信息：出库类型（调拨/报损/其他）、出库仓库、来源单号（可选）、备注（可选）。
3. 在商品明细区，扫描商品条形码或手动添加商品行；条码命中后自动填入 SKU 编码、商品名称、规格、单位，操作人填写出库数量、批次（可选）。
4. 重复步骤 3，直至所有出库商品均已添加。
5. 核查无误后点击「提交出库」。
6. 系统逐行校验（见第 10 节），校验通过后执行库存扣减：
   - 手动单一般**无前置锁定**，直接扣减**可用库存与实物库存**（可用 ↓、实物 ↓）。
   - 若该明细存在前置锁定（如调拨已锁库），则按 8.1 的「解冻 + 扣减」逻辑处理。
7. 每条明细生成出库流水，出库单状态置为「已完成」。
8. 若任一行写入失败，回滚本次出库并置为「出库失败」，记录失败原因。

### 7.3 出库库存扣减逻辑（核心）

库存维度统一为「仓库 + SKU + 批次号」，批次为空则按「仓库 + SKU」聚合。

| 场景                  | 前置锁定 | 库存动作                     | 流水类型    |
| ------------------- | ---- | ------------------------ | ------- |
| APP 发货生成出库单         | 有    | 锁定 ↓（解冻） + 实物 ↓（扣减），可用不变 | 解冻 + 扣减 |
| WEB 手动出库（无锁定）       | 无    | 可用 ↓ + 实物 ↓              | 扣减      |
| WEB 手动出库（有锁定，如调拨预锁） | 有    | 锁定 ↓（解冻） + 实物 ↓（扣减）      | 解冻 + 扣减 |

扣减约束：

```
扣减后 实物库存 ≥ 0   且   可用库存 ≥ 0
```

任一约束不满足则阻断提交（手动单）或转「出库失败」（APP 单），不允许出现负库存。

## 9. 规则要求

### 9.1 出库单规则

- 出库单号由系统自动生成，格式：`OUT-YYYYMMDD-NNNNNN`，全局唯一。
- 出库单需标记「生成方式」（APP 自动生成 / WEB 手动新建）以便区分来源。
- APP 自动生成的出库单不经过草稿，直接进入提交中。
- WEB 手动单草稿状态可编辑全部字段；已完成、已取消的出库单只读。
- 提交时商品明细不得为空，至少包含一行。
- 同一来源单号 + 同一发货批次重复触发时按幂等处理，避免重复生成出库单与重复扣减。

### 9.2 扫码与商品行规则（WEB 手动单）

- 一次扫码对应新增一行，不自动合并相同 SKU；如需合并由操作人手动处理。
- 出库数量为必填，正整数，最小值 1，不支持小数。
- 出库数量不得超过该「仓库 + SKU + 批次」的当前可用库存。
- 条形码长度限制：6–20 位数字或字母数字组合。
- 商品档案未维护的条码，允许手动填写 SKU 编码和商品名称后出库。

### 9.3 库存扣减规则（核心）

- 库存以「仓库 + SKU + 批次号」为最小颗粒度聚合，批次为空则按「仓库 + SKU」聚合。
- **APP 发货生成的出库单**：先解冻该明细前置锁定库存（锁定 ↓），再扣减实物库存（实物 ↓）；可用库存不变。
- **WEB 手动出库（无前置锁定）**：直接扣减可用库存与实物库存（可用 ↓、实物 ↓）。
- **WEB 手动出库（有前置锁定）**：按「解冻 + 扣减」处理。
- 出库扣减后实物库存与可用库存均不得小于 0，否则阻断或转出库失败。
- 实际发货数量 < 锁定数量（少发）：扣减实际发货数量，剩余锁定数量按规则解冻回可用库存。
- 实际发货数量 > 锁定数量（多发）：超出部分需校验可用库存是否充足，不足则阻断；充足则一并扣减。
- 每条明细对应生成「解冻」「扣减」库存流水，流水一经生成不可删除。

### 9.4 出库明细规则

- 出库明细随出库单生成/提交成功后生成，与出库单一一对应。
- 出库明细不可单独编辑，如需纠正需通过反向单据（退库/库存调整）处理（后续版本）。
- 出库明细支持按出库单号查询和导出。

## 10. 校验要求

| 校验项    | 触发时机     | 校验规则              | 错误提示              |
| ------ | -------- | ----------------- | ----------------- |
| 出库类型   | 提交时（WEB） | 不可为空              | 请选择出库类型           |
| 出库仓库   | 提交时（WEB） | 不可为空              | 请选择出库仓库           |
| 商品明细   | 提交时      | 至少有一行有效明细         | 请添加至少一条出库商品       |
| 出库数量   | 实时 + 提交时 | 正整数，最小值 1         | 出库数量必须为正整数        |
| 可用库存   | 提交时（WEB） | 出库数量 ≤ 当前可用库存     | 出库数量超过可用库存，剩余可用 X |
| 实物库存   | 扣减时      | 扣减后实物库存 ≥ 0       | 库存不足，无法出库         |
| 条形码格式  | 扫码后实时    | 6–20 位            | 条形码格式不正确          |
| SKU 编码 | 提交时      | 不可为空（条码未命中时需手动填写） | SKU 编码不能为空        |

## 11. 异常场景处理

| 异常场景             | 系统处理                                |
| ---------------- | ----------------------------------- |
| 同一发货/来源单重复触发出库   | 按来源单号 + 发货批次幂等处理，不重复生成出库单           |
| APP 发货数量与锁定数量不一致 | 按 10.3 少发/多发规则处理剩余锁定或补扣库存           |
| 条形码无法识别（WEB）     | 插入空行并提示「条码未找到」，操作人手动填写 SKU          |
| 出库数量为 0 或负数      | 阻断提交并高亮错误行                          |
| 出库仓库未选择（WEB）     | 阻断提交并提示                             |
| 明细为空             | 阻断提交并提示「请添加至少一条出库商品」                |
| 可用 / 实物库存不足      | 阻断提交（WEB）或转「出库失败」（APP），不允许负库存       |
| 库存写入失败           | 回滚本次出库全部明细，状态变为「出库失败」，记录失败原因，支持重新提交 |
| 网络中断（WEB）        | 数据已保存为草稿，提示「网络异常，数据已自动保存为草稿」        |

## 12. 验收要点

- 揽货 APP「完成发货」后能自动生成对应出库单，出库单标记为「APP 自动生成」。
- APP 发货生成出库单时，能解冻原锁定库存并真实扣减实物库存，可用库存保持不变。
- WEB 端能「新建出库单」，选择出库类型、仓库、来源单号，并扫码/手动添加商品行。
- WEB 手动出库提交后，能正确扣减对应「仓库 + SKU + 批次」的可用库存与实物库存。
- 出库数量超过可用库存时能阻断并提示。
- 出库扣减后不会出现负库存。
- APP 发货数量与锁定数量不一致时，剩余锁定能正确解冻或超出部分能正确校验。
- 出库单详情页能展示基本信息、出库明细（含解冻数量、实扣数量）和出库流水（解冻/扣减）。
- 能在列表页按出库类型、出库状态、生成方式、仓库、出库单号、来源单号、SKU 编码查询。
- WEB 手动单草稿能编辑、取消，出库失败能查看原因并重新提交。
- 每条出库明细均能生成对应的解冻与扣减库存流水，且流水不可删除。

## 13. 前端 UI 规范

### 13.1 页面导航方式

| 操作 | 打开方式 |
| --- | --- |
| 点击出库单号 / 查看详情 | 右侧滑入抽屉（宽度 860px），不离开列表页 |
| 点击新建出库单 | 整页跳转（替换当前视图） |
| 详情抽屉内点击编辑 | 整页跳转到编辑页 |
| 提交 / 取消成功后 | 关闭抽屉，列表刷新当前行 |

### 13.2 列表页

- 筛选区 + 统计卡片 + 表格三段式垂直排列
- 统计卡片横排 4 个，点击可联动筛选对应状态
- 表格行悬停显示操作按钮（不占列宽），操作项按出库单状态动态显示
- 空状态（筛选无结果）：居中插图 + 说明文案 + 清空筛选按钮

### 13.3 新建 / 编辑页

- 整页视图，顶部固定表头区（回退按钮 + 页面标题），底部操作栏为 inline 布局，不使用 fixed 定位
- 基本信息、商品明细两个区块卡片垂直排列
- 商品明细表格超出屏幕高度时页面整体滚动，不在表格内部产生滚动条
- 客户端校验失败：行内红色边框 + 提示文字，同时在底部操作栏上方展示错误摘要条，禁止使用 alert 弹窗

### 13.4 详情抽屉

- 从右侧滑入，宽度 860px，左侧列表页保持可见（非全屏遮罩）
- 抽屉顶部区域固定不动：出库单号 + 状态 Badge + 操作按钮组
- 内容区可滚动；Tab 栏（出库明细 / 出库流水）在随页面滚动离开视口时吸附于内容区顶部
- 草稿态不显示 Tab 区，改为展示「待提交」提示条
- 点击遮罩或按 Esc 关闭抽屉

### 13.5 状态 Badge 颜色

| 状态 | 颜色 |
| --- | --- |
| 草稿 | 灰色 |
| 提交中 | 蓝色 |
| 已完成 | 绿色（主题色 #00ab95） |
| 出库失败 | 红色 |
| 已取消 | 灰色 |

### 13.6 操作反馈

- 保存草稿 / 提交成功：右上角 Toast 通知，3 秒后自动消失
- 取消出库单 / 重新提交：Modal 二次确认弹窗，确认按钮点击后显示 loading 状态直到请求返回
- 表格行删除（新建页）：行淡出动画，序号实时重排
- 扫码添加商品：扫码输入框下方即时展示成功 / 失败反馈文字，3 秒后自动清空
