# WMS_WEB端信息架构

## 1. 产品定位

`WMS_WEB端` 是 WMS 的后台管理与运营控制台，负责承接开放平台运维、主数据维护、库存管理、入库管理、出库管理、发货履约管理、物流协同、退货管理、调拨管理、异常工单和费用对账等后台能力。

它只处理 WMS 自身管理能力，不负责第三方电商系统的下单前台、用户订单中心、售后申请入口和运营配置后台。

## 2. 使用角色

| 角色类型 | 使用目标 | 数据范围 |
| ---- | ---- | ---- |
| 系统管理类 | 管理平台账号、角色、权限和开放平台配置，支持全局排查 | 全量 |
| 仓内作业类 | 管理仓内业务、查看库存和单据、处理履约与现场任务 | 按授权货主/仓库 |
| 货主查询类 | 查询自家货主的店铺、库存、入库、出库、发货和物流结果 | 仅本货主授权范围 |

## 3. 全局页面框架

| 区域 | 内容 |
| ---- | ---- |
| 顶部栏 | 货主上下文、仓库/店铺上下文、全局搜索、消息提醒、当前账号 |
| 左侧导航 | 按业务模块组织一级导航和二级菜单 |
| 主内容区 | 列表、详情、抽屉、弹窗、结果页、日志区 |
| 全局提示 | 加载中、空数据、无权限、接口失败、操作成功/失败 |

## 4. 上下文模型

### 页面标准结构

后续文档按“两层结构”表达页面信息，避免页面清单与页面原型说明字段不一致：

| 字段 | 说明 |
| ---- | ---- |
| 页面清单字段 | `页面目标 / 使用角色 / 页面入口 / 优先级 / 核心操作` |
| 页面原型说明补充字段 | `需求来源 / 页面布局` |
| 使用原则 | 页面清单保持轻量，页面原型说明负责补足来源、布局、状态和交互细节 |

| 维度 | 适用范围 | 规则 |
| ---- | ---- | ---- |
| 货主 | 全系统通用 | 所有业务页面默认带货主上下文 |
| 店铺 | 发货履约单、退货单、部分渠道库存 | 只在必须关联店铺的单据中强制展示 |
| 仓库 | 库存、入库、出库、调拨、仓内作业 | 默认作为查询和执行的核心维度 |
| 履约模式 | 发货履约、物流协同 | 在发货履约单、运单、轨迹、包裹等页面中展示 |

说明：

- 库存归属围绕 `货主 + 仓库 + 货位 + 批次 + 状态` 建立。
- 店铺是履约和服务关系，不是库存归属主体。
- `shipment_order_id` 是履约查询与执行的核心对象。
- 物流协同能力并入 WMS_WEB端 后，物流查询仍以 `shipment_order_id`、`package_id`、运单号作为核心主键。

## 9. 原型设计注意事项

| 注意项 | 说明 |
| ---- | ---- |
| 不再使用旧版“工作台”作为默认 P0 页面 | 新版优先围绕功能模块和业务对象组织页面 |
| 开放平台以运维页为主 | token 获取等纯接口能力不单独设计模拟调用页 |
| 发货履约单为执行主对象 | 页面必须突出 `shipment_order_id`、`parent_order_id`、`fulfillment_mode` |
| 物流能力并入 Web，但仍保持独立主对象 | 运单、包裹、轨迹、面单不与履约详情混成一页 |
| 库存页面禁止用店铺代替库存归属 | 店铺只在渠道/履约场景展示 |
| 低优先级模块先保留结构 | 加工、工单、账单等先进入页面清单，不先做高保真展开 |
