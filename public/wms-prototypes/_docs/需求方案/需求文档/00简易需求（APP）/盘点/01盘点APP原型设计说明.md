# 仓库 APP - 盘点管理原型设计说明

> 依据文档：
>
> - 需求：[00盘点APP简易需求文档.md](./00盘点APP简易需求文档.md)
> - UI 规范：[2606改仓配端APP UI规范.md](../../../../UI规范/2606改仓配端APP UI规范.md)
> - 现有原型参考：`APP端HTML原型/pages/pickup-accept.html`、`pickup-work.html`（任务式作业骨架：状态 banner、信息块、商品行、步进器、底部组合操作栏、弹层）；`inbound-list.html`、`inbound-create.html`（列表卡片、状态页签、筛选抽屉、扫码弹层、选货抽屉）。
>
> 本说明覆盖「进入盘点 → 查看/筛选盘点任务 → 新建盘点单 → 领取并开始盘点 → 扫码定位/逐 SKU 录实盘（明盘）→ 暂存 / 提交待复核 → 详情查看差异 → 作废」全流程。盘点为**任务式作业**，整体沿用 pickup 的作业范式，不新造样式体系。

---

## 1. 设计目标

- 在不破坏现有 APP 视觉的前提下，落地「库房+SKU 级」盘点作业闭环，贯彻「简洁 / 有值才显示 / 一屏可扫」原则。
- 复用现有 APP 组件：任务卡片、状态页签、筛选抽屉、状态 banner、信息块、商品行、数量步进器、扫码弹层、底部组合操作栏（pickup 的「左次动作 + 中扫码 + 右主动作」布局）。
- 落实盘点特有交互：**明盘**（账面始终显示，录入后实时显示盘盈/盘亏/一致）、**进度可视**（已盘 N/共 M）、**差异配色**（一致/盘盈浅绿底+绿条、盘亏浅红底+红条）、**差异原因录入**、**抽盘三级分类左右分栏选择**。
- 产出可直接交给技术人员/AI 还原的页面级设计说明，配合需求文档即可开发。

## 2. 设计范围

### 2.1 本期范围
- 新建盘点单页（PD04）：选库房/盘点类型、抽盘范围三级分类左右分栏选择、备注、账面快照预览、生成。
- 任务列表页（PD01）：导航、搜索、状态页签、筛选抽屉、轻量统计条、盘点任务卡片（含进度/差异）、上拉加载。
- 盘点作业页（PD02）：状态/进度头、工具条（扫码定位/搜索/筛选）、明细列表、账面常显 + 实盘录入、实时差异配色、差异原因录入、底部组合操作栏（暂存/扫码/提交）。
- 详情页（PD03）：状态 banner、基本信息动态行、盘点明细多态（待盘/一致/盘盈/盘亏）、差异汇总、时间线、按状态底部操作。
- 弹层：扫码定位、SKU 搜索、差异原因选择、筛选抽屉、抽盘分类左右分栏抽屉、提交确认、作废确认。
- 字段显隐多态与多数据场景演示。

### 2.2 暂不涉及
- **差异复核与库存调账**（WEB 端能力，APP 只读）。
- 货位级清点、循环盘点、扫码逐位清点。
- 导入/导出、真实扫码硬件、真实接口（原型用内联样例数据）。

## 5. 列表页设计（PD01）

### 5.1 骨架
沿用 `inbound-list.html` + `pickup-accept.html` 列表骨架：顶部导航 → 搜索区 → 状态页签 → 统计条 → 卡片列表。逻辑尺寸 `375×812`，左右安全边距 `12px`，背景 `--app-bg`(`#F5F7F8`)，卡片白底圆角 `--app-radius-card`(`10px`)、间距 `10px`、轻阴影。

### 5.2 顶部导航与搜索
- 导航：左返回，居中标题「盘点任务」(16px/600 `--app-text`) + 右侧「＋ 新建」主色小胶囊（APP 支持新建，进 PD04）。
- 搜索：浅灰胶囊输入框 + 主色「搜索」按钮，placeholder「搜索盘点单号」。

### 5.3 状态页签 + 筛选
- 横向 Tab：`全部 / 待盘点(N) / 待复核(N) / 已完成 / 已作废`，当前项主色 `#43B8A8` 下划线（沿用 `.ib-tab`）。「待盘点」聚合 status=1 草稿与 2 盘点中。**待盘点、待复核页签名后带数量**（如「待盘点（2）」），其余页签不带数量。
- 页签行右侧「筛选」漏斗图标，点击打开筛选抽屉。

### 5.4 轻量统计条（随 tab 切换）
- 页签下方一行小字，12px `--app-text-secondary`，不使用大统计卡片。
- **全部** tab：显示「待盘点 N 单 · 有差异 N 单」（status=1/2 计数 + 有差异盘点单计数）。
- **待盘点 / 待复核 / 已完成 / 已作废** tab：显示「有差异 N 单」（有差异行的盘点单计数）。

### 5.5 盘点任务卡片
沿用 `.ib-order-card` / pickup 任务卡，新增**进度条**与**差异条数**：

```text
PD20260620001                               ● 盘点中
盘点类型     全盘
库房         piao自营
盘点人        李海
进度         ████████░░  18 / 25
差异          3 条                          ← 有差异才显示
```

| 元素 | 规格 |
| --- | --- |
| 单号 | 14px/700 等宽字体 |
| 状态 | 右上角小圆点 + 文字（UI 规范 8.4）：草稿 `--app-text-muted` / 盘点中 `--app-warning` / 待复核 `--app-info`(`#2AA7C9` 进度色) / 已完成 `--app-success` / 已作废 灰 |
| 字段名 | 12px `--app-text-secondary`；字段值 12-13px `--app-text` |
| 进度 | 细进度条（主色填充）+ 文本「已盘/共」；100% 时填满 |
| 差异 | 有差异条数才渲染该行，数字用 `--app-danger` 强调；无差异不渲染 |

> 卡片不放底部金额（盘点无金额维度），保持紧凑。

### 5.6 分页与空态
列表上拉到底加载下一页，底部「加载中…」/「没有更多了」。空态：📋 +「暂无盘点任务」。

### 5.7 筛选抽屉
底部抽屉，复用筛选抽屉骨架：

```text
筛选
盘点类型   [全部][全盘][抽盘]
库房       [全部][piao自营][KL自营仓库]...
时间       [开始日期] - [结束日期]
                 [重置]      [确定]
```
胶囊单选；确定后按条件过滤并显示筛选标记；重置清空。

## 6. 卡片/行字段显隐多态 ★

同一组件按数据完整度与盘点阶段呈现不同形态，**无值不渲染、不留「—」**。

### 6.1 列表卡片态
- 固定显示：盘点类型、库房、盘点人、进度。
- 条件显示：差异条数（>0 才显示）、盘点范围（抽盘且有范围才显示）。

### 6.2 盘点明细商品行四态 ★（明盘）
```text
待盘态：        无穷盐焗鸡翅 60g                      待盘
               卤制食品 · 15g*4包/袋 · 条码3000001
               账面 5                实盘 [ − 实盘 + ]   ← 白底

已盘·一致态：    黄飞红麻辣花生 210g                   ✓ 已盘
               花生瓜子 · 210g*1袋 · 条码12345678
               账面 6   一致                          ← 浅绿底 + 绿色左条

已盘·盘盈态：    银鹭牛奶花生 360g                     ✓ 已盘
               账面 2   盘盈 +2   原因：错记            ← 浅绿底 + 绿色左条

已盘·盘亏态：    甘源缤纷每日豆果 208g                  ✓ 已盘
               账面 5   盘亏 -1   原因：破损            ← 浅红底 + 红色左条
```
- 副信息行（分类·规格·条码）只拼接有值项，用「·」分隔；全空不渲染。
- 明盘：账面数始终显示；录入实盘后实时比对：一致显示灰色「一致」标、盘盈显示绿色「盘盈 +N」、盘亏显示红色「盘亏 -N」。
- 配色：一致/盘盈整行浅绿底（`rgba(104,185,46,.08)`）+ 绿色左条（`inset 3px var(--app-success)`）；盘亏整行浅红底（`rgba(232,91,74,.07)`）+ 红色左条（`var(--app-danger)`）；待盘白底。禁止大面积高饱和。
- 差异原因：盘盈/盘亏且已填才显示标签。
- 作业页（PD02）与详情页（PD03）同款配色，保持一致。

### 6.3 详情基本信息态
- 行顺序固定：盘点类型 → 库房 → 盘点人 → 盘点时间 → 范围 → 备注。
- 仅渲染有值行；范围/备注为空时整行不显示。

## 7. 盘点作业页设计（PD02）★

整体沿用 `pickup-work.html` 任务作业骨架（状态 banner + 信息块 + 商品行 + 底部组合操作栏）。

### 7.1 状态/进度头
- 顶部 `status-banner`：左返回，中部「盘点中」状态标题 + 单号（可复制），副行显示库房。
- 进度块：进度条 + 「已盘 18 / 共 25」，主色填充。

### 7.2 工具条
卡片标题行右侧小按钮（沿用 `.ib-mini-btn`）：
- `📷 扫码定位`：打开扫码弹层，命中条码后**滚动并聚焦**该 SKU 行、自动唤起实盘输入；未命中 toast「条码未匹配到本单商品」。
- `🔍 搜索 SKU`：按名称/条码筛选明细行。
- 筛选胶囊：`全部 / 待盘 / 已盘 / 有差异`（当前项主色弱底）。

### 7.3 盘点明细列表
- 沿用 pickup 的 `sku-item`/`sku-main`/`sku-info`/`sku-stepper` 结构。
- 每行：商品名（`sku-name`）+ 副信息（`sku-spec`，按显隐拼接）+ 实盘录入（步进器 `sku-stepper`，min 0，可点中间数字直接键盘输入）+ 已盘标记。
- 明盘：账面数位常显「账面 N」，录入实盘后该行 `count_status` 置已盘并打 ✓。
- 录入实盘后**实时**比对账面：一致打灰色「一致」标 + 浅绿底+绿条；盘盈打绿色「盘盈 +N」+ 浅绿底+绿条；盘亏打红色「盘亏 -N」+ 浅红底+红条。
- 差异原因入口：在「盘盈/盘亏行」于提交校验阶段统一要求补填（见 7.5）。

### 7.4 底部组合操作栏（pickup 三段式）
沿用 UI 规范 8.5.4「左次动作 + 中扫码 + 右主动作」：
- 左：`暂存`（描边，写库不改单状态）。
- 中：`扫码定位`高频动作图标按钮（突出）。
- 右：`提交盘点`（主色胶囊）。
- 左侧另显进度小字「已盘 18/25」。

### 7.5 提交校验与差异原因补填
- 点「提交盘点」先校验完整性：**必须所有行已盘**才可提交，否则 toast「还有 N 个商品未盘点」并跳到第一条待盘行。
- 系统计算差异，若存在差异行，弹「差异确认」面板：列出盘盈/盘亏行，逐行要求选差异原因（破损/过期/错记/被盗/其它）；未选齐不可确认。
- 确认后状态 盘点中(2) → 待复核(3)，跳详情或回列表并 toast「已提交，等待复核」。**此步不改库存。**

## 8. 详情页设计（PD03）

### 8.1 结构
沿用 `inbound-list.html` 详情屏 + pickup 信息块：

```text
[banner] PD20260620001  复制                 ● 待复核
[基本信息]  盘点类型 / 库房 / 盘点人 / 盘点时间 / (范围) / (备注)   ← 动态行
[盘点明细 (N)]  多态商品行（亮账面/实盘/差异）
[差异汇总]  盘点 25 SKU | 有差异 3 | 盘盈 +5 | 盘亏 -4
[时间线]  创建·账面快照 → 开始盘点 → 提交待复核 (→ 复核完成 / 驳回)
```

### 8.2 差异汇总块
浅灰底 `--app-bg-soft`(`#F7F8FA`) 卡片，四个指标：盘点 SKU 数、有差异数（`--app-danger`）、盘盈合计（`--app-success` 前缀 +）、盘亏合计（`--app-danger` 前缀 -）。已完成单额外可显示「已调账」标记。

### 8.3 底部操作（按状态）★
| 状态 | 底部按钮 |
| --- | --- |
| 草稿 | 作废（描边/红字）· 开始盘点（主色） |
| 盘点中 | 作废（描边/红字）· 继续盘点（主色） |
| 待复核 | 无操作（纯只读，等 WEB 复核） |
| 已完成 | 无操作（只读） |
| 已作废 | 无底部栏（纯只读） |

### 8.4 时间线
沿用 `.ib-log-node`：创建·账面快照（＋）→ 开始盘点（▶）→ 提交待复核（✓）→ 复核完成·已调账（✓）或被驳回（↺，并提示退回盘点中可重盘）/ 作废（✕）。

## 8A. 新建盘点单设计（PD04）

沿用 `inbound-create.html` 表单骨架（`.ib-card` + `.ib-row` + 库房抽屉 + 底部操作栏 + 成功页）。

### 8A.1 结构
```text
[基本信息]  盘点库房*（选择抽屉）/ 盘点类型（全盘·抽盘胶囊）/ (抽盘范围) / 备注
[账面快照预览]  大数字「N 个 SKU」+ 提示 + 预览列表（名称/分类规格/账面数）
[底部栏]  库房·N 个 SKU + 生成盘点单（库房未选或无 SKU 时禁用）
```

### 8A.2 抽盘范围 — 三级分类左右分栏选择器 ★
- 仅「抽盘」类型下出现「抽盘范围」入口行，收起显示「已选 N 项」摘要，点开底部抽屉。
- 抽屉**左右分栏**：
  - 左列（106px，浅灰底）：竖排一级分类，当前项白底 + 主色左条；右上角角标显示该一级下已选叶子数。
  - 右列：当前一级下按二级分组，组标题带「全选/取消全选」按钮（全选态主色实底）与「部分」半选提示；其下三级叶子每行带方形勾选框（选中主色实底打 ✓）。
- 顶部搜索框：跨三级按名称过滤，结果平铺为叶子列表并显示「一级 / 二级」路径。
- 底部「已选 N 项 / 重置 / 确定」，确定后写回入口行摘要并刷新快照预览；未选叶子时默认快照全部。
- 选中逻辑：勾选二级=选中其下全部三级；叶子可单独勾选；账面预览按所选叶子分类过滤 SKU。

### 8A.3 生成
- 校验库房必选、快照 SKU 数 > 0；生成 status=1 草稿盘点单（快照账面）→ 成功页（单号 + 库房/类型/SKU 数 + 「返回列表 / 开始盘点」）。

## 9. 弹层一览

| 弹层 | 形态 | 用途 |

## 13. 原型落地规则

- 三个页面均在 `APP端HTML原型/pages/`：`stocktake-list.html`（PD01 列表 + PD03 详情同页，参照 inbound-list）、`stocktake-create.html`（PD04 新建，参照 inbound-create）、`stocktake-count.html`（PD02 作业页，参照 pickup-work），**保持单文件自包含**（样例数据 + 控制器内联，与 `inbound-*`/`pickup-*` 一致）；内联脚本 < 50KB（check-wms-prototypes.sh 限制）。
- 不新造卡片/弹层/Tab/步进器样式，复用 UI 规范第 9 节 Design Tokens 与现有 APP 组件（`.ib-*`、`.sku-*`、`.modal-*`、`.step-btn` 等）。
- 入口接线：`assets/wms-app-page.js` 的 `navigate()` 与 `assets/wms-app-shell.js` 的 `frameUrl()` 中已加映射 `stocktake_task / inventory_count → stocktake-list.html`、`create_stocktake → stocktake-create.html`、`stocktake_count → stocktake-count.html`。
- 工作台现有「盘点」入口（`inventory_count`）指向 PD01 列表；APP 菜单目录（`APP菜单目录.html`）盘点项指向 stocktake-list，并补「新建盘点单 / 盘点作业」两页条目。
- 字段显隐用「有值判断 + 不渲染空行」实现，禁止用「—」占位。
- AI 新生成草稿先放 `_drafts/`，确认后再合并正式 APP 原型。
- 数据口径以 MySQL `wms` 真实表为准；盘点单/明细为新增表，原型用内联样例模拟其字段结构（见需求文档 3.1/3.2 DDL 草案）。
