# WMS 前端 UI 规范

> 审计日期：2026-06-10
> 适用对象：`public/wms-prototypes/WEB端HTML原型` 下的 WEB 后台原型。
> 重要说明：本规范不是对当前实现的复刻，而是基于当前原型中可保留的视觉方向，修正已发现的问题后形成的目标态规范。

## 1. 适用范围与边界

本规范优先约束 WEB 后台原型，包括主壳、侧边栏、顶部栏、筛选区、统计卡片、表格、抽屉、弹窗、按钮和状态提示。

APP 端是移动端工作台视觉语言，不能直接套用 WEB 后台规范。APP 端需要单独维护移动端 UI 规范，至少应保持自己的手机容器、底部导航、移动卡片密度和触控尺寸。

总入口页可以保留独立展示型样式，但不得作为 WEB 后台业务页的样式模板。

## 2. UI 审计结论

### 2.1 可保留的视觉方向

- 整体气质：浅灰背景、白色半透明业务面板、轻阴影、低饱和线条，适合 WMS 后台的长期查看和密集操作。
- 主色：`#00ab95` 作为业务强调色是可保留方向，适合库存、仓库、履约这类偏运营系统。
- 信息密度：后台页面应保持高信息密度，优先服务扫描、筛选、比较和批量操作，不做营销式大面积留白。
- 侧边栏：左侧 248px 左右的模块导航、图标 + 模块名 + 子菜单层级清晰，可保留。
- 顶部栏：粘性顶部栏、面包屑、全局搜索、仓库/渠道切换、用户身份区域方向正确。
- 卡片：统计卡片、业务面板、列表项采用白底、浅边框、轻阴影和状态色顶线，方向可保留。
- 表格：12-13px 表格字号、浅灰表头、行分隔线、状态标签、操作按钮，适合后台数据表。
- 交互层级：查询、重置、导出、新增、查看详情、抽屉详情的页面层级符合 WMS 使用场景。

### 2.2 必须修正的问题

- 样式来源漂移：当前多个业务页面仍内嵌完整 `<style>`，页面未引用共享 CSS。审计抽样中，业务 iframe 页 `styleTags=1`、`linkedCss=0`；全目录存在 28 个带 `<style>` 的 HTML。这会让后续 AI 继续复制页面级规范，导致漂移。
- 筛选区换行不稳定：`.filters-row.is-quarter` 在 1440 浏览器宽度下，iframe 可用宽约 1192px，实际仍变成 3 列，4 个筛选控件拆成 2 行。入库页 1024 宽时，日期范围内部还出现横向溢出。
- 统计卡片规则过散：同类 KPI 同时存在 `.metrics`、`.mini-grid`、`.inbound-stats` 等多套写法，局部用高优先级类名抵消全局媒体查询，容易出现过早换行或卡片高度不一致。
- 宽表可读性下降：商品表格采用左固定列 + 中间滚动列 + 右操作列，方向正确，但 1024 宽时中间滚动区只剩约 292px，信息查看压力过大。
- 固定列风险：当前存在 sticky 单表和三段式表格两种思路。后续如果混用，容易出现固定列重叠、阴影遮挡、表头和表体行高不同步。
- 页面级魔法值过多：存在 `style=`、`onclick`、空 `div` 占位、`height: 100px !important`、负 `letter-spacing`、字符符号图标等写法，后续生成容易把局部补丁当规范。

## 3. 设计原则

1. 后台优先：页面首先服务查询、筛选、对比、批量处理和异常定位。
2. 一屏可扫：首屏优先展示页面标题、关键筛选、核心 KPI、主表格开头，避免大 hero 和说明型文案占据业务空间。
3. 组件统一：相同功能必须使用同一套类名、同一套尺寸、同一套交互状态。
4. 容器优先：响应式规则以内容容器宽度为准，不能只按浏览器视口写全局断点。
5. 可维护优先：正式页面不得复制整页样式和脚本。视觉规范必须沉淀到共享 CSS 和共享组件写法。

## 4. 基础视觉规范

### 4.1 色彩

| 用途 | 目标值 | 使用说明 |
| --- | --- | --- |
| 页面背景 | `#f5f5f7` | WEB 后台主背景，允许轻微线性明暗变化 |
| 主面板 | `#ffffff` / `rgba(255,255,255,0.90)` | 卡片、表格、筛选区 |
| 弱面板 | `#fafafc` | 表格容器、列表项底色 |
| 边框 | `rgba(29,29,31,0.08)` | 默认分割线 |
| 主文本 | `#1d1d1f` | 标题、关键字段 |
| 次文本 | `rgba(29,29,31,0.72)` | 说明、表格普通字段 |
| 弱文本 | `rgba(29,29,31,0.48)` | 占位、辅助说明 |
| 主色 | `#00ab95` | 查询、确认、启用、成功类业务动作 |
| 主色弱底 | `rgba(0,171,149,0.10)` | 选中菜单、轻提示、状态底 |
| 警告 | `#c77c11` | 库存预警、临期、等待 |
| 危险 | `#d92d20` | 超时、失败、删除、不可逆动作 |

禁止新增与主色冲突的大面积高饱和蓝、紫、橙背景。蓝色只能作为少量信息状态或链接辅助色，不作为 WEB 后台主品牌色。

### 4.2 字体

- 字体族：优先 `-apple-system`、`BlinkMacSystemFont`、`PingFang SC`、`Microsoft YaHei`、`sans-serif`。
- 页面标题：24-28px，字重 600-700，行高 1.15-1.25。
- 区块标题：18-20px，字重 600-700。
- 正文和控件：13px。
- 表格表头：12px，字重 600。
- 表格内容：13px。
- 数字 KPI：28-36px，使用等宽数字特性。

禁止使用负 `letter-spacing`。禁止用 `vw` 或 `clamp(...vw...)` 控制后台页面字号。字号应由组件层级决定，不跟随视口连续缩放。

### 4.3 圆角、阴影、间距

- 页面主面板：16-20px 圆角。
- 统计卡片：16-20px 圆角。
- 输入框：10-12px 圆角。
- 按钮：业务按钮可用胶囊圆角；表格内小按钮用 8-10px。
- 阴影：只用于主面板、浮层、可点击卡片 hover，强度保持轻。不要用厚重投影制造层级。
- 页面外边距：16-24px。
- 面板内边距：16-24px。
- 表格单元格：普通表 12-16px 横向内边距，紧凑表 10-12px。

## 5. WEB 后台布局规范

### 5.1 主壳

- 侧边栏宽度保持 248px 左右，允许在窄屏变为顶部/静态导航。
- 顶部栏保持 sticky，包含面包屑、搜索、仓库/渠道选择和用户身份。
- 主内容区域必须 `min-width: 0`，防止表格或长文本撑破布局。
- 业务页面内容采用全宽后台布局，不使用营销式 hero，不把主内容放进装饰性大卡片中。

### 5.2 页面结构

标准页面顺序：

1. 页面标题区：标题、简短副标题、主要页面级动作。
2. 筛选区：查询条件、查询/重置/导出等动作。
3. KPI 区：可选，最多一行优先展示关键指标。
4. 主表格或主业务列表。
5. 抽屉、弹窗、详情面板。

禁止在首屏放大段说明文字。业务说明应进入需求抽屉或辅助提示。

### 5.3 响应式规则

响应式应以内容容器宽度为准，不能只写全局 `@media (max-width: 1360px)` 去改所有 `.metrics` 或 `.filters-row`。

推荐目标：

| 内容容器宽度 | 筛选区 | KPI 卡片 | 表格 |
| --- | --- | --- | --- |
| ≥ 1080px | 4 列筛选，动作同排 | 4-5 卡同排 | 表格占满容器 |
| 840-1079px | 3 列筛选 | 4 卡可同排，5 卡需评估最小宽 | 宽表允许横向滚动 |
| 640-839px | 2 列筛选 | 2 列卡片 | 表格横向滚动或字段折叠 |
| < 640px | 1 列筛选 | 1 列卡片 | 移动端降级展示 |

## 6. 筛选区规范

### 6.1 基础结构

筛选区统一使用 `surface-controls` + `filters-grid` 类组件。后续重构时，应把当前 `.filters-row.is-quarter`、`.filters-row.is-one` 等分叉收敛到统一组件。

推荐语义：

```html
<div class="surface-controls">
  <div class="filters-grid" data-cols="4">
    ...
  </div>
  <div class="filters-grid filters-grid-search">
    ...
  </div>
</div>
```

### 6.2 控件尺寸

- 输入框、下拉框高度：40px。
- 控件最小宽度：普通筛选不低于 176px；关键词搜索不低于 280px。
- 控件内部必须 `min-width: 0`，长 placeholder 用省略处理。
- 同一行内的控件基线、圆角、边框、聚焦态必须一致。

### 6.3 动作按钮

- 查询按钮放在筛选动作组首位。
- 重置为中性按钮。
- 导出为中性按钮或次级按钮。
- 同一筛选区只允许一个主按钮。
- 动作组不得因为空 `div` 占位而换行；应由布局类控制。

### 6.4 日期范围

日期范围必须封装成独立组件，例如：

```html
<div class="date-range-control">
  <input class="filter-ctrl" type="date" />
  <span>至</span>
  <input class="filter-ctrl" type="date" />
</div>
```

内部布局使用 `grid-template-columns: minmax(0,1fr) auto minmax(0,1fr)`。禁止用内联 `display:flex`、`style="flex:1"` 临时拼日期范围。

## 7. 统计卡片规范

### 7.1 使用场景

- KPI 卡片用于“可扫描的关键指标”，不用于承载长说明。
- WEB 后台列表页默认最多 4 个 KPI。
- 驾驶舱允许 5 个核心 KPI，但必须保证每张卡片的有效宽度和可读性。

### 7.2 尺寸

- 普通 KPI 卡片最小宽度：180px。
- 紧凑 KPI 卡片最小宽度：160px。
- 数字最多一行，说明最多两行。
- 卡片高度由内容自然撑开，允许设置 `min-height`，禁止用固定 `height` 强压所有卡片。

### 7.3 状态

- 成功/正常：主色或绿色弱提示。
- 警告：黄色/棕黄色。
- 危险：红色。
- 状态色只用于顶线、标签、小面积背景，不做整卡高饱和填充。

## 8. 表格规范

### 8.1 普通表格

- 表格外层必须提供横向滚动能力。
- 表头背景用浅灰，表体白底。
- 行高保持 40-48px。
- 长文本默认省略，必要时用 `title` 或详情抽屉展示完整内容。
- 数字字段右对齐或按列统一对齐，文本字段左对齐。

禁止只有外层 `overflow: hidden` 而没有滚动容器的宽表。

### 8.2 宽表

宽表优先使用以下两种模式之一，不得混用：

1. 单表 sticky 模式：一张表内用 sticky 固定左列或右操作列。
2. 三段式表格模式：左固定表 + 中间滚动表 + 右固定操作表。

选择三段式表格时：

- 左固定列建议 200-240px。
- 右操作列建议 148-180px，不应默认过宽。
- 中间滚动区可读宽度不低于 420px；商品资料类超宽表建议不低于 520px。
- 当容器宽度不足时，整张表格壳应横向滚动，不得继续压缩中间滚动区。
- 三段表头、表体、空状态、分页必须行高同步。

选择 sticky 模式时：

- 多个固定列必须逐列累加 `left` 或 `right` 偏移。
- 表头固定列 `z-index` 必须高于表体固定列。
- sticky 列必须有不透明背景。
- 禁止多个固定列都写 `left: 0`。

### 8.3 操作列

- 表格行内操作优先用文字按钮：查看、编辑、同步、取消。
- 单行超过 3 个操作时，保留 1-2 个高频动作，其余进入更多菜单。
- 危险动作必须用危险色，并需要二次确认。

## 9. 按钮、标签、图标

### 9.1 按钮层级

- 主按钮：页面最重要动作，如查询、新增、提交，使用主色。
- 中性按钮：重置、导出、取消、返回，白底或浅灰底。
- 危险按钮：删除、取消单据、失败重试后的危险确认，使用危险色。
- 同一区域不要同时出现多个主按钮。批量导入、批量启用、导出等应根据重要性降级为中性或次级按钮。

### 9.2 标签

- 状态标签使用小面积弱底 + 状态色文字。
- 标签文字应短，不超过 6 个汉字为宜。
- 同一业务状态必须在所有页面使用同一色彩和文案。

### 9.3 图标

- 图标来源必须统一。当前可继续使用共享 `iconSvg`，后续如引入图标库，应一次性替换为统一图标集。
- 搜索、刷新、设置、列设置等功能不要使用纯字符符号冒充图标。
- 图标按钮必须有 `aria-label` 或可见 tooltip。

## 10. 代码与生成规范

### 10.1 共享资产

WEB 后台正式页面的目标结构：

```html
<link rel="stylesheet" href="../assets/wms-web-prototype.css" />
<script src="../assets/wms-content-app.js"></script>
```

主壳页面继续引用：

```html
<link rel="stylesheet" href="./assets/wms-web-prototype.css" />
<script src="./assets/wms-shell.js"></script>
```

需求数据继续只从：

```text
public/wms-prototypes/WEB端HTML原型/assets/wms-requirement-data.json
```

应用逻辑继续只从：

```text
public/wms-prototypes/WEB端HTML原型/assets/wms-content-app.js
```

### 10.2 页面 HTML 职责

页面 HTML 只承担页面挂载、结构容器和必要语义，不承载整页样式、整页脚本和需求数据副本。

新增或重构业务页时，不能参考当前仍有页面级脚本的历史页作为模板，例如 `outbound.html`、`stock-flow.html`、`warehouse-room.html`。这些页面可以作为业务内容参考，但不能作为生成规范参考。

### 10.3 CSS 职责

共享 CSS 负责：

- 颜色 token
- 字体 token
- 布局栅格
- 组件尺寸
- 按钮/输入框/表格/卡片/抽屉/弹窗
- 响应式规则

页面级特殊样式必须先判断是否能抽象为共享组件。只有一次性草稿或已明确不会进入正式链路的试验文件，才允许临时样式。

## 11. 禁止写法清单

以下写法后续 AI 生成或重构正式 WEB 原型时禁止使用：

```html
<!-- 禁止：业务页面内嵌整页样式 -->
<style>...</style>

<!-- 禁止：行内样式修布局 -->
<div style="display:flex;align-items:center;gap:6px">

<!-- 禁止：行内事件 -->
<button onclick="filterByStatus('草稿')">...</button>

<!-- 禁止：页面内嵌需求数据副本 -->
<script>
  window.WMS_REQUIREMENT_DATA = {...}
</script>

<!-- 禁止：页面内嵌应用逻辑副本 -->
<script>
  function renderPage() {...}
</script>
```

以下 CSS 写法禁止继续新增：

```css
/* 禁止：用过宽全局断点重置所有同类组件 */
@media (max-width: 1360px) {
  .metrics { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

/* 禁止：固定高度强行对齐卡片 */
.todo-item { height: 100px !important; }

/* 禁止：负字距 */
.page-title { letter-spacing: -0.04em; }

/* 禁止：后台字号随视口连续缩放 */
.hero h1 { font-size: clamp(30px, 3vw, 34px); }

/* 禁止：宽表外层隐藏溢出但没有滚动容器 */
.table-wrap { overflow: hidden; }

/* 禁止：多个固定列使用同一个 left */
.sticky-col-a,
.sticky-col-b { left: 0; }
```

以下布局行为禁止：

- 用空 `div` 占位控制筛选按钮位置。
- 用 `style="grid-column:1/-1"` 临时撑开字段。
- 让搜索区、日期范围、按钮组在 1080px 以上内容宽度提前拆成多行。
- 让固定列宽度挤压中间表格到不可读。
- 把当前页面截图或现状 HTML 当成 UI 规范。
- 新生成“最终版/优化版/副本”HTML 覆盖正式页面。

## 12. 后续 AI 输出验收清单

每次生成或修改 WEB 原型前，必须检查：

- 是否只改共享数据、共享 JS、共享 CSS 或必要页面结构。
- 是否没有在业务页面新增 `<style>`。
- 是否没有新增 `style=`。
- 是否没有新增 `onclick`、页面级 `<script>`、内嵌数据副本。
- 筛选区在 1440、1280、1024 宽下是否稳定，不出现无意义换行。
- 日期范围是否用统一组件，不出现内部横向溢出。
- KPI 卡片是否根据容器宽度合理排布，不因全局断点过早换行。
- 宽表是否有明确横向滚动策略。
- 固定列是否不重叠，表头和表体行高是否同步。
- 按钮层级是否清楚，同一区域是否只有一个主按钮。
- 状态色是否使用规范 token。
- 字体是否无负字距、无视口字号。
- 临时稿是否放在 `_drafts/`，正式链路是否仍只认 3 个固定正式文件。

## 13. 一句话原则

保留当前 WMS 原型“浅色、克制、高密度、后台感”的方向，但不要复制当前页面级实现；后续所有 WEB 业务页必须向共享 CSS、共享 JS、稳定栅格、可滚动宽表和明确禁止清单收敛。
