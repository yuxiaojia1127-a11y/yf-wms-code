# WMS_APP端第二轮简易版PRD

## 1. 文档说明

本文为 `WMS原型设计` 中 `WMS_APP端` 的第二轮简易版 PRD，承接第一轮 `通用基础能力 + 工作台与任务中心 + 入库执行主链路 + 出库执行主链路`，继续补齐 APP 端中的物流协同与调拨作业。

本轮重点覆盖：

- 物流协同
- 调拨作业

本轮特别说明：

- `WMS_APP_物流系统` 在需求文档侧独立拆分，但在原型阶段继续并入 `WMS_APP端` 的 `物流协同` 模块中呈现。
- 本轮聚焦现场执行端的“交接、回看、调拨出入库”，不展开 Web 端后台物流管理视角。
- 调拨作业在 APP 端以现场执行为主，Web 端负责后台跟踪与管理，两端需要保持状态口径一致。

本轮不展开以下范围：

- 售后作业
- 仓内作业
- 消息中心
- 我的
- 异常中心的完整闭环处理

状态口径说明：本文中的任务状态、执行节点状态、交接状态、质检状态和异常状态统一引用 [16WMS_APP端状态口径总表.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/原型设计/WMS原型设计/16WMS_APP端状态口径总表.md)；若本文件局部示例与状态口径总表存在差异，以状态口径总表为准。

## 2. 功能目标

本轮简易版 PRD 的目标是在 APP 端补齐“出库后的现场物流交接”和“仓间调拨执行”两类能力，让一线作业从出库完成自然衔接到物流交接，并支持调拨出库和调拨入库的完整现场处理。

具体目标如下：

1. 建立物流交接确认能力，支持在出库完成后选择物流方式、记录交接人、交接时间和现场确认结果。
2. 建立运单回看能力，让现场主管和管理员可快速查看运单号、承运状态和异常摘要。
3. 建立调拨出库任务执行能力，支持开始备货、复核和提交发运。
4. 建立调拨入库任务执行能力，支持收货、差异登记和提交入库。
5. 明确物流协同和调拨作业与 Web 端履约中心、物流协同、调拨中心之间的依赖关系。

## 7. 核心流程

### 7.1 物流交接主链路

1. 作业员在出库确认完成后进入物流交接确认页。
2. 选择当前物流方式，如即时配送、快递配送或手工物流。
3. 录入交接人、交接时间和现场备注。
4. 确认交接后，任务进入已交接或交接异常状态。
5. 如需查看后续承运状态，可进入运单回看页查看运单号和轨迹摘要。

### 7.2 调拨出库主链路

1. 作业员在任务中心进入调拨出库任务详情。
2. 接单后锁定任务归属。
3. 根据任务明细开始备货，并完成复核。
4. 发运提交成功后，调拨任务进入已发运或在途状态。
5. 结果回流到 Web 端调拨单详情和库存结果中。

### 7.3 调拨入库主链路

1. 作业员在任务中心进入调拨入库任务详情。
2. 接单后开始收货。
3. 录入实收结果并登记少收、破损、批次不符等差异。
4. 提交入库成功后，任务进入已完成状态。
5. 结果回流到调拨中心、入库中心和库存中心。

## 8. 状态流转

本章节不再定义独立的 APP 端状态体系，统一引用 [16WMS_APP端状态口径总表.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/原型设计/WMS原型设计/16WMS_APP端状态口径总表.md)；以下内容仅用于说明本轮涉及任务或结果对象的状态使用范围、页面展示位置和理解方式。

| 状态 | 说明 |
| ---- | ---- |
| 待交接 | 出库完成，待选择物流方式并确认交接 |

## 13. 异常处理

| 场景 | 处理要求 |
| ---- | ---- |
| 交接未完成 | 不允许直接跳过交接进入完成态 |
| 运单未生成 | 提示稍后查看或手动刷新，不误导为失败 |
| 运单状态异常 | 展示异常摘要，并保留上报入口 |
| 调拨出库任务失效 | 提示当前任务状态已变更，不允许继续操作 |
| 调拨入库数量不符 | 必须登记差异原因 |
| 调拨批次不符 | 显式提示批次异常，记录处理结果 |
| 网络异常 | 所有提交动作统一进入在线重试能力 |
