# 仓库APP-销售订单跟踪原型设计说明

> 依据文档：
>
> - 需求：[00销售订单跟踪简易需求文档.md](./00销售订单跟踪简易需求文档.md)
> - UI 规范：[2606改仓配端APP UI规范.md](../../../../UI规范/2606改仓配端APP UI规范.md)
> - 设计参考：打包复核详情（揽货指令切换、商品分组）、发货管理列表、揽货/发货详情
>
> 本说明覆盖「进入销售订单跟踪 → 查看/搜索订单 → 进入跟踪详情 → 看订单总览/进度 → 订单商品（三数量对照）→ 打包/发货记录 → 履约进度时间轴（置底）」全流程。本功能为**只读跟踪**，详情整合揽货、打包复核、发货三页内容，只呈现各环节**最终结果**。

---

## 1. 设计目标

- 基于销售订单跟踪简易需求文档与 APP UI 规范，输出可直接还原原型的页面设计说明。
- 列表整体复用「发货管理」列表卡片结构（不展示商品图片）；详情参考「打包复核详情」的揽货指令切换与商品分组交互，把揽货/打包/发货的最终结果整合到一页。
- **核心体验目标**：以订单为单位，一屏看清整体进度、各环节操作人，以及**「订单数量 → 实际揽货数量 → 打包复核数量」三个数量的对照关系**，异常一眼可辨。
- 全程只读：不出现接单、揽货、打包、发货、扫码、步进等任何作业控件。

---

## 2. 设计范围

### 2.1 本期范围

- 订单跟踪列表页：搜索、阶段页签（含待接单 + 待处理角标）、配送类型筛选、时间排序、订单卡片（参考发货管理列表，无商品图）。
- 订单跟踪详情页（顺序）：① 订单总览与 6 步进度概览条 → ② 订单信息卡/收货人 → ③ 订单商品（三数量对照 + 揽货指令切换）→ ④ 打包复核记录 → ⑤ 发货与配送记录 → ⑥ 履约进度时间轴（置底，含操作时间戳）。
- 三数量对照组件：订单数量 / 实际揽货 / 打包复核的并列展示与差异高亮。
- 异常最终结果展示：缺货 / 退货 / 换货（原商品 ↔ 实际商品配对）/ 退差价。

### 2.2 暂不涉及

- 任何作业写操作（接单、揽货、打包、发货、改址、扫码、步进控件）。
- 退货 / 换货 / 退差价的资金结算与退款状态。
- 订单拦截原因处理详情页。
- 物流轨迹三方对接细节页面。
- WEB 端布局与组件（后续单独输出）。
- 权限矩阵配置页。

## 5. 列表页设计

### 5.1 整体骨架

列表页对齐「发货管理」列表：顶部浅青背景区 → 搜索区 → 阶段页签 → 配送类型筛选 → 订单卡片列表。差异：无勾选框、无底部「统一发货」操作栏（只读），状态标签替换为「整体进度」，卡片不含商品图。

- 页面背景 `--app-bg #F5F7F8`；顶部浅青 `--app-primary-soft #DDF8F2`。
- 内容左右安全边距 `12px`；卡片白底，圆角 `8px`，卡片间距 `8px-10px`。

### 5.2 搜索区

| 元素 | 规格 |
| ---- | ---- |
| 搜索框 | 弱灰底胶囊，圆角 `16px-18px`，高度约 34px |
| placeholder | 「请输入订单号/联系人/揽货指令ID」，12px `--app-text-muted` |
| 搜索按钮 | 主色胶囊，文字「搜索」，右侧贴合 |

### 5.3 阶段页签与配送筛选

- **阶段页签**（首行）：全部 / 待接单 / 异常 / 揽货中 / 待打包 / 待发货 / 配送中 / 已完成；当前页签 16px / 600 + 主色下划线。页签区域 `.tab-scroll`(flex:1) 横向滚动；**「时间」排序为同级独立元素 `.sort-toggle`(flex-shrink:0)，固定在右侧、带左分隔线，不随页签滚动**。
- **页签角标**：除「全部」「已完成」外，每个页签后跟红色小角标 `(N)` 显示该阶段待处理数量（11px，`--app-danger`）。角标随「配送类型筛选 + 搜索」联动，数字与列表一致。「已完成」页签归集「已送达 + 已完成」订单。
- **配送类型筛选**（次行，chip）：全部（默认）/ 即时配送 / 预约单 / 物流发货；**每个 chip 后带数量统计 `(N)`**（按当前阶段 + 搜索统计，随阶段切换更新）。选中 chip 深底白字 `#2B2F36`，未选白底深字。
- 切换页签/筛选刷新列表并保留搜索条件；默认按下单时间升序。

### 5.4 订单卡片设计

卡片复用发货管理订单卡片骨架，去掉勾选框与商品图，状态改为整体进度。

| 元素 | 设计规格 |
| ---- | ---- |
| 订单类型标签 | 左上角小标签，「预约单 / 实时单」，浅底主色字 |
| 联系人 | 标题位，14px / 600，深蓝黑 |
| 整体进度 | 右上角小圆点 + 文字，颜色随阶段（见 5.5） |
| 订单号 | `SM2025002140190351`，13px，右侧浅蓝「复制」 |
| 履约库房 | 单库房展示名称；多库房「吉隆坡前置仓 等 2 个」 |
| 揽货指令数 | `揽货指令 2 张（已完成 1/2）`，12px |
| 配送方式 | `即时配送 ｜ 2小时内送达 ｜ XXkm`，12px |
| 用户预约时间 | `2025-02-10 14:00-16:00` / `尽快送达，预估 12:09` / `-`（物流单），12px |
| 商品数量 | `3（共10件）`，与详情数量口径一致 |
| 下单时间 | `2025-02-10 12:00:00`，12px 弱色 |
| 异常标识 | 含缺货 / 含退货 / 含换货 / 含退差价 / 配送异常 / 已拦截，橙/红小标签，存在时展示 |
| 操作区 | 右对齐，仅次按钮「跟踪详情」（只读，无主操作按钮） |

### 5.5 整体进度状态色

| 阶段 | 颜色 | 说明 |
| ---- | ---- | ---- |
| 待接单 | `#8C8F99` 灰 | 揽货指令已下发、尚无人接单 |
| 揽货中 | `--app-warning #D99A19` | 揽货进行中 |
| 待打包 | `#2AA7C9` 青 | 全部揽货到齐，等待打包 |
| 待发货 | `--app-info #2F80ED` | 打包完成 |
| 配送中 | `--app-purple #7C5CFC` | 已发货，配送途中 |
| 已送达 | `--app-teal #14998C` | 配送已送达，待用户确认 |
| 已完成 | `--app-success #68B92E` | 用户确认收货 / 送达超 1 天自动完成 |
| 异常 / 已取消 | `--app-danger #E85B4A` | 缺货 / 退货 / 换货 / 退差价 / 拦截 / 取消（异常为跨阶段标识） |

## 6. 详情页设计

### 6.1 整体骨架

详情页参考「打包复核详情」的骨架并改为只读信息流，模块顺序固定：

1. 顶部导航：返回 + 标题「订单跟踪」。
2. 订单总览：整体进度标题、订单号、配送信息、**6 步进度概览条**。
3. 订单信息卡：库房、预约送达、缺货偏好、订单备注、收货人、邮编、收货详情。
4. **订单商品**（见 §8，含三数量对照与揽货指令切换，整块单一卡片）。
5. 打包复核记录、发货与配送记录（见 §9）。
6. **履约进度时间轴（置于详情最底部）**（见 §7）。

详情页不出现任何作业控件（无步进器、无扫码按钮、无完成/确认按钮、无底部操作栏）。

### 6.2 订单总览与进度概览条

| 元素 | 规格 |
| ---- | ---- |
| 整体进度标题 | 当前阶段，如「配送中 / 已送达 / 已完成」，20px / 600 |
| 订单号 | `SM2025002140190351`，13px + 浅蓝「复制」 |
| 配送信息 | `即时配送 ｜ 2小时内送达 ｜ XXkm`，13px |
| 进度概览条 | 横向 **6 步**分段：接单 → 揽货 → 打包 → 发货 → 送达 → 完成 |

进度概览条视觉：已完成节点主色实心圆 + 主色连接线；当前节点主色描边高亮；未到达节点灰色空心圆 + 灰虚线。节点下方 10px 小字标注阶段名，当前节点小字主色加粗。「送达」对应配送已送达，「完成」对应用户确认收货或送达后超 1 天系统自动完成。

### 6.3 订单信息卡

沿用揽货/打包详情卡片层级（白底，圆角 8px，内边距 12px）：库房（多库房逐行）、预约送达时间、商品缺货时（橙色强调）、订单备注（橙色强调，超两行可展开）、联系人+电话（电话图标可拨号）、邮编、收货详情（蓝色链接，可展开灰底块含完整地址/收货点/门牌号/Wechat/WhatsApp）。

## 7. 履约进度时间轴（置于详情最底部）

> 时间轴位于详情页最底部（第 ⑥ 块），承载订单全生命周期数据流：每个节点统一展示「节点 + 操作人 + 时间 + 结果」，是操作记录的追溯入口。节点含已下单 → 揽货指令下发 → 接单 → 揽货中/已揽货 → 待打包 → 已打包 → 已发货 → 已送达 → 已完成。

### 7.1 结构

竖向时间轴，左侧节点圆点 + 连接线，右侧节点卡。

```
●─ 已打包                       2025-02-10 13:40
│   打包人：李四 ｜ 完成打包复核
●─ 已揽货（揽货#1 吉隆坡前置仓）  2025-02-10 13:20
│   揽货人：张三 ｜ 含换货 1 项
○─ 已发货                        —
```

### 7.2 视觉规则

| 元素 | 规格 |
| ---- | ---- |
| 已完成节点 | 主色实心圆 11px + 主色连接线 |
| 当前节点 | 主色描边圆，节点名加粗 |
| 未到达节点 | 灰色空心圆 + 灰连接线，节点名与时间灰态，时间占位「—」 |
| 操作人 | 12px 深色，标注角色（接单/揽货人、打包人、发货人、系统、骑手） |
| 时间 | 11px 弱色，精确到分 |
| 异常节点 | 橙/红圆点 + 节点名同色，备注标异常类型 |

多张揽货指令时，「接单 / 已揽货」节点按指令各展示一行（标注揽货#N + 库房 + 揽货人），便于看清每个库房分别由谁、何时完成。

## 8. 订单商品（核心，整块单一卡片）

> 详情第 ③ 模块。切换栏、三数量汇总条、商品列表全部承载于**同一个白色卡片**内，商品之间用浅分隔线区分。重点是把「订单数量 → 实际揽货数量 → 打包复核数量」三个数量清晰对照出来。

### 8.1 切换栏

参考打包复核详情的横向分段切换栏，置于卡片顶部：

| 项 | 规格 |
| ---- | ---- |
| 容器 | 浅灰底 `--app-bg-soft`，高度约 44-52px，圆角 6-8px |
| 单项 | 最多一屏 4 项，超出横向滚动 |
| 当前项 | 白底浮层 + 顶部主色 2px 线 |
| 主文本 | 「全部」「揽货#1」「揽货#2」，12px / 600 |
| 辅助文本 | 揽货人姓名 + 状态图标（✅ 已揽货 / ⏳ 揽货中 / 🕗 待接单） |

- 选中「全部」→ 展示订单级三数量汇总条 + 商品三数量对照（§8.2）。
- 选中「揽货#N」→ 展示该指令实际揽货商品明细（§8.4）。
- 单库房（仅一张揽货指令）时切换栏可只保留「全部」。

### 8.2 三数量对照组件（重点）

商品行底部用**等宽三栏并列**展示，各栏「数值在上、标签在下」，竖向浅分隔线隔开，整体放在浅底条 `.qty-compare` 里：

```
┌───────────┬───────────┬───────────┐
│    3      │    2      │    2      │
│  订单数量  │  实际揽货  │  打包复核  │
└───────────┴───────────┴───────────┘
```

| 栏 | 取数 | 视觉 |
| ---- | ---- | ---- |
| 订单数量 | 订单原始下单数量 | 数值 16px / 600 深色，标签 11px 弱色 |
| 实际揽货 | `depot_task_skus.picked_quantity` 按 SKU 汇总（含换货商品） | 与订单数一致时常规色；少于订单数时 `--app-danger` 红橙 |
| 打包复核 | 打包出库数量 `outbound_order_items.quantity` 按 SKU 汇总 | 与实际揽货一致时常规色；不一致或未打包（显示「—」灰态）时区分 |

差异表达：三数量完全一致 → 三栏常规色 + 行右上角绿勾；实揽 < 订单 → 实揽栏红橙；复核 ≠ 实揽 → 复核栏红橙；未到打包阶段 → 复核栏「—」灰态。

### 8.3 订单级数量汇总条

切换栏下方一条订单级汇总（绿底 `--app-primary-soft`），呼应三数量口径：`订单数量 N ｜ 实际揽货 N ｜ 打包复核 N`，不一致的数量红橙强调。

### 8.4 「揽货#N」视图：该指令实际揽货商品明细

复用与「全部」视图**相同的商品行组件**（三数量对照 + 异常展示，见 §8.5），仅多展示货位并按指令分组：分组标题 `揽货#N ｜ 库房 ｜ 接单/揽货人` + 货位（主色 11px）+ 商品图/名/规格/条码 + 三数量对照 + 异常。

### 8.5 异常商品展示形态（参考揽货功能）

依据 `depot_task_skus`：`status`（3换货 / 4退货 / 6退差价）、`source_type`（1原订单 / 2换货）、`origin_id`（换货商品→原商品行）。五种形态：

| 形态 | 标签 | 数量表现 | 附加（单行紧凑） |
| ---- | ---- | ---- | ---- |
| 正常 | 无（绿勾） | 订单=实揽=复核 | — |
| 缺货 | 红「缺货」 | 实揽栏红橙 | `.p-note.bad`：「缺货 N 件」 |
| 退货 | 红「退货」 | 实揽/复核红橙 | `.p-note.bad`：「退货 N 件」 |
| 换货 | 橙「换货」 | 原商品实揽/复核红橙 | 换货配对块（无附加文案行） |
| 退差价 | 橙「退差价」 | 三数量一致 | 仅标签 |

> 标签即表达异常类型，附加行只保留必要数量（缺货 N 件 / 退货 N 件）；不显示「库存不足」原因与「仅标记/待退款」状态，保持紧凑。

**换货配对块 `.exch`**：浅灰底圆角块，缩进挂在原商品行下：

```
🧴 北海道牛奶 1L            [换货]
   订单 1 | 实揽 0 | 复核 0          ← 原商品（实揽/复核红橙）
   ╰→ 换货为
   🥛 明治醇香牛奶 1L
      实际揽货 1 | 打包复核 1         ← 换货商品：仅两数量，不显示订单数量
```

视觉：`.exch` 浅灰底，标题「╰→ 换货为」弱色 11px；换货商品图 40px；其数量用**两列 `.qty-compare.two`（实际揽货 / 打包复核）白底**，不含「订单数量」列。一个原商品可挂多条换货商品。换货商品实际揽货计入订单汇总，原商品对应数量为 0。

## 11. 关键交互设计

- **只读优先**：全页无作业控件；任何数量、状态均为展示态，不可编辑。
- **三数量对照为核心**：商品行固定以「订单 / 实际揽货 / 打包复核」三栏呈现，差异自动红橙强调，无需点击即可识别缺货、换货、退货、退差价。
- **换货配对**：原商品 ↔ 实际换货商品在同一行组内上下呈现，换货商品只展示实揽/复核两数量。
- **切换不改总览**：切换「全部 / 揽货#N」只刷新订单商品区，订单总览、记录卡、时间轴不变。
- **阶段未达占位**：未到达的环节对应数量与记录块以「—」或灰态占位，不隐藏，保持结构完整。
- **异常显著**：列表卡片、商品行三数量、时间轴节点三处对异常使用统一橙/红表达。
- **角标联动**：阶段页签待处理角标随配送筛选与搜索实时更新，与列表一致。
- **状态保留**：从详情返回列表保留筛选、排序与滚动位置。
- **多库房可追溯**：多揽货指令场景下，时间轴与揽货#N 视图均标注库房与揽货人。

## 13. 原型落地规则

- 新页面草稿先放 `public/wms-prototypes/_drafts/`，确认后按 APP 原型规则合并到 `pages/` 并接线（navigate + frameUrl + 菜单目录三处），不直接覆盖正式入口。
- 样式统一引用 APP UI 规范 Design Tokens，不新增一套订单跟踪专属颜色、圆角或阴影。
- 列表卡片复用发货管理列表结构，去掉勾选与统一发货操作、不含商品图；订单商品区复用打包复核分组与切换结构，复核步进器替换为只读三数量对照。
- 订单商品整块为单一卡片：切换栏 + 汇总条 + 商品列表（含换货配对块）同卡承载，商品之间用浅分隔线。
- 三数量对照作为可复用样式块 `.qty-compare`（三栏）与 `.qty-compare.two`（换货品两栏），订单级汇总条共用同一视觉语言。
- 详情页不出现任何作业按钮（扫码、步进、完成、确认、改址）。
- 多揽货指令必须保留指令分组与库房/揽货人信息，不平铺。
- 中英文兼容：三数量标签（订单数量/Ordered、实际揽货/Picked、打包复核/Reviewed）需预留英文长度，三栏按英文最长项校验等宽。
- 自包含约定：样本订单数据与控制器内联在页面 `<script>` 内，单文件保持 <50KB（check-wms-prototypes.sh 限制）。
