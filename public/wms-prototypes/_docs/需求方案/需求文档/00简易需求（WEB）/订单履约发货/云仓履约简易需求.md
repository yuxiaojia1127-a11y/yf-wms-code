# 云仓履约简易需求

> 文档用途：整合云仓履约背景、发货流程配置、发货流程处理规则、可售库存查询规则，作为研发实现与接口设计输入。\
> 文档状态：简易需求，待评审收口\
> 更新时间：2026-05-21

## 1. 需求背景

当前 WMS 已明确按多货主云仓模式建设，自营业务与第三方卖家业务共用一套底层履约体系。

现阶段存在两类典型业务差异：

| 业务场景    | 当前特征                               | 对 WMS 的影响                    |
| ------- | ---------------------------------- | ---------------------------- |
| 自营超市系统  | 一张订单仅支持一个前置仓发货，不需要分仓，但需要支持供应商虚拟仓发货 | 可沿用单仓履约模型，但底层仍需兼容统一云仓能力      |
| 第三方卖家云仓 | 一张订单的商品可能分布在不同仓库，可能需要分仓履约、集货发货     | 需要支持一张上游订单拆成多个履约子单、多个包裹、多个运单 |

本期需要统一以下口径：

1. OMS 如何向 WMS 创建云仓发货单。
2. 多渠道订单如何识别并加载对应履约规则。
3. 订单是否允许拆分、按什么粒度拆分。
4. 店铺绑定多仓时，WMS 如何按仓路由和配路由完成履约。
5. 电商系统如何查询某条履约规则下的可售库存。
6. 供应商虚拟仓如何参与履约和可售计算。

## 2. 本期目标

| 目标       | 说明                      |
| -------- | ----------------------- |
| 统一发货流程配置 | 形成研发可直接实现的发货流程配置表与处理规则  |
| 明确库存查询口径 | 明确单仓可售与规则网络可售两种查询方式     |
| 支持多仓履约   | 支持商家指定仓、云仓路由仓、多仓拆单履约    |
| 支持多渠道接入  | 支持自营渠道、第三方卖家渠道、其他电商平台渠道 |
| 统一虚拟仓口径  | 虚拟仓能力按 SKU 配置，不按订单配置    |

## 3. 核心业务口径

### 3.1 履约对象层级

| 对象   | 定义                        | 关系  |
| ---- | ------------------------- | --- |
| 上游订单 | OMS/电商系统下发给 WMS 的原始交易履约请求 | 1   |
| 履约子单 | WMS 根据库存、规则、仓配模式拆分出的执行单   | 1:N |
| 包裹   | 打包后的物理包裹                  | 1:N |
| 运单   | 承运商/配送平台生成的运输单号           | 1:N |

### 3.2 运输要求与最终履约模式

| 概念     | 含义                               | 来源         |
| ------ | -------------------------------- | ---------- |
| 运输要求   | 上游 OMS 对订单期望的配送模式、时效服务、服务承诺      | OMS 下单时传入  |
| 最终履约模式 | WMS 结合仓能力、库存分布、地址范围、规则配置后确认的执行模式 | WMS 规则引擎判定 |

规则说明：

1. OMS 下单时必须传入期望配送模式，如即时配送、快递物流、门店自提。
2. OMS 下单时建议同步传入时效服务，如预约送达（具体时间）、小时达（1/2/3/4小时达）、半日达、当日达、次日达、标准快递。
3. WMS 不承诺无条件按 OMS 要求执行，而是按仓、配、库存与规则校验后执行。
4. 若规则无法满足，WMS 返回拒单、改配建议、部分履约结果或拆单结果。

### 3.3 多仓与网络可售

| 口径      | 说明                        |
| ------- | ------------------------- |
| 店铺与仓库关系 | 一个履约店铺可绑定多个仓库             |
| 可售库存判断  | 对外可按店铺维度汇总多个仓库库存形成网络可售    |
| 实际履约分配  | 接单后按 OMS 指定规则执行：指定仓/指定配场景按上游指定执行，云仓路由场景由 WMS 按规则分配到一个仓或多个仓 |

### 3.4 虚拟仓口径

1. 虚拟仓能力按 SKU 配置，不按订单配置。
2. 同一订单中，部分 SKU 可走虚拟仓，部分 SKU 必须走实体仓。
3. 不支持虚拟仓的 SKU，不参与虚拟仓可售计算，也不能分配到虚拟仓履约。
4. 支持虚拟仓的 SKU，可按配置参与补货履约或全量虚拟履约。

建议 SKU 配置字段如下：

| 字段                          | 说明                                                  |
| --------------------------- | --------------------------------------------------- |
| `virtual_warehouse_enabled` | 是否支持虚拟仓                                             |
| `virtual_fulfillment_mode`  | `disabled` / `supplement_only` / `full_fulfillment` |
| `must_physical_warehouse`   | 是否必须实体仓履约                                           |
| `allow_qty_split`           | 是否允许按数量拆分                                           |

## 4. 发货流程配置表

| 配置项      | 字段编码                       | 配置值                                                     | 是否必配 | 规则说明                                            | 系统处理口径                   |
| -------- | -------------------------- | ------------------------------------------------------- | ---- | ----------------------------------------------- | ------------------------ |
| 渠道标识     | `channel_id`               | `easy_supermarket`、`third_party_platform`、`marketplace` | 是    | 标识订单来源渠道                                        | 用于匹配默认履约规则、库存口径、拆单能力     |
| 业务类型     | `business_type`            | `self_operated`、`merchant`                              | 是    | 自营/第三方卖家                                        | 决定默认是否允许分仓履约             |
| 货主       | `owner_id`                 | 字符串                                                     | 是    | 库存归属主体                                          | 用于库存隔离、仓网隔离、履约策略隔离       |
| 店铺       | `store_id`                 | 字符串                                                     | 是    | 履约店铺                                            | 用于绑定履约仓网络和配送规则           |
| 外部订单号    | `external_order_no`        | 字符串                                                     | 是    | 上游订单唯一标识                                        | 创建发货主单幂等校验               |
| 发货商品明细   | `order_lines`              | SKU + 数量                                                | 是    | 订单商品及数量                                         | 参与库存校验、拆单、路由             |
| 收货信息     | `receiver_info`            | 地址/联系人/电话                                               | 是    | 收货信息                                            | 用于仓路由、配路由、服务范围校验         |
| 运输要求     | `delivery_mode_required`   | `instant`、`express`、`pickup`                            | 是    | 上游期望配送模式                                        | 参与最终履约模式计算               |
| 服务时效     | `service_level`            | `2h`、`same_day`、`next_day`、`standard`                   | 建议必填 | 时效要求                                            | 参与仓配路由筛选                 |
| 拆单模式     | `split_mode`               | `by_sku`、`by_sku_qty`                                   | 是    | `by_sku`=按商品拆分不支持按数量拆；`by_sku_qty`=按商品拆分且支持按数量拆 | 决定同一 SKU 是否允许拆到多个履约子单    |
| 是否允许分仓履约 | `split_delivery_allowed`   | `true`、`false`                                          | 是    | 控制是否允许拆成多个履约子单/包裹                               | `false` 时必须单仓满足，否则拒单或转人工 |
| 仓路由模式    | `warehouse_route_mode`     | `merchant_assign`、`wms_assign`                          | 是    | 商家指定仓/云仓路由仓                                     | 决定仓库来源                   |
| 配路由模式    | `delivery_route_mode`      | `merchant_assign`、`wms_assign`                          | 是    | 商家指定配/云仓路由配                                     | 决定物流方式和承运商来源             |
| 指定仓      | `preferred_warehouse_id`   | 仓库 ID                                                   | 条件必填 | 当 `warehouse_route_mode=merchant_assign` 时必填    | WMS 只做仓可履约校验，不改仓         |
| 指定配送方式   | `preferred_delivery_mode`  | `instant`、`express`、`pickup`                            | 条件必填 | 当 `delivery_route_mode=merchant_assign` 时必填     | WMS 只做能力校验，不改配           |
| 指定物流商    | `preferred_logistics_code` | 物流商编码                                                   | 否    | 商家指定承运商                                         | 若指定则按承运商能力校验             |
| 是否允许改配   | `allow_delivery_adjust`    | `true`、`false`                                          | 是    | WMS 是否允许按规则更换配送方式                               | `false` 时不满足即拒单          |
| 发货失败处理   | `failure_strategy`         | `reject`、`manual_review`                                | 是    | 不满足履约规则时的处理方式                                   | 拒单或转人工审核                 |

## 5. 发货流程处理规则

| 规则编码          | 规则名称          | 触发条件                                                                                 | 处理规则                         | 输出结果                   |
| ------------- | ------------- | ------------------------------------------------------------------------------------ | ---------------------------- | ---------------------- |
| `FULFILL_001` | 创建云仓发货单       | OMS 提交订单                                                                             | 创建发货主单，记录渠道、货主、店铺、商品、地址、规则参数 | 生成 `delivery_order_id` |
| `FULFILL_002` | 多渠道识别         | `channel_id` 有值                                                                      | 按渠道加载默认履约参数                  | 带出默认拆单、仓配、库存口径         |
| `FULFILL_003` | 商家指定仓 + 商家指定配 | `warehouse_route_mode=merchant_assign` 且 `delivery_route_mode=merchant_assign`       | 校验指定仓库存、指定配送能力、指定物流商能力       | 成功则按指定仓指定配履约；失败则拒单     |
| `FULFILL_004` | 商家指定仓 + 云仓路由配 | `warehouse_route_mode=merchant_assign` 且 `delivery_route_mode=wms_assign`            | 固定指定仓，WMS 按地址、时效、物流规则选配送方式   | 输出实际配送方式/物流商           |
| `FULFILL_005` | 云仓路由仓 + 云仓路由配 | `warehouse_route_mode=wms_assign` 且 `delivery_route_mode=wms_assign`                 | WMS 按履约网络、库存、时效、成本自动选仓选配     | 输出实际履约仓和配送方式           |
| `FULFILL_006` | 按商品拆分         | `split_mode=by_sku`                                                                  | 同一 SKU 不可拆数量，只能完整归属一个履约子单    | 不满足则换仓或拒单              |
| `FULFILL_007` | 按商品 + 数量拆分    | `split_mode=by_sku_qty`                                                              | 同一 SKU 允许拆分到多个履约子单           | 输出多个子单明细               |
| `FULFILL_008` | 单仓履约校验        | `split_delivery_allowed=false`                                                       | 必须一个履约仓一次满足全部商品              | 不满足则拒单或转人工             |
| `FULFILL_009` | 多仓履约校验        | `split_delivery_allowed=true`                                                        | 允许拆成多个履约子单                   | 输出子单、包裹、运单关系           |
| `FULFILL_010` | SKU 级虚拟仓补货    | SKU 配置 `virtual_warehouse_enabled=true` 且 `virtual_fulfillment_mode=supplement_only` | 实体仓不足时允许虚拟仓补齐缺口              | 输出实体仓 + 虚拟仓混合履约        |
| `FULFILL_011` | SKU 级虚拟仓全量履约  | SKU 配置 `virtual_fulfillment_mode=full_fulfillment`                                   | 符合条件时允许虚拟仓独立承接               | 输出虚拟仓履约子单              |
| `FULFILL_012` | 改配校验          | `allow_delivery_adjust=true`                                                         | 指定配不满足时，允许改为可达配送方式           | 输出改配结果                 |
| `FULFILL_013` | 履约结果回传        | 发货单创建成功                                                                              | 回传实际仓、实际配、拆单结果、失败原因          | OMS 同步履约确认结果           |

补充说明：

1. 一张上游订单可拆成多个履约子单、多个包裹、多个运单。
2. 不同履约子单允许采用不同配送模式，但必须对子单级结果回传 OMS。
3. 自营默认以单仓履约为主；第三方卖家默认支持多仓履约。

## 6. 可售库存查询规则表

| 配置项      | 字段编码                     | 配置值                                   | 是否必配 | 规则说明          | 系统处理口径             |
| -------- | ------------------------ | ------------------------------------- | ---- | ------------- | ------------------ |
| 查询类型     | `saleable_query_type`    | `single_warehouse`、`network_rule`     | 是    | 单仓可售/规则网络可售   | 决定库存计算范围           |
| 渠道标识     | `channel_id`             | 同发货单                                  | 是    | 按渠道匹配库存规则     | 渠道不同可售口径可不同        |
| 业务类型     | `business_type`          | `self_operated`、`merchant`            | 是    | 自营/第三方        | 决定是否允许多仓汇总         |
| 货主       | `owner_id`               | 字符串                                   | 是    | 货主隔离          | 只计算当前货主库存          |
| 店铺       | `store_id`               | 字符串                                   | 是    | 店铺维度履约网络      | 用于匹配店铺绑定仓网         |
| SKU 列表   | `sku_list`               | SKU 集合                                | 是    | 查询商品集合        | 批量返回可售结果           |
| 期望数量     | `request_qty`            | 数字                                    | 否    | 购买数量          | 用于直接判断是否足量可售       |
| 收货区域     | `receiver_region`        | 省市区/经纬度                               | 建议必填 | 用于筛选服务范围内仓    | 影响规则网络可售结果         |
| 仓路由模式    | `warehouse_route_mode`   | `merchant_assign`、`wms_assign`        | 是    | 按实际履约方式查询     | 决定查单仓还是查规则仓网       |
| 指定仓      | `preferred_warehouse_id` | 仓库 ID                                 | 条件必填 | 单仓查询时必填       | 只计算该仓库存            |
| 配路由模式    | `delivery_route_mode`    | `merchant_assign`、`wms_assign`        | 是    | 配送方式约束        | 过滤不支持该配送的仓         |
| 服务时效     | `service_level`          | `2h`、`same_day`、`next_day`、`standard` | 否    | 时效约束          | 过滤不支持时效的仓          |
| 拆单模式     | `split_mode`             | `by_sku`、`by_sku_qty`                 | 是    | 决定网络库存可否按数量组合 | 影响可售计算逻辑           |
| 是否允许分仓履约 | `split_delivery_allowed` | `true`、`false`                        | 是    | 决定是否允许多仓组合可售  | `false` 时仅单仓足量才算可售 |
| 返回可售数量   | `saleable_qty`           | 数字                                    | 否    | 最终可售数量        | 用于前台是否可下单判断        |
| 返回可售类型   | `saleable_type`          | `single_warehouse`、`network_rule`     | 否    | 可售结果来源        | 前端展示与 OMS 判断使用     |
| 返回命中仓    | `matched_warehouses`     | 仓列表                                   | 否    | 命中的履约仓集合      | 用于 OMS 预览履约来源      |
| 返回规则编码   | `fulfillment_rule_code`  | 字符串                                   | 否    | 命中的规则编码       | 用于问题追踪             |

## 7. 可售库存计算规则

| 规则编码      | 规则名称         | 触发条件                                                                                 | 计算规则                                | 返回结果                     |
| --------- | ------------ | ------------------------------------------------------------------------------------ | ----------------------------------- | ------------------------ |
| `ATP_001` | 单仓可售查询       | `saleable_query_type=single_warehouse`                                               | 可售 = 可用库存 - 已预占 - 锁定库存              | 返回单仓 `saleable_qty`      |
| `ATP_002` | 规则网络可售查询     | `saleable_query_type=network_rule`                                                   | 先按店铺履约网络筛仓，再按仓配规则过滤，再计算可售           | 返回网络可售数量                 |
| `ATP_003` | 单仓足量判断       | `split_delivery_allowed=false`                                                       | 必须同一仓满足全部数量才算可售                     | 足量返回可售，不足返回 0            |
| `ATP_004` | 多仓组合判断       | `split_delivery_allowed=true` 且 `split_mode=by_sku`                                  | 不同 SKU 可分配不同仓，但同一 SKU 不可拆数量         | 返回按 SKU 组合后的可售结果         |
| `ATP_005` | 数量拆分判断       | `split_delivery_allowed=true` 且 `split_mode=by_sku_qty`                              | 同一 SKU 允许在多个仓按数量拼接可售                | 返回跨仓拼接后的可售数量             |
| `ATP_006` | SKU 级虚拟仓补货可售 | SKU 配置 `virtual_warehouse_enabled=true` 且 `virtual_fulfillment_mode=supplement_only` | 实体仓不足时，虚拟仓补足缺口后计入可售                 | 返回实体 + 虚拟补齐结果            |
| `ATP_007` | SKU 级虚拟仓全量可售 | SKU 配置 `virtual_fulfillment_mode=full_fulfillment`                                   | 虚拟仓可直接纳入网络可售计算                      | 返回包含虚拟仓的总可售              |
| `ATP_008` | 配送能力过滤       | 有 `delivery_route_mode` / `service_level` / `receiver_region`                        | 不支持区域、配送方式、时效的仓不参与可售计算              | 返回过滤后的可售                 |
| `ATP_009` | 指定仓可售        | `warehouse_route_mode=merchant_assign`                                               | 只查询指定仓，不允许跨仓汇总                      | 返回指定仓可售                  |
| `ATP_010` | 云仓路由可售       | `warehouse_route_mode=wms_assign`                                                    | 查询规则仓网下的可售能力                        | 返回规则网络可售                 |
| `ATP_011` | 可下单判断        | 提供 `request_qty`                                                                     | `saleable_qty >= request_qty` 判定可下单 | 返回 `can_sale=true/false` |

补充口径：

1. 可售库存查询按 SKU 逐条计算，不按整单统一判断虚拟仓能力。
2. 若 SKU 不支持虚拟仓，只能计算实体仓可售。
3. 规则网络可售是销售口径，不等于现场作业口径；实际履约仍需落到具体仓、包裹、运单。

## 8. 默认策略建议

| 场景                     | 默认仓路由             | 默认配路由        | 默认拆单模式       | 默认可售口径             |
| ---------------------- | ----------------- | ------------ | ------------ | ------------------ |
| `easy_supermarket`     | `merchant_assign` | `wms_assign` | `by_sku`     | `single_warehouse` |
| `third_party_platform` | `wms_assign`      | `wms_assign` | `by_sku_qty` | `network_rule`     |
| `marketplace`          | `wms_assign`      | `wms_assign` | `by_sku_qty` | `network_rule`     |

## 9. 研发实现要求

1. 发货主单固定一单一条，拆分后生成多条履约子单。
2. 履约结果必须回传实际履约仓、实际配送方式、履约子单、包裹、运单关系。
3. 可售库存查询只返回规则下可售结果，不直接暴露全部仓明细给前台。
4. 虚拟仓能力以 SKU 主数据配置为准，订单级不提供虚拟仓开关。
5. 若 OMS 不允许拆分且单仓库存不足，WMS 不能静默拆单，只能拒单或转人工。
