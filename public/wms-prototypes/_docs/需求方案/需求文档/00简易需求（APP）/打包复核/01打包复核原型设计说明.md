## 1. 设计目标

- 基于打包复核简易需求文档、打包复核 UI 参考图和 APP UI 规范，输出可直接用于还原原型的页面设计说明。
- 覆盖打包复核列表页、打包复核详情页、揽货单切换、商品复核行、扫码复核状态、完成打包底部栏与异常弹窗。
- 核心体验目标：扫码为主路径，订单级合单清楚，已揽商品与复核进度一眼可辨，完成打包前校验明确。

---

## 2. 设计范围

### 2.1 本期范围

- 打包复核列表页：搜索、配送页签、时间排序、任务卡片、底部扫码入口。
- 打包复核详情页：任务摘要、订单信息卡、收货人信息、揽货单切换区、复核商品列表。
- 合单打包展示：同一订单下多张揽货单以「全部 / 揽货#N」切换。
- 商品复核行状态：待复核 / 复核中 / 已完成 / 异常提示。
- 扫码复核交互：扫商品条码自动累加复核数量，达成揽货数量后自动完成。
- 底部三段操作栏：任务指派 / 扫码 / 完成打包。
- 完成打包校验弹窗：未全部揽货、未完成复核、订单已拦截。

### 2.2 暂不涉及

- 揽货员接单、去揽货、完成揽货页面。
- 退货、换货、退差价等异常商品处理 UI。
- 打包耗材、包裹重量、包裹尺寸、面单打印。
- 物流发货交接与发货确认页。
- 订单拦截处理详情页。
- 任务指派完整流程（本期仅保留入口）。

## 4. 页面关系

| 来源页面 | 触发动作 | 目标页面 | 带入参数 |
| ---- | ---- | ---- | ---- |
| 工作台 > 打包 | 点击模块卡片 | 打包复核列表页 | 当前仓库 / 当前角色 |

## 5. 页面设计

### 5.1 列表页整体骨架

列表页参考「打包复核」UI 图，采用标准移动页结构：顶部浅青背景区 → 搜索区 → 配送页签 → 任务卡片列表 → 固定底部扫码入口。

- 页面背景：`--app-bg #F5F7F8`。
- 顶部可使用浅青背景 `--app-primary-soft #DDF8F2`，高度覆盖导航与搜索区。
- 内容左右安全边距 `12px`。
- 列表卡片白底，圆角 `8px`，卡片间距 `8px-10px`。
- 底部扫码入口固定，需避开 iPhone 底部安全区。

### 5.2 顶部导航与搜索区

**顶部导航**

- 高度 `44px`，左侧返回图标，居中标题「打包复核」，标题 16px / 600。
- 导航区不放多余说明文字，保持作业场景紧凑。

**搜索区**

| 元素 | 规格 |
| ---- | ---- |
| 搜索框 | 白底或弱灰底胶囊，圆角 `16px-18px`，高度约 34px |
| 左侧图标 | 扫码/识别图标，深色线性图标，尺寸 18-20px |
| placeholder | 「请输入订单号/联系人/任务ID」，12px `--app-text-muted` |
| 搜索按钮 | 主色胶囊按钮，文字「搜索」，高度与输入框一致，右侧贴合 |

交互：点击搜索框进入输入态；点击左侧扫码图标可直接唤起扫码；点击「搜索」按订单号、联系人、任务ID 模糊查询。

### 5.3 配送页签与排序

参考 UI 图中的「即时配送 / 物流发货」结构：

- 页签区白底或极浅底，与搜索区下方衔接。
- 当前页签：文字 16px / 600，颜色 `--app-text`，底部主色短下划线。
- 未选页签：文字 16px / 400，颜色 `--app-text-secondary`。
- 右侧排序入口：文字「时间」+ 上下箭头，12px；激活方向使用主色。
- 页签切换后列表刷新，保持搜索条件；排序切换只改变当前页签下任务顺序。

### 5.4 任务卡片设计

任务卡片复用 APP UI 规范 8.4 的任务列表卡片模式。

| 元素 | 设计规格 |
| ---- | ---- |
| 卡片容器 | 白底 `#FFFFFF`，圆角 `8px`，内边距 `10px-12px`，轻阴影 `--app-shadow-card` |
| 联系人 | 左上角标题，如 linzhaobin，14px / 600，深蓝黑色 |
| 状态标签 | 右上角小圆点 + 状态文字；待复核绿色，复核中橙色，已打包蓝色 |
| 字段区 | 左右两列对齐，字段名 12px 弱色，字段值 12px 深色 |
| 商品数量 | 展示 `3（共10件）`，与详情页复核商品数量口径一致 |
| 分隔线 | 字段区与按钮区之间使用虚线或极浅实线 `--app-border` |
| 操作区 | 右对齐，次按钮「复核详情」浅灰底，主按钮「开始复核 / 继续复核」主色底白字 |

状态规则：

| 状态 | 颜色 | 主按钮 | 说明 |
| ---- | ---- | ---- | ---- |
| 待复核 | `--app-success #68B92E` | 开始复核 | 订单所有揽货单已完成，等待打包人员复核 |
| 复核中 | `--app-warning #D99A19` | 继续复核 | 已有复核数量或打包人员进入过详情 |
| 已打包 | `--app-info #2F80ED` | 查看详情（可选） | 历史态，默认可不展示在待处理列表 |

### 5.5 列表页底部扫码入口

底部固定白色操作栏，高度 `56px` + 安全区，顶部 `--app-border` 细线。

```
          [  扫码图标  打包复核  ]
```

- 主按钮居中，宽度约 214px，高度 44px，主色胶囊，文字 16px / 500。
- 左侧使用白色扫码图标，图标尺寸约 20px。
- 点击后唤起扫码，扫到订单号/任务ID直接进入对应打包复核详情页；扫到商品条码时，若能唯一定位待复核任务，则进入详情并提示已匹配商品，否则提示选择任务。

## 6. 详情页设计

### 6.1 详情页整体骨架

详情页参考「打包复核详情」与「打包复核详情-其他情况」UI 图，复用揽货详情展开态的作业骨架：

1. 顶部导航：返回 + 页面标题「打包复核」。
2. 任务摘要：状态标题、任务ID、订单号、配送信息。
3. 订单信息卡：仓库、预约送达时间、缺货偏好、订单备注、收货人、邮编、收货详情。
4. 复核商品汇总：`复核商品: N（共N件）`。
5. 揽货单切换区：`全部 / 揽货#1 / 揽货#2 / 揽货#3`。
6. 商品分组卡：按揽货单展示商品复核行。
7. 底部操作栏：任务指派 / 扫码 / 完成打包。

详情页不展示退货、换货、退差价操作按钮。打包复核只处理实际已揽商品的数量核对。

### 6.2 任务摘要区

| 元素 | 规格 |
| ---- | ---- |
| 状态标题 | 「待复核 / 复核中 / 已打包」，20px / 600，左对齐 |
| 任务ID | `任务ID 0000000000014`，13px，弱色字段名 + 深色值 |
| 订单号 | `SM2025002140190351`，13px，右侧浅蓝「复制」标签 |
| 配送信息 | `即时配送 ｜ 2小时内送达 ｜ XXXkm`，13px，深色文本 |

状态标题根据操作升级：默认「待复核」；首次扫码或手动调整复核数量后变为「复核中」；完成打包成功后变为「已打包」。

### 6.3 订单信息卡

订单信息卡沿用接单/揽货详情页字段层级，白底卡片，圆角 `8px`，内边距 `12px`。

| 字段 | 展示方式 |
| ---- | ---- |
| 仓库 | 左字段名，右侧仓库名称，如「吉隆坡前置仓」 |
| 预约送达时间 | 右侧展示时间或 `XXXXXXX` |
| 商品缺货时 | 橙色强调展示，仅作为订单偏好信息 |
| 订单备注 | 橙色强调展示，长文本最多两行，超出可展开 |
| 联系人 + 电话 | 人形图标主色，姓名 + 电话；右侧电话图标按钮 |
| 邮编 / 收货详情 | 邮编常规展示；「收货详情」使用信息蓝色链接，可展开灰底详情块 |

展开收货详情时，在卡片底部增加浅灰补充块，内容包括完整地址、收货点、门牌号、Wechat、WhatsApp；不改变商品区顺序。

### 6.4 复核商品汇总

复核商品区标题位于商品列表上方：

```
复核商品: 3（共10件）
```

- 标题 14px / 600，颜色 `--app-text`。
- 数字与总件数保持常规色，不使用过强红色；仅商品行内价格和数量使用红橙强调。
- 若当前选中某一揽货单，标题仍展示订单级总数，分组标题展示当前揽货单数量。

## 7. 揽货单切换区

### 7.1 切换区结构

切换区参考 UI 图中的横向灰底分段栏，固定在复核商品标题下方或随内容滚动到商品区顶部。

| 项 | 规格 |
| ---- | ---- |
| 容器 | 浅灰底 `#E9EEF0` 或 `--app-bg-soft`，高度约 44-52px，圆角 6-8px |
| 单项 | 等宽或内容自适应，最多一屏展示 4 项，超出横向滚动 |
| 当前项 | 白底浮层，顶部主色 2px 线，底部小三角指示，可轻微阴影 |
| 主文本 | 「全部」「揽货#1」「揽货#2」，13px / 600 |
| 辅助文本 | 揽货员姓名，如「张三 / Cannie / liqiqi」，10px 弱色 |
| 状态图标 | 对勾、等待、箱体等小图标，尺寸 10-12px |

### 7.2 状态标识

| 状态 | 图标/颜色 | 说明 |
| ---- | ---- | ---- |
| 已完成揽货且可复核 | 绿色对勾 `--app-success` | 当前揽货单商品已进入复核范围 |
| 等待其他揽货单 | 橙色等待标识 `--app-warning` | 该订单仍存在未完成揽货单，不能完成打包 |
| 系统/特殊来源 | 蓝色小图标 `--app-info` | 与参考图保持一致，作为来源或扩展状态 |

视觉规则：

- 切换区只表达揽货单来源与状态，不承载复杂说明。
- 选中「全部」时，下方按揽货单顺序展示所有商品分组。
- 选中「揽货#N」时，只展示该揽货单商品分组。
- 单张揽货单场景可隐藏切换区，或仅展示「全部」一项，避免空占高度。

## 8. 商品复核行设计

### 8.1 商品分组卡

每个揽货单使用白色分组卡承载，圆角 `8px`，内边距 `12px`。

```
揽货#1 ｜ 2（共7件）

[商品复核行]
[商品复核行]
```

- 分组标题 14px / 600。
- 数量说明 12px `--app-text-secondary`。
- 多个商品之间保留 `8px-10px` 间距，不用粗分割线。

### 8.2 商品基础信息层

商品行参考 APP UI 规范 8.6，使用浅青弱底小卡承载，圆角 `8px`，内边距 `8px-10px`。

| 元素 | 规格 |
| ---- | ---- |
| 货位编码 | 主色货位/箱体图标 + 「常温区 A01-01-1」，11px 深色 |
| 条码 | 条码图标 + `5748754666`，11px 深色；可与货位左右分布 |
| 商品图片 | 52-60px，圆角 6px，左侧展示 |
| 商品名称 | 13px / 500，最多两行省略 |
| 商品SKU | 11px `--app-text-muted`，如 `10斤/有机/礼盒装 ｜ 0.5KG` |
| 售价 | `售价: RM145.00`，金额红橙 `--app-danger` |
| 成本价 | `成本价: RM30.00`，金额常规弱色 |
| 商品数量 | 右侧 `x3`，12px-13px，红橙强调 |

在「全部」视图下，同一商品可能出现在不同揽货单分组中；必须保留分组标题与货位编码，避免误以为是重复数据错误。

### 8.3 复核数量层

复核数量控件位于商品行右下角，参考 UI 图中的小型步进器。

```
−   2   +
```

- 容器高度约 28px，最小触控面积 24px。
- 边框 `--app-border`，圆角 4-6px。
- 减号、数字、加号三段等宽，数字 13px / 600。
- 扫码会自动累加数字；手动点击加减可修正现场误扫。
- 复核数量下限 0，上限为揽货数量；达到上限后继续扫码提示「该商品已完成复核」。

### 8.4 商品复核状态

| 状态 | 触发条件 | 视觉表现 |
| ---- | ---- | ---- |
| 待复核 | 复核数量为 0 | 商品行正常展示，步进数字为 0 |
| 复核中 | 复核数量大于 0 且小于揽货数量 | 步进数字显示当前数量；可在商品行右上角显示小型进度 `2/3` |
| 已完成 | 复核数量等于揽货数量 | 商品行右上角显示绿色对勾或「已完成」小标签 |
| 异常提示 | 扫到非本订单商品 / 超量扫码 | 商品行下方或 toast 使用红橙小字提示，不能整卡变红 |

已完成状态不改变商品行整体底色，避免列表跳动；只通过对勾、标签和步进数字表达。

## 9. 底部操作栏

详情页底部操作栏复用完成揽货页三段式底部栏，高度 `56px` + 安全区，白底，顶部 `--app-border` 细线。

| 区域 | 按钮 | 规格 |
| ---- | ---- | ---- |
| 左侧 | 任务指派 | 次按钮，白底/浅灰底，灰色描边，圆角胶囊，宽度约 80px，高度 38-40px |
| 中央 | 扫码 | 黑底圆形按钮，直径 48px，向上突出 8px，白色扫码图标 |
| 右侧 | 完成打包 | 主色胶囊按钮，宽度约 100-112px，高度 40px，文字 14px / 500 |

按钮状态：

- 「完成打包」默认可点击，但点击后执行强校验；若希望更强引导，也可在未全部复核时置弱禁用态并显示未完成原因。
- 「扫码」始终可用；已打包状态下进入只读时禁用扫码与完成打包。
- 「任务指派」本期仅入口预留，点击可 toast「任务指派功能待完善」。

## 10. 弹窗与提示

### 10.1 未全部揽货完成

- 标题：「暂不能完成打包」
- 正文：「订单仍有揽货单未完成，请等待全部揽货完成后再打包。」
- 按钮：单按钮「我知道了」主色胶囊。

### 10.2 存在未复核商品

- 标题：「还有商品未完成复核」
- 正文：「还有 N 件商品未完成复核，请核对后再完成打包。」
- 按钮：单按钮「继续复核」主色胶囊。

### 10.3 订单已拦截

- 标题：「无法完成打包」，标题可使用 `--app-danger #E85B4A`。
- 正文：「订单已拦截，无法继续打包，请前往拦截订单处理任务。」
- 按钮行：左「我知道了」浅灰胶囊，右「去处理」主色胶囊。

### 10.4 扫码异常 toast

| 场景 | 提示文案 |
| ---- | ---- |
| 扫到非当前订单商品 | 商品不在当前打包复核任务中 |
| 商品已达到复核数量 | 该商品已完成复核 |
| 列表页扫码无法定位唯一任务 | 未找到对应打包复核任务 |
| 网络异常 | 操作失败，请稍后重试 |

弹窗遵循 UI 规范 8.8：遮罩黑色 35%-45%，弹窗圆角 `12px-16px`，主按钮青绿色，取消按钮浅灰。

## 12. 关键交互设计

- **扫码主路径**：打包人员优先点击中央扫码按钮，扫商品条码后自动匹配商品并复核数量 +1；达到揽货数量后自动标记完成。
- **合单展示**：同一订单多张揽货单在一个详情页内统一展示，默认进入「全部」视图；切换单张揽货单只改变商品列表，不改变订单摘要。
- **同条码处理**：当前选中「揽货#N」时优先给该揽货单商品累加；选中「全部」时按未完成复核数量从前到后分配。
- **手动修正**：步进器允许打包人员修正误扫数量，但不能超过揽货数量，也不能低于 0。
- **完成打包强校验**：点击「完成打包」后依次校验揽货单是否全部完成、商品是否全部复核、订单是否拦截。
- **状态保留**：返回列表再进入详情时保留复核进度；列表卡片状态同步为「复核中」。
- **只读完成态**：已打包任务再次进入详情时，商品行可显示复核结果，但禁用扫码、步进和完成打包。

## 14. 原型落地规则

- 新页面草稿先放 `public/wms-prototypes/_drafts/`，确认后再按 APP 原型规则合并，不直接覆盖正式 APP 原型入口。
- 样式统一引用 APP UI 规范中的 Design Tokens，不新增一套打包复核专属颜色、圆角或阴影。
- 列表卡片、订单信息卡、商品行、底部操作栏尽量复用接单揽货与完成揽货原型结构，只替换打包复核字段和状态。
- 商品行至少支持 `review-pending`、`reviewing`、`review-done`、`review-error` 四类状态类，通过局部状态切换，不生成多套页面。
- 打包复核页面不出现退差价、退货、换货按钮；若后续业务需要异常处理，应进入独立异常处理流程。
- 合单打包必须保留揽货单分组信息，不能把所有商品无分组平铺，避免多库房、多揽货员场景下无法追溯来源。
- 中英文兼容：按钮文案（开始复核/Start、继续复核/Continue、完成打包/Complete Packing）需预留英文长度，按钮最小宽度按英文校验。
