> 本说明聚焦 **发货管理 > 待发货 > 选择 Lalamove > 车型选择/报价下单页（P3）** 的原型，并落地 06 文档三项调整：①订单来源标签 ②位置图查看 ③修改地址→实际发货地址（谷歌地图搜索）。P3 的基础结构已在 05 文档 §6 定义，本文档在其上补充三项调整的组件、状态与交互，不重复 P1 列表/P2 弹窗设计。

---

## 1. 设计目标

1. 在 P3 报价下单页的「路线规划」每个收货点（stop）上，清晰承载来源标签、位置图缩略图、修改地址入口，且不破坏既有路线卡片信息层级。
2. 新增「地址搜索页（谷歌地图）」，与现有 APP 搜索/列表组件一致。
3. 「实际发货地址」状态可视、可回看、可重新报价；与订单原地址清晰区分。
4. 三项调整均**数据驱动**（来源标签、位置图、实际发货地址来自后端，原型用样例 JSON 模拟），不写死。

## 2. 页面清单与流转

```text
P1 发货管理列表（待发货）
  └─ 勾选订单 → 统一发货 → P2 确认发货弹窗 → 选 Lalamove + 确定
        └─ P3 车型选择/报价下单页  shipping-lalamove.html   ← 本文档主体
              ├─ 路线规划卡（每 stop：来源标签 / 位置图缩略图 / 修改地址 / 备注）
              ├─ M1 位置图放大预览
              ├─ P4 地址搜索页（谷歌地图）  address-search.html
              ├─ 车型选择 / 取货时间 / 服务类型 / 钱包余额 / 报价
              └─ 确认订单 → P5 支付下单页 → 调 PlaceOrder → 下单成功
P5 支付下单页（确认下单）  shipping-pay.html              ← 新增
P6 发货详情页（Lalamove 配送详情/状态查询）  shipping-delivery-detail.html  ← 新增
  （从 P1 已发货列表「订单详情」进入）
```

| 来源 | 触发 | 目标 | 带入/回传 |
| ---- | ---- | ---- | ---- |
| P3 stop | 点位置图缩略图 | M1 放大预览 | `address_images` |
| P3 stop | 点「修改地址」 | P4 地址搜索 | picking_order_id + 原地址 |
| P4 | 选定候选地址 | 返回 P3| 实际发货地址(文本+经纬度) |
| P3 | 实际发货地址变更 | 重新 Quotation | stop 新坐标 |
| P3 | 确认订单 | P5 支付下单页 | quotation_id + 车型 + 服务 + 各 stop 地址 |
| P5 | 确认订单 | PlaceOrder → 下单成功 | 配送单/出库单/订单转已发货 |
| P1 已发货列表 | 订单详情 | P6 发货详情页 | delivery_order_id |
| P6 | 加小费 / 确认修改 / 配送取消 | 重新报价下单 / 取消 | priority_fee / delivery_status |

> 三页地址展示口径一致：**有实际发货地址展示实际发货地址（原地址+实际发货地址上下对比），否则只显示原地址**；每个收货点备注行统一为「**备注**」（`picking_orders.remark`，早期占位文案「门牌号收货点」作废）。

## 3. P3 路线规划卡片（核心调整区）

### 3.1 调整后 stop 卡片结构

```text
┌─────────────────────────────────────────────┐
│ ①  Liuzhaobin | 5392000                  × ⠿ │  ← 序号 + 联系人|邮编 + 删除/拖拽
│    订单原地址                                   │
│    room15, crush cosss, malaysia street …      │  ← 未改址只显示这一行地址
│    ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
│    实际发货地址                                 │  ← 改址后才出现，与原地址上下对比
│    LiveIn @ The Hamilton Wangsa Maju …         │
│    [🖼缩略图] [🖼缩略图]                         │  ← 位置图：有图直接显示缩略图，点击放大
```

各 stop 卡背景沿用截图配色（①绿/②米/③蓝弱底，仅区分顺序，非状态色）。

> 关键调整（对齐最终原型）：①订单来源标签下移到底部操作行、「修改地址」前，不占额外行、不放联系人行；②位置图直接显示缩略图（点击放大），不再是文字入口；③实际发货地址在卡片内「订单原地址 / 实际发货地址」上下两行直接对比，无标签徽标、无弹窗；④移除「门牌号收货点」输入框。

### 3.2 组件规格

| 元素 | 组件/样式 | 数据 | 说明 |
| ---- | ---- | ---- | ---- |
| 序号圆标 | 主色圆形 `--app-primary` + 白字数字 | stop_index | 沿用现有 |
| 联系人\|邮编 | 14px/600 `--app-text`，flex 撑开、超长省略 | receiver_name + postal | 头部行只留 序号+联系人+✕+拖拽 |
| 删除/拖拽 | ✕ 关闭 + ⠿ 拖拽手柄 | - | 沿用现有，长按拖动调顺序 |
| 地址区 | 未改址：单行地址 12px；已改址：「订单原地址」(弱色) + 虚线 + 「实际发货地址」(深色加粗) 上下对比 | 原地址 / 实际发货地址 | 见 §6 |
| **位置图缩略图** | 缩略图行（50×50 圆角小图），点击放大 | `address_images` | 有图直接显示，无图隐藏，见 §5 |

> 操作行（来源标签 + 修改地址）放在地址区/缩略图下方，左对齐同一行排布；来源标签在前、修改地址在后，不额外占行。已移除「门牌号收货点」输入框。

## 4. 订单来源标签设计

- 位置：stop 卡**底部操作行、「修改地址」按钮前**（与修改地址同一行，不额外占行；不放联系人标题行——避免与联系人、删除/拖拽图标挤行）。
- 形态：小胶囊标签，10px，弱底 + 对应描边色，单行不换行。
- 取值（`picking_orders.order_source`，对齐 06 文档 §3.1）：

| 来源 | 中文标签 | 英文 | 建议色（弱底/描边） |
| ---- | ---- | ---- | ---- |
| 1 | 微信小程序 | WeChat Mini Program | `--app-success` 弱底 |
| 2 | H5 | H5 | `--app-info` 弱底 |
| 3 | APP | App | `--app-primary` 弱底 |

- 缺省（无来源）：不展示标签（不占位）。
- 标签仅展示、不可点击；不使用大面积高饱和底色（UI 规范 3.4）。

## 5. 位置图查看（缩略图 + M1 放大预览）

### 5.1 展示（直接缩略图，非入口按钮）

- 在地址区下方**直接以缩略图行展示**位置图（50×50 圆角小图，白底描边），无「位置图」文字标签。
- 仅当 `address_images` 非空时显示该缩略图行；无图不显示。
- 点击任一缩略图，从该张打开 M1 放大预览。

### 5.2 放大预览 M1

- 形态：居中/全屏图片预览层（UI 规范 8.8 弹窗规则，遮罩黑 45%）。
- 内容：图片轮播（左右切换 + 指示点），支持双指放大；顶部右上角关闭 ✕。
- 底部可显示 `1/3` 页码。
- 图片只读，不提供编辑/删除/上传（位置图为用户下单时上传，发货端只看）。
- 加载失败占位：灰底 + 「图片加载失败」弱字。

> 中英文：位置图 = Location Photo。

## 6. 修改地址 → 实际发货地址

### 6.1 P3 侧交互

- 点击 `✎ 修改地址` → 进入 P4 地址搜索页。
- 选定地址返回后：
  - stop 地址区**直接分两行上下对比展示**：上为「订单原地址」（弱色），虚线分隔，下为「实际发货地址」（深色加粗）。**无需点击弹窗即可对照**。
  - 「实际发货地址」仅以弱色小标题标注，不再使用徽标/标签，也不再有地址对照弹窗。
  - 触发**重新报价**（坐标变更，loading 态刷新金额）。
- 缺省：未改址的 stop 只显示一行订单原地址（无「实际发货地址」行）。

### 6.2 地址展示优先级

```text
实际发货地址记录存在 ?  → 上下对比展示：订单原地址(弱色) + 实际发货地址(加粗)
否                     → 仅展示订单原收货地址（单行）
```

> 对应 06 文档 §3.3 / §5.2：实际发货地址仅本次 Lalamove 下单生效，不改订单原地址、不改用户原始地址；下单 stop 取实际发货地址坐标。

## 7. P4 地址搜索页（谷歌地图）

对应截图「地址搜索」。新增页面 `address-search.html`。

### 7.1 结构

```text
[app-nav]   < 地址搜索
[search-row] 🔍 请输入小区/公寓/排屋/写字楼/酒店等        [搜索]
[map]        Google 地图（当前定位蓝点 + POI 标注）        [⊙定位]
[list]       候选地址列表
             ┌───────────────────────────────────┐
             │ Kuala Lumpur                        │
             │ Kuala Lumpur                        │
             ├───────────────────────────────────┤
             │ LiveIn @ The Hamilton Wangsa Maju   │
             │ Jalan Wangsa Delima, Wangsa Maju …  │
             └───────────────────────────────────┘
```

### 7.2 组件规格

| 区域 | 组件/样式 | 说明 |
| ---- | ---- | ---- |
| 顶部导航 | `app-nav` | 左返回，居中标题「地址搜索 / Address Search」 |
| 搜索区 | `search-row`>`search-box`+`search-btn` | placeholder「请输入小区/公寓/排屋/写字楼/酒店等」；主色「搜索」按钮 |
| 地图 | 地图容器（Google Maps） | 上半屏，当前定位蓝点、POI 标注；右下角主色圆形「定位」按钮 |
| 候选列表 | 列表行（名称 14px `--app-text` + 详细地址 12px `--app-text-muted`） | 行间 `--app-border` 细分割线；点选即回填返回 P3 |

### 7.3 交互

- 进入默认定位到原地址附近（或当前定位），地图与列表联动。
- 输入关键词「搜索」→ 调 Google Places 检索 → 刷新候选列表与地图标注。
- 点候选项：取其名称+详细地址+经纬度，作为**实际发货地址**回填 P3，标记该 stop 已改址并重新报价。
- 「定位」按钮：回到当前/原坐标。
- 返回（不选）：不改地址、不生成实际发货地址记录。
- 选定但无经纬度：提示「请选择有效地址」，不可回填（06 文档 §7）。

> 谷歌地图 SDK/Key 见 06 文档 §8 待确认；原型用静态地图图 + 样例候选列表模拟。

## 8. 报价/下单区（沿用 05 文档 §6，标注联动）

- 车型选择、取货时间、服务类型、钱包余额、报价金额、确认订单沿用 05 文档 §6。

## 8.5 P5 支付下单页（确认下单）

P3 选好车型/服务点「确认订单」后进入本页做最终确认，复用 UI 规范卡片与底部主按钮。

```text
[app-nav]   < 支付下单
[card] 其它信息
        +60 177638162            订单联系号码
        RM 607.70                wallet余额
[card] 订单信息
        ● Kuchai Supermarket（取货点）
        ① Liuzhaobin | 5392000                    [复制]
           订单原地址 …
           实际发货地址 …            ← 有改址才显示，与原地址上下对比
           备注：…
        ② / ③ …（合单多 stop 同结构）
        取货时间：Now                              ›
        车型选择：Motorcycle
        支付方式：Wallet              RM 20.00
[footer] [确认订单]
```

| 区域 | 组件/数据 | 说明 |
| ---- | ---- | ---- |
| 其它信息 | `sender_phone`（订单联系号码）、`providers.wallet_balance`（wallet 余额） | 弱底信息块 |
| 订单信息 | 取货点（库房）+ 各 stop：联系人\|电话 + 复制、收货地址、**备注** | 地址同 P3：有实际发货地址展示实际发货地址（原地址+实际发货地址上下对比） |
| 取货时间 / 车型 / 支付方式 | Now / `vehicle_type` / `payment_method`(Wallet) + `quote_amount` | 列表行，分隔线 |
| 确认订单 | 主色全宽胶囊按钮 | 调 PlaceOrder；成功后生成配送单/出库单、订单转已发货（04 §5），跳转下单成功/回列表 |

> 复用组件：`app-nav` + `card` + 列表行 + 底部主按钮；金额用 `--app-primary` 文字，钱包余额用 `--app-warning`。

## 8.6 P6 发货详情页（Lalamove 配送详情 / 状态查询）

从 P1「已发货」列表点「订单详情」进入，查看 Lalamove 配送状态与轨迹；待接单阶段可加骑手小费、确认修改、取消配送。

```text
[app-nav]   < 待接单 / 配送详情
[head] 🟢 待接单     派单时间: 12-24 12:00:00
[steps] ●待接单 ─ ○已接单 ─ ○已取货 ─ ○配送中 ─ ○已送达      ← 状态时间轴
[card] 添加骑手配送小费，调配更多骑手
        [+RM1.00] [+RM1.50] [+RM2.00]   [RM 自定义金额]
[card] 车型选择                          Motorcycle
[card] 配送路线
        ● Kuchai Supermarket（取货点）
        ① Liuzhaobin | 5392000          [复制]
           订单原地址 … / 实际发货地址 …
           备注：…
        ② / ③ …
[foot] 预估运费                 RM 20.00
        （钱包余额：RM 200.00）
        [配送取消]            [确认修改]
```

| 区域 | 组件/数据 | 说明 |
| ---- | ---- | ---- |
| 顶部状态 | 当前状态文案 + 派单时间 | `delivery_status` + `created_at` |
| 状态时间轴 | 待接单→已接单→已取货→配送中→已送达 | `delivery_status`(1/2/3/7) + `tracks` 节点；当前节点主色实心，未达置灰；**本期先展示状态** |
| 加骑手小费 | +RM1/+RM1.5/+RM2/自定义（胶囊选择 + 输入框） | `priority_fee`；选中态主色描边 |
| 车型选择 | 车型 | `vehicle_type`（只读展示） |
| 配送路线 | 取货点 + 各 stop：联系人\|电话+复制、收货地址、**备注** | 地址同 P3：有实际发货地址展示实际发货地址 |
| 预估运费 | 运费 + 钱包余额 | `quote_amount`+`currency`、`wallet_balance` |
| 底部操作 | 配送取消（次按钮）/ 确认修改（主按钮） | 取消→Lalamove 取消并写 `delivery_status=5`；确认修改→提交小费/改动重新报价下单 |

> 复用组件：`app-nav` + 步骤条（小圆点+连线，当前主色）+ `card` + 底部双按钮。状态色：待接单 `--app-success`、配送中 `--app-warning`、已送达 `--app-info`。完整轨迹明细/取消改派异常另行输出（04 文档约定）。

## 9. 状态与视觉映射

| 对象 | 状态 | 视觉 |
| ---- | ---- | ---- |
| 订单来源标签 | 微信小程序/H5/APP | 操作行小胶囊弱底（success/info/primary），无来源不展示 |
| 位置图缩略图 | 有图/无图 | 有图直接显示缩略图行（点击放大）；无图隐藏 |
| 实际发货地址 | 已改址/未改址 | 已改址：「订单原地址(弱色) + 实际发货地址(加粗)」上下对比；未改址：仅单行原地址 |

| 确认订单 | 可点/置灰/提交中 | 余额不足或报价失败置灰；提交中 loading 禁重复 |
