# 入库管理简易需求（1.0 简化版）

## 1. 基本信息

- 功能名称：入库管理
- 所属系统：WMS_WEB端
- 页面编号：`WMS-WEB-IN01`
- 所属模块：入库管理
- 文档定位：1.0 简化版 · 自营业务
- 适用范围：采购入库、退货入库、调拨入库、其他入库
- 版本说明：1.0 版本仅支持 WEB 端操作，在新建入库单页面通过扫码添加商品行，提交后直接完成入库并更新库存，不涉及 APP 端、收货任务、质检任务和上架任务。

---

## 2. 核心结论

### 2.1 WMS 管理对象

| 对象 | 主键/编码 | 管理口径 | 作用 |
| --- | --- | --- | --- |
| 入库单 | 入库单号 | 入库业务主单 | 承接采购、退货、调拨等入库来源，是本版本核心操作对象 |
| 入库明细 | 入库单号 + SKU | 入库商品明细 | 记录每个 SKU 的入库数量、批次、效期和实际入账数量 |
| 入库流水 | 流水号 | 库存增加记录 | 入库提交后为每条明细生成一条库存增加流水 |

### 2.2 核心规则

1. 1.0 版本入库操作全部在 WEB 端完成，不依赖 APP 端扫码收货。
2. 新建入库单时，通过扫描商品条形码逐行添加入库商品。
3. 条形码扫描成功后，系统自动填入 SKU 编码、商品名称、规格、单位，操作人手动填写入库数量。
4. 一条条形码可以对应多次扫描（重复扫描同一条码时，增加一行或累加数量，由操作人选择）。
5. 入库单提交后，系统直接将明细数量入账到对应仓库的实物库存，无需额外的上架操作。
6. 每次提交成功后生成入库明细记录和库存增加流水。
7. 入库明细和库存流水不可撤销，仅支持通过新建负数调整单修正。

---

## 3. 业务目标

1.0 版本入库管理以"快速入账"为核心目标，让操作人在 WEB 端通过扫码完成商品入库，提交后直接更新库存，减少入库步骤。适用于自营仓储的日常采购收货、退货入库和调拨到货等场景。

---

## 4. 功能范围

**本版本（1.0）包含：**

- 入库单列表查询与分页
- 新建入库单（选择入库类型、仓库、来源单号）
- 扫码添加入库商品行（条形码触发自动填充）
- 手动录入或修改商品行（SKU 编码、名称、数量、批次、效期）
- 删除商品行
- 保存草稿
- 提交入库（校验 → 库存入账 → 生成明细和流水）

- 取消草稿入库单

**本版本（1.0）不包含（留待后续版本）：**

- APP 端扫码收货
- 收货任务管理
- 质检任务管理
- 上架任务管理
- 入库差异处理
- 推荐库位

## 5. 入库类型

| 入库类型 | 来源单据 | 典型场景 | 说明 |
| --- | --- | --- | --- |
| 采购入库 | 采购单 / 到货通知 | 自营采购商品到仓 | 最常见的入库类型 |
| 退货入库 | 退货单 / 售后单 | 消费者退货、拒收退回 | 需填写退货原因 |
| 调拨入库 | 调拨单 | 仓间调拨到货 | 来源仓为调出仓 |
| 其他入库 | 手工创建 | 初始化库存、特殊补货 | 需填写入库原因备注 |

## 6. 状态流程

### 6.1 入库单状态

| 状态 | 含义 | 规则 |
| --- | --- | --- |
| 草稿 | 已创建、尚未提交 | 可编辑所有字段、可取消 |
| 提交中 | 已提交、系统处理中 | 短暂过渡状态，前端展示加载态 |
| 已完成 | 库存入账成功 | 只读，可查看明细和流水 |
| 已取消 | 草稿主动取消 | 保留记录，不参与库存操作 |
| 入库失败 | 提交后库存写入异常 | 可重试提交或联系管理员处理 |

### 6.2 状态流转图

```
新建
  └─→ 草稿 ──→ 提交中 ──→ 已完成
        │           └──→ 入库失败（可重试）
        └─→ 已取消
```

## 7. 关键流程

### 7.1 标准入库流程

1. 操作人在入库单列表页点击「新建入库单」，进入新建表单页。
2. 填写基本信息：入库类型、目标仓库、来源单号（可选）、备注（可选）。
3. 在商品明细区，将扫码枪光标定位到扫码输入框，扫描商品条形码。
4. 系统识别条码，自动在明细表格中插入新行，并填入 SKU 编码、商品名称、规格、单位。
5. 操作人在新行中填写入库数量，按需填写批次号、生产日期、到期日期。
6. 重复步骤 3–5，直至所有入库商品均已添加。
7. 操作人核查商品行信息，确认无误后点击「提交入库」。
8. 系统校验通过后，将各明细行数量写入对应仓库的实物库存，生成入库明细记录和库存增加流水。
9. 状态更新为「已完成」，页面跳转至入库单详情。

### 7.2 扫码添加商品行详细逻辑

| 步骤 | 操作 | 系统响应 |
| --- | --- | --- |
| 1 | 光标聚焦扫码输入框 | 输入框高亮，提示「请扫描或输入商品条形码」 |
| 2 | 扫码枪扫描条形码 / 手动输入后回车 | 系统触发条码查询 |
| 3a | 条码命中商品档案 | 自动插入新行，填充 SKU、名称、规格、单位；光标定位到该行「入库数量」字段 |
| 3b | 条码未命中 | 提示「条码未匹配到商品，请手动填写或检查商品档案」，仍插入空行供手动录入 |
| 3c | 条码已存在于当前明细 | 弹出提示：「该商品已存在，是否新增一行？」；选「是」则插入新行，选「否」则聚焦已有行的数量字段 |
| 4 | 操作人填写入库数量 | 数量必填，最小值 1 |
| 5 | 操作人填写批次号（可选） | 批次号不超过 50 字符 |
| 6 | 操作人填写生产日期 / 到期日期（可选） | 日期格式 YYYY-MM-DD；到期日期不早于生产日期 |
| 7 | 操作人继续扫下一个条码 | 输入框自动清空，等待下一次扫码 |

### 7.3 入库提交与库存入账逻辑

1. 提交时，系统逐行校验（见第 10 节规则）。
2. 校验通过后，系统按行执行库存增加：

```
库存增加 = 当前仓库 × SKU × 批次（可空）× 入库数量
```

3. 每行明细写入成功后生成一条库存增加流水，包含：入库单号、SKU、数量、仓库、操作人、操作时间。
4. 全部明细写入成功后，入库单状态更新为「已完成」。
5. 若任意一行写入失败，系统回滚本次入库并更新状态为「入库失败」，并记录失败原因。

### 7.4 入库明细记录逻辑

入库单提交成功后，系统为每一条商品明细生成一条入库明细记录，作为库存增加的凭证和追溯依据：

| 字段 | 来源 |
| --- | --- |
| 入库单号 | 自动生成 |
| 入库类型 | 操作人填写 |
| 来源单号 | 操作人填写（可空） |
| 仓库 | 操作人填写 |
| SKU 编码 | 扫码/手动填写 |
| 商品名称 | 商品档案自动填充 |
| 条形码 | 扫码输入 |
| 入库数量 | 操作人填写 |
| 批次号 | 操作人填写（可空） |
| 生产日期 | 操作人填写（可空） |
| 到期日期 | 操作人填写（可空） |
| 操作人 | 当前登录用户 |
| 提交时间 | 系统记录 |

## 9. 规则要求

### 9.1 入库单规则

- 入库单号由系统自动生成，格式：`IN-YYYYMMDD-NNNNNN`，全局唯一。
- 草稿状态可编辑全部字段。
- 已完成和已取消的入库单只读，不可编辑。
- 提交时商品明细不得为空，至少包含一行。
- 来源单号（如采购单号）建议填写，用于追溯，但非必填。

### 9.2 扫码与商品行规则

- 一次扫码对应新增一行，不自动合并相同 SKU。
- 同一 SKU 如需合并，操作人手动在已有行上修改数量，或在提示中选择合并。
- 所有字段中，入库数量为必填，最小值为 1，不支持小数。
- 条形码长度限制：6–20 位数字或字母数字组合。
- 商品档案中未维护的条码，允许手动填写 SKU 编码和商品名称后入库，系统记录为「未知商品条码」。

### 9.3 库存入账规则

- 提交入库后，系统按明细行逐行执行库存增加，写入目标仓库的实物库存。
- 库存以「仓库 + SKU + 批次号」为最小颗粒度进行聚合，批次为空则按「仓库 + SKU」聚合。
- 库存增加后，对应 SKU 的可用库存、实物库存同步更新。
- 每条明细行对应一条库存增加流水，流水一经生成不可删除。
- 若已存在相同「仓库 + SKU + 批次」的库存记录，则在原记录上累加数量；若不存在，则新建库存记录。

### 9.4 入库明细规则

- 入库明细随入库单提交成功后生成，与入库单一一对应。
- 入库明细不可单独编辑，如需纠正数量错误，需通过库存调整功能处理（后续版本）。
- 入库明细支持按入库单号查询和导出。

## 10. 校验要求

| 校验项 | 触发时机 | 校验规则 | 错误提示 |
| --- | --- | --- | --- |
| 入库类型 | 提交时 | 不可为空 | 请选择入库类型 |
| 目标仓库 | 提交时 | 不可为空 | 请选择目标仓库 |
| 商品明细 | 提交时 | 至少有一行有效明细 | 请添加至少一条入库商品 |
| 入库数量 | 实时 + 提交时 | 正整数，最小值 1 | 入库数量必须为正整数 |
| 到期日期 | 实时 + 提交时 | 不早于生产日期 | 到期日期不得早于生产日期 |
| 条形码格式 | 扫码后实时 | 6–20 位 | 条形码格式不正确 |
| SKU 编码 | 提交时 | 不可为空（条码未命中时需手动填写） | SKU 编码不能为空 |

## 11. 异常场景处理

| 异常场景 | 系统处理 |
| --- | --- |
| 条形码无法识别 | 插入空行并提示「条码未找到」，操作人手动填写 SKU |
| 同一条码重复扫入 | 弹出确认：「该商品已存在，是否新增一行？」 |
| 入库数量为 0 或负数 | 阻断提交并高亮错误行 |
| 仓库未选择 | 阻断提交并提示 |
| 明细为空 | 阻断提交并提示「请添加至少一条入库商品」 |
| 库存写入失败 | 回滚全部明细写入，状态变为「入库失败」，记录失败原因，支持重新提交 |
| 网络中断 | 数据已保存为草稿，提示「网络异常，数据已自动保存为草稿」 |

---

## 12. 验收要点

- 能在列表页查询草稿、已完成、已取消、入库失败的入库单。
- 能新建入库单，选择入库类型、仓库、来源单号。
- 扫描商品条形码后能自动添加新行，并自动填充 SKU 编码、商品名称、规格、单位。
- 条形码未匹配时能提示并允许手动填写。
- 重复扫码时能弹出确认提示。
- 能手动填写或修改商品行中的入库数量、批次号、生产日期、到期日期。
- 能删除单个商品行。
- 能保存草稿后再次编辑并提交。
- 提交入库后，各明细行的入库数量能正确增加到对应仓库的实物库存。
- 提交成功后能查看入库明细记录和库存增加流水。
