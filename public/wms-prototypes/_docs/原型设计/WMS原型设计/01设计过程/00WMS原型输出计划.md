# WMS原型输出计划

## 1. 计划目标

基于最新 API 接口清单、`00WMS功能清单.md` 和流程图，重新建立一套适用于当前版本的 WMS 原型输出计划，统一指导后续页面清单、原型说明、可交互原型和 PRD 回写动作。

本计划适用于以下两个系统：

- `WMS_WEB端`
- `WMS_APP端`

其中物流能力不再独立成系统，而是拆分并并入上述两个系统。

## 3. 输出原则

1. 只做 WMS 自身系统原型，不展开第三方电商系统页面。
2. 先做系统边界和信息架构，再做页面清单和页面原型说明。
3. 先做 P0/P1 主流程，再做 P2/P3 扩展管理能力。
4. 每轮页面原型说明输出前，必须先输出对应模块的简易版 PRD。
5. 每轮原型输出后，必须形成“原型设计反向变更清单”，识别是否需要回写 PRD 和功能清单。
6. 页面清单保持轻量，只承载页面目标、使用角色、页面入口、优先级和核心操作。
7. 页面原型说明负责补充需求来源、页面布局、核心数据、状态、异常和权限差异。
8. 所有状态、对象名称、主键口径必须与 API 和流程图保持一致。
9. 物流能力统一视为 `WMS_WEB端` 和 `WMS_APP端` 中的模块，不再按独立系统排期。

## 4. 核心执行闭环

| 步骤 | 输出物 | 说明 |
| ---- | ---- | ---- |
| 1 | 范围确认 | 确认本轮系统、模块、优先级、参考资料 |
| 2 | 简易版 PRD | 明确目标、角色、页面、流程、状态、异常、待确认项 |
| 3 | 原型方案 | 输出信息架构、页面清单、页面原型说明 |
| 4 | 原型反查 | 识别缺失页面、字段、状态、规则冲突和交互歧义 |
| 5 | PRD 回写建议 | 将新增规则、状态、筛选项、异常处理建议回写 PRD |
| 6 | 版本收口 | 记录本轮变更范围，进入下一轮 |

## 7. 每轮标准输出

### 7.1 简易版 PRD 固定结构

每轮正式输出原型前，先产出该模块的简易版 PRD，至少包含：

- 功能目标
- 适用角色
- 业务范围
- 页面清单
- 核心流程
- 状态流转
- 查询条件
- 列表字段
- 详情字段
- 关键操作
- 异常处理
- 权限控制
- 待确认项

### 7.2 原型输出固定内容

每轮原型产出至少包括：

- 页面清单
- 信息架构
- 页面清单
- 页面原型说明
- 原型设计反向变更清单
- PRD 回写建议

补充说明：

- 页面清单阶段统一只输出：`页面目标 / 使用角色 / 页面入口 / 优先级 / 核心操作`。
- 页面原型说明阶段再补充：`需求来源 / 页面布局 / 状态 / 异常 / 权限差异 / 交互细节`。

## 8. 当前建议执行顺序

1. 先确认新版 `WMS_WEB端` 信息架构和页面清单。
2. 再确认 `WMS_APP端` 的任务模型与物流交接模块边界。
3. 评审通过后，再按模块输出每轮简易版 PRD 和高保真原型说明。
