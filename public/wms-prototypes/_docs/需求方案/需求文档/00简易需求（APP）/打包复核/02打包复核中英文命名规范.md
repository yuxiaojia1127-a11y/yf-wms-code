# 仓库APP-打包复核中英文命名规范

> 更新日期：2026-06-13
>
> 本文档用于统一仓库 APP「打包 / 打包复核 / 完成打包」相关页面的中英文命名。适用范围包括工作台卡片、打包复核列表页、打包复核详情页、按钮、状态、字段与筛选项。
>
> **口径决定**：本模块作业口径统一使用「**打包**」。需求文档中以「复核」表达的状态与动作（待复核 / 复核中 / 开始复核 / 复核商品 / 复核数量等），在 UI 文案上统一改用「打包」口径（待打包 / 打包中 / 开始打包 / 打包商品 / 打包数量）。「复核」仅作为业务机制描述（扫码核对）保留在需求文档说明中，不作为面向作业人员的界面用词。
>
> 共享字段（仓库 / 配送方式 / 揽货单 / 邮编等）沿用 [`../接单揽货/04接单揽货中英文命名规范.md`](../接单揽货/04接单揽货中英文命名规范.md) 已确立的口径，保持两模块一致。

## 1. 命名原则

| 原则 | 说明 |
| ---- | ---- |
| 打包统一译为 Packing | 模块、状态、动作统一用 Packing。不单独用 Pack 作模块名（Pack 更像动词）。 |
| 作业口径用「打包」而非「复核」 | 面向打包人员的状态与按钮统一为 待打包 / 打包中 / 已打包、开始打包 / 完成打包；不在界面暴露「复核」。 |
| 扫码核对动作并入打包口径 | 详情页「复核商品 / 复核数量 / 复核状态」统一为「打包商品 / 打包数量 / 打包状态」，英文用 Items to Pack / Packed Qty。 |
| 状态避免裸用 Pending | 必须说明 pending 什么：待打包用 To Pack（短）/ Pending Packing（完整）。 |
| 沿用揽货规范的共享字段 | Warehouse 不用 Depot；Picking Details 不用 Pickup；Delivery Method 不用 Delivery；Scheduled Delivery Time 不用 Reserve Time；Carrier Shipping 不用 Logistics；Postcode 不用 Zip/Postal Code；揽货单 = Picking Slip。 |
| 短标签优先短英文，详情可用完整英文 | 工作台与 Tab 用 To Pack；详情页、文档可用 Pending Packing。 |
| Pick / Pack 词形对齐 | 揽货侧用 Pick（Items to Pick / Picked Qty），打包侧用 Pack（Items to Pack / Packed Qty），形成自然对照。 |

## 10. 不推荐用词

| 不推荐英文 | 推荐替代 | 原因 |
| ---- | ---- | ---- |
| Pack（单独作模块名） | Packing | Pack 更像动词，不像菜单名。 |
| Pack Review / Packing Review | Packing Tasks | 列表页用 Packing Tasks 与揽货侧 Picking Tasks 对仗；Review 会把"复核"带回界面。 |
| Go Pack | Start Packing | Go Pack 不地道。 |
| Pickup Details | Packing Details / Address Details | 打包任务详情用 Packing Details；收货地址用 Address Details。 |
| Pending（裸用） | To Pack / Pending Packing | Pending 太泛。 |
| Depot | Warehouse | 沿用揽货规范。 |
| Delivery（字段名） | Delivery Method | 「配送方式」不能只写 Delivery。 |
| Reserve Time | Scheduled Delivery Time | Reserve Time 不自然。 |
| Logistics | Carrier Shipping | 单独 Logistics 不够明确。 |
| Postal Code / Zip Code | Postcode | 马来语境统一 Postcode。 |
| Goods | Items | APP 字段用 Items 更自然。 |
| 复核 / 待复核 / 复核数量（界面用词） | 打包 / 待打包 / 打包数量 | 口径已统一为打包，界面不暴露复核。 |
| 未翻译中文（共N张揽货单 / 当日配送 / 尽快送达） | 见第 5.1 节 | 英文界面需完整翻译。 |
