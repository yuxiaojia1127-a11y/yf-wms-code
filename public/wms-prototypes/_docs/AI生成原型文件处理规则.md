# AI 生成原型文件处理规则

## 1. 目的

为了避免 AI 在修改原型时自动生成新的 HTML 文件，导致正式入口、预览、部署和线上版本混乱，当前项目统一采用“正式文件 + 草稿目录”的处理规则。

## 2. 正式文件

当前正式链路只认以下 3 个固定文件名：

- `public/wms-prototypes/02WEB端HTML版/WMS原型总入口.html`
- `public/wms-prototypes/02WEB端HTML版/WMS-WEB端原型.html`
- `public/wms-prototypes/03APP端HTML版/WMS-APP端原型.html`

以下动作只允许针对这 3 个正式文件执行：

- 总入口跳转
- 本地预览主链路
- Vercel 生产部署
- 线上正式访问

## 3. 草稿文件

AI 新生成的 HTML 文件一律先放到：

- `public/wms-prototypes/_drafts`

草稿文件只用于以下场景：

- 试验性新方案
- AI 自动重构稿
- 临时对比稿
- 待确认版本

草稿文件不允许直接作为正式入口，不允许直接写入总入口按钮路径，也不建议直接作为线上分享地址。

## 4. 推荐命名

草稿文件建议采用以下命名方式：

```text
YYYYMMDD-模块-用途.html
```

例如：

- `20260608-web-驾驶舱优化稿.html`
- `20260608-app-工作台重构稿.html`

不要再使用以下容易混淆的命名：

- `最终版.html`
- `最新版.html`
- `优化后.html`
- `副本.html`

## 5. AI 生成新文件后的处理方式

当 AI 自动生成了一个新的 HTML 版本时，按以下顺序处理：

1. 先确认该文件是否属于草稿
2. 如果是草稿，放入 `public/wms-prototypes/_drafts`
3. 先本地预览草稿文件
4. 确认方案可用后，再人工决定：
   - 覆盖正式文件
   - 只摘取其中部分改动合并到正式文件
5. 正式文件更新后，再走统一部署流程

## 6. 禁止事项

为了避免再次混乱，禁止以下做法：

- 让总入口直接指向 AI 临时稿
- 在正式目录里堆积多个“v1.2 / 最终版 / 优化版 / 副本”
- 部署时临时判断“这次发哪个 HTML”
- 把 `_drafts` 目录当成正式版本目录使用

## 7. 一句话原则

AI 可以生成新 HTML，但新 HTML 默认只是草稿；正式链路永远只认固定命名的正式文件。
