## 1. 设计目标

- 基于简易需求文档与 UI 设计稿，输出可直接还原原型的页面设计说明。
- 覆盖揽货详情页（作业态）、商品行多态（完成/退差价/换货/退货）、整单揽货标记浮层、换货商品扫码区、完成揽货底部栏与弹窗。
- 核心体验目标：扫码为主路径，单手可操作；商品状态一眼可辨；异常流程（换货/退货）不干扰正常拣货节奏。

---

## 2. 设计范围

### 2.1 本期范围

- 揽货详情页（作业态）整体骨架与字段布局
- 揽货商品行四态：readonly（待处理）→ 完成 / 退差价 / 退货 / 换货
- 换货商品扫码展开区
- 整单揽货标记按钮及确认弹窗（即采即销仓专属）
- 底部三段操作栏：任务指派 / 扫码 / 完成揽货
- 完成揽货校验弹窗（订单拦截 / 未处理商品二次确认）

### 2.2 暂不涉及

- 任务指派详细交互（入口预留）
- 实际退差价退款流程与换货物流安排
- 打包复核、发货等揽货后续流程
- 订单拦截详情处理页

## 3. 信息架构

```
仓库APP
└─ 我的任务（WMS-APP-001 > 我的任务页签）
   └─ 揽货详情-作业态（WMS-APP-002）
      ├─ 顶部导航（返回）
      ├─ 任务摘要区（状态标题 / 任务ID / 订单号 / 配送信息）
      ├─ 订单信息卡（库房 / 预约送达 / 缺货处理 / 备注 / 收货人 / 收货详情展开）
      ├─ 揽货商品区
      │  ├─ 整单揽货标记按钮（即采即销仓专属，右上角浮标）
      │  ├─ 揽货单标识行（揽货#N ｜ 第N/共N张揽货单）
      │  └─ 商品行（N条，每条支持四态切换）
      │     ├─ 商品基础信息行（货位 / 条码 / 图 / 名称 / 规格 / 售价 / 成本价）
      │     ├─ 操作按钮组（完成 / 退差价 / 退货 / 换货）
      │     ├─ 揽货数量步进控件（− N +，含退货数量标注）
      │     └─ 换货展开区（仅换货态可见）
      │        └─ 换货商品列表 + 「扫码换货商品」入口
      └─ 底部操作栏（任务指派 / 扫码 / 完成揽货）
```

## 5. 页面设计

### 5.1 整体骨架

复用接单揽货详情页骨架（规范 8.5.1）：顶部导航 → 任务摘要 → 订单信息卡 → 揽货商品区 → 底部操作栏。与接单详情的差异：

- 状态标题变为「已接单」→「揽货中」（首次操作后升级）
- 商品行从只读（readonly）升级为可操作（actionable）
- 底部操作栏从单按钮「确认接单」变为三段式「任务指派 / 扫码 / 完成揽货」

---

### 5.2 揽货商品区

**区块标题行**

```
揽货商品: 3（共10件）          [▲ 标记为整单揽货]（仅即采即销仓可见）
```

- 标题 14px / 600；数量部分常规色
- 整单揽货标记按钮：橙色标签样式（`--app-warning` 弱底 + 文字），右侧浮标，圆角胶囊，字号 12px；标记后变为灰色禁用「已标记整单揽货」

**批次标识行**（多张揽货单时展示）

- 格式：`揽货#N ｜ 第N/共N张揽货单`；「第N」使用 `--app-primary` 蓝绿色，12px
- 右侧可预留「标记为整单揽货」次入口（如区块标题空间不足时）

---

### 5.3 商品行设计（四态）

商品行整体用浅灰底容器 `--app-bg-soft`，圆角 8px，内边距 8-10px，商品间距 8px。

**基础信息层（所有态共用，只读）**

| 元素 | 规格 |
| ---- | ---- |
| 货位标签行 | 温区图标（主色）+ 「常温区 A01-01-1」；条码图标 + 条码号；字号 11px，灰底胶囊小标 |
| 商品主体行 | 图片 52-60px 圆角；商品名最多两行省略；规格 11px `--app-text-muted`；售价红橙 `--app-danger`；成本价常规色；右侧「x3」红橙 |

**操作按钮组**（基础信息层下方）

四个并排胶囊按钮：「完成」「退差价」「退货」「换货」

- 默认态：白底 + 深色文字，圆角 6px，高度 28px，字号 12px
- 选中态：`--app-primary #43B8A8` 底色 + 白字（完成/退差价/退货选中）
- 换货选中态：`--app-primary` 底色 + 白字
- 四态互斥：点击其中一个，其余恢复默认；再次点击取消选中（恢复 readonly 外观）

**揽货数量步进行**（操作按钮组下方）

```
揽货:  −  1  +        退货: 3（仅退货态展示）
```

- 「揽货:」12px `--app-text-secondary`；数字 14px / 600；±按钮 24px 最小触控面积
- 退货态时步进右侧附加「退货: N」橙色小字

**完成态视觉**：操作按钮「完成」选中，步进数量达目标值，商品行整体无其他变化（不加绿色背景，保持轻量）

---

### 5.4 换货展开区

仅「换货」态下，在步进控件行下方展开：

```
[ 换货商品列表（已扫码）]
  ▮▮ 5748754888   佳能Glad锡纸铝箔8m×30cm   x1   [×]
  ▮▮ 5748754999   其他商品                   x2   [×]

[ 扫码换货商品 ]（次按钮，左对齐）
```

- 换货商品行：浅灰底嵌套卡片（`--app-bg` 背景），字号 12px；右侧删除「×」小图标按钮
- 「扫码换货商品」：描边次按钮，圆角胶囊，主色边框 + 主色文字，字号 12px
- 若原商品尚无揽货标记，换货区顶部展示橙色提示行：「原商品没有揽货标记了」12px `--app-warning`

---

### 5.5 底部操作栏

遵循规范 8.5.2 多操作底部栏规则，高度 56px + 安全区，顶部 `--app-border` 分割线：

| 区域 | 按钮 | 规格 |
| ---- | ---- | ---- |
| 左侧 | 任务指派 | 次按钮，浅灰底，圆角胶囊，字号 13px，宽度约 80px |
| 中央 | 扫码 | 黑底（`#1F2329`）圆形图标按钮，直径 48px，内含扫码 SVG 图标（白色），向上突出底部栏约 8px |
| 右侧 | 完成揽货 | 主色胶囊按钮，圆角 22px，高度 40px，宽度约 100px，字号 14px / 500 |

---

### 5.6 整单揽货标记确认弹窗

遵循规范 8.8，居中弹窗：

- 标题：「确认标记整单揽货？」15px / 600
- 正文：「标记后前置仓将提前收到揽货任务，请确认当前揽货无缺货或换货问题。」12px 灰色，行高 1.6
- 按钮行：左「取消」浅灰胶囊，右「确认标记」主色胶囊

---

### 5.7 完成揽货校验弹窗

**场景一：订单已拦截**

- 标题：「无法完成揽货」红橙色标题
- 正文：「订单已拦截，无法继续揽货，请前往拦截订单处理任务。」12px 灰色
- 按钮：单一「去处理」主色胶囊（跳转入口预留，当前 toast 提示）

**场景二：存在未处理商品**

- 标题：「还有商品未标记」14px / 600
- 正文：「还有 N 件商品未完成揽货标记，是否确认提交？」12px 灰色
- 按钮行：左「继续揽货」浅灰胶囊，右「确认提交」主色胶囊

## 7. 关键交互设计

- **扫码主路径**：点击中央扫码按钮唤起扫码模块，扫到已知条码自动匹配对应商品并揽货数量 +1；满足目标数量自动标记「完成」；若当前有换货商品待添加（换货态激活），扫码结果作为换货商品添加。
- **四态互斥切换**：同一商品行的操作按钮组单选，切换时前一态视觉清除；步进数量保留，换货展开区随换货态开关。
- **步进触控**：减号下限为 0（不可低于 0），加号上限不强制（允许超量揽货）；退货数量独立计数。
- **整单标记不可撤销**：确认后按钮立即变灰色禁用态，页面其余操作不受影响。
- **返回保留进度**：返回「我的任务」列表后再次进入详情，商品行状态保留（前端本地状态，正式实现可接口持久化）。

## 9. 原型落地规则

- 新页面草稿先放 `public/wms-prototypes/_drafts/`，确认后合并至 `APP端HTML原型/pages/`。
- 样式统一引用 UI 规范第 9 节 Design Tokens，不新造颜色与圆角。
- 揽货详情骨架（任务摘要 + 订单信息卡）与接单详情页共享结构，差异仅在商品区与底部栏；原型实现时复用头部 HTML 片段，避免重复维护。
- 商品行需支持 `readonly`、`done`、`price-diff`、`return`、`exchange` 五类 CSS 状态类，通过 JS 切换，不生成多套独立 HTML。
- 中英文兼容：按钮文案（完成/Done、退差价/Price Diff、退货/Return、换货/Exchange）预留英文变长宽度（规范 3.6）。
