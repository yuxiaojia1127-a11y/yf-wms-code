# 仓库APP-接单揽货中英文命名规范

> 更新日期：2026-06-13
>
> 本文档用于统一仓库 APP「揽货 / 接单揽货 / 完成揽货」相关页面的中英文命名。适用范围包括工作台卡片、接单揽货列表页、揽货详情页、完成揽货页、按钮、状态、字段与筛选项。

## 1. 命名原则

| 原则 | 说明 |
| ---- | ---- |
| 仓内揽货统一译为 Picking | 本模块表达的是仓库揽货人员接到任务后，去货架或库位取货、扫码、标记并提交作业结果，属于 WMS 标准 Picking 场景。 |
| 接单表达为 Accept / Acceptance | 「接单」是作业人员领取并锁定任务，不是客户下单，也不是物流方接单。按钮用 Accept，状态或标题可用 Acceptance。 |
| 列表与状态避免只写 Pending | Pending 单独使用太泛，必须说明 pending 什么，例如 To Accept、Pending Acceptance、To Pick。 |
| 避免 Pickup | Pickup 更容易被理解为上门取货、客户自提、承运商取货，不适合表示仓内揽货作业。 |
| 短标签优先短英文，详情页可用完整英文 | 工作台卡片和 Tab 空间较紧，可用 To Accept、To Pick；详情页、弹窗、文档可用 Pending Acceptance、Pending Picking。 |

## 2. 模块与页面标题

| 中文 | 推荐英文 | 使用位置 | 备注 |
| ---- | ---- | ---- | ---- |
| 揽货 | Picking | 工作台模块卡片、一级功能模块 | 推荐作为模块名。 |
| 接单揽货 | Picking Tasks | 接单揽货列表页标题 | 比 Accept Order 更准确，表示这里是揽货任务池。 |
| 完成揽货 | Complete Picking | 完成揽货作业页标题 | 表达完成当前揽货任务的作业页。 |
| 揽货详情 | Picking Details | 详情按钮、详情页标题或区块名 | 不用 Pickup Details。 |
| 我的任务 | My Tasks | Tab、任务池入口 | 使用复数 Tasks。 |
| 待接单 | To Accept | 工作台统计、Tab、短状态标签 | UI 短标签优先使用。 |
| 待接单 | Pending Acceptance | 完整状态名、接口状态说明、文档说明 | 比 Pending 更明确。 |
| 待揽货 | To Pick | 工作台统计、短状态标签 | 表示已接单后等待实际揽货。 |
| 待揽货 | Pending Picking | 完整状态名、接口状态说明、文档说明 | 用于正式状态口径。 |

## 3. 工作台卡片命名

| 中文 | 推荐英文 | 说明 |
| ---- | ---- | ---- |
| 揽货 | Picking | 模块卡片标题。 |
| 待接单 | To Accept | 待揽货员接单的任务数。 |
| 待揽货 | To Pick | 已接单、等待开始或继续揽货的任务数。 |

推荐展示：

```text
Picking
To Accept
To Pick
```

## 4. 接单揽货列表页命名

### 4.1 顶部与搜索

| 中文 | 推荐英文 | 不建议 | 说明 |
| ---- | ---- | ---- | ---- |
| 接单揽货 | Picking Tasks | Accept Order / Order List | 页面展示的是揽货任务列表，不是普通订单列表。 |
| 请输入订单号/联系人 | Order No. / Contact Name | Order No. / Contact | Contact Name 更完整。 |
| 搜索 | Search | - | 标准按钮。 |
| 时间 | Time | - | 排序按钮可配上下箭头。 |

### 4.2 Tab 与筛选项

| 中文 | 推荐英文 | 说明 |
| ---- | ---- | ---- |
| 待接单 | To Accept | Tab 短标签。 |
| 我的任务 | My Tasks | 已由当前揽货员接单的任务。 |
| 全部 | All | 全部配送方式。 |
| 即时配送 | Instant Delivery | 即时配送/同城快速配送类任务。 |
| 物流发货 | Carrier Shipping | 由物流或承运商发出的任务；比单独 Logistics 更明确。 |

> ✅ 已确认：「物流发货」统一使用 Carrier Shipping。

### 4.3 列表状态与按钮

| 中文 | 推荐英文 | 使用位置 | 说明 |
| ---- | ---- | ---- | ---- |
| 待接单 | To Accept | 卡片右上角状态、短状态 | 不建议只写 Pending。 |
| 已接单 | Accepted | 卡片右上角状态 | 表示任务已被当前人员领取。 |
| 揽货详情 | Picking Details | 次按钮 | 空间紧张时可简写为 Details。 |
| 接单 | Accept | 主按钮 | 列表卡片按钮。 |
| 去揽货 | Start Picking | 主按钮 | 比 Pick Now 更正式。 |
| 暂无揽货任务 | No Picking Tasks | 空态 | 首字母大小写按界面风格统一。 |
| 未找到相关任务 | No Tasks Found | 搜索无结果 | 简洁明确。 |

## 5. 任务卡片字段命名

| 中文字段 | 推荐英文 | 不建议 | 说明 |
| ---- | ---- | ---- | ---- |
| 任务ID | Task ID | - | 保留 ID 大写。 |
| 库房 | Warehouse | Depot | WMS 仓储场景优先用 Warehouse。 |
| 配送方式 | Delivery Method | Delivery | Delivery 单独使用容易被理解为配送模块。 |
| 送达时间选择 | Scheduled Delivery Time | Reserve Time | 表达用户选择的送达时间。 |
| 预约送达时间 | Scheduled Delivery Time | Appt. Delivery | 页面空间足够时使用完整表达。 |
| 商品数量 | Qty / Item Quantity | Goods | 卡片标签用 Qty，完整可用 Item Quantity；件数单位统一用 pcs，如 `2 (3 pcs)`。 |
| 下单时间 | Order Time | - | 指消费者下单时间。 |

## 6. 揽货详情页命名

### 6.1 详情信息

| 中文 | 推荐英文 | 不建议 | 说明 |
| ---- | ---- | ---- | ---- |
| 订单号 | Order No. | - | 可用于复制字段。 |
| 复制 | Copy | - | 标准动作。 |
| 已复制 | Copied | - | Toast 文案。 |
| 商品缺货时 | Stockout Handling | Out of Stock | 这里是缺货处理方式，不只是缺货状态。 |
| 订单备注 | Order Note | Remark | Order Note 更具体。 |
| 收货人 | Recipient | Receiver | 两者都可用，推荐 Recipient。 |
| 收货详情 | Address Details | Pickup Details | 这里是收货地址详情，不是取货详情。 |
| 收货点 | Delivery Point | Pickup Point | Pickup Point 容易误解为自提点。 |
| 楼层/门牌号 | Floor / Unit No. | Floor/Unit | 可读性更好。 |
| 邮编 | Postcode | Zip Code | 马来西亚语境可用 Postcode。 |

### 6.2 揽货商品与揽货单

| 中文 | 推荐英文 | 不建议 | 说明 |
| ---- | ---- | ---- | ---- |
| 揽货商品 | Items to Pick | Picking Goods / Pick Items | Items to Pick 更自然。 |
| 揽货单 | Picking Slip | Batch | 若表达一张内部揽货指令，建议用 Picking Slip。 |
| 揽货#1 | Picking Slip #1 | Batch #1 | 用于多张揽货单分组。 |
| 第 1/2 张揽货单 | 1 of 2 Picking Slips | 1/2 slips | 用于批次说明。 |
| 售价 | Price | - | 商品售价。 |
| 成本价 | Cost | - | 商品成本价。 |
| 支付金额（已付金额） | Amount Paid | Payment | 该字段表达消费者已支付金额，用 Amount Paid。若另有"应付/订单金额"字段，再用 Payment Amount。 |
| 总成本价 | Total Cost | - | 标准金额字段。 |

推荐展示：

```text
Items to Pick
Picking Slip #1 | 1 of 2 Picking Slips
```

## 7. 接单动作与弹窗命名

| 中文 | 推荐英文 | 使用位置 | 说明 |
| ---- | ---- | ---- | ---- |
| 接单 | Accept | 列表主按钮 | 领取并锁定任务。 |
| 接单揽货 | Accept & Start Picking | 揽货详情页底部主按钮 | 接下该揽货单并进入揽货作业；接单(Accept)+去揽货(Start Picking)两动作合一。不用 Accept & Pickup。 |
| 确认接单 | Confirm Acceptance | 弹窗标题、详情页主动作 | 比 Confirm Accept 更自然。 |
| 取消 | Cancel | 弹窗按钮 | 标准按钮。 |
| 确认 | Confirm | 弹窗主按钮 | 弹窗中可不重复 Acceptance。 |
| 接单成功 | Accepted Successfully | Toast | 表示任务已领取成功。 |
| 任务已被接单 | Task Already Accepted | Toast / 异常提示 | 任务被其他人领取。 |
| 接单后任务将进入「我的任务」，请尽快完成揽货。 | After acceptance, the task will move to My Tasks. Please complete picking promptly. | 弹窗说明 | 保留业务含义。 |

## 10. 不推荐用词

| 不推荐英文 | 推荐替代 | 原因 |
| ---- | ---- | ---- |
| Pickup | Picking | Pickup 常指自提、上门取货或承运商取货，不是仓内拣货。 |
| Pickup Details | Picking Details / Address Details | 若是揽货任务详情，用 Picking Details；若是收货地址详情，用 Address Details。 |
| Pick | Picking / Start Picking / Picked | Pick 单独作为模块名不够像菜单名，更像动词。 |
| Pending | To Accept / Pending Acceptance / To Pick | Pending 太泛，无法判断待处理内容。 |
| Order List | Picking Tasks | 页面不是普通订单列表，而是揽货任务池。 |
| Accept Order | Picking Tasks / Accept Task | 容易误解为接受客户订单。 |
| Depot | Warehouse | WMS 仓储场景更常用 Warehouse。 |
| Delivery | Delivery Method | 字段名「配送方式」不能只写 Delivery。 |
| Reserve Time | Scheduled Delivery Time | Reserve Time 不自然，容易误解为保留时间。 |
| Goods | Items | APP 字段和商品列表中 Items 更自然。 |
| Batch | Picking Slip | 若表达一张揽货指令，不建议泛化成 Batch。 |
