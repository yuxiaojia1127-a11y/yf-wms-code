## 1. 设计目标

- 基于发货简易需求文档、发货 UI 参考图和 APP UI 规范，输出可直接用于还原原型的页面设计说明。
- 覆盖发货列表页、订单卡片、推荐发货展开区、底部统一发货栏、确认发货弹窗、物流信息表单、拦截订单提示。
- 核心体验目标：发货人员能快速找到待发货订单，按地址推荐合单，批量选择后一次确认物流并完成发货；待发货、推荐、已发货状态在移动端一眼可辨。

---

## 2. 设计范围

### 2.1 本期范围

- 发货列表页：顶部导航、搜索、状态页签、时间排序、配送类型筛选、订单卡片列表。
- 合单选择：单卡勾选、推荐订单勾选、底部已选数量、统一发货入口。
- 推荐发货：点击单卡「推荐发货」后展开前 5 张推荐订单，并展示订单当前状态。
- 确认发货弹窗：物流公司选择、Lalamove 模式提示、非 API 物流单号录入、物流信息上传。
- 发货校验提示：未选订单、非待发货订单、订单已拦截、物流字段缺失、API 下单失败。
- 发货成功反馈：提交成功后订单从「待发货」进入「已发货」或物流初始状态。

### 2.2 暂不涉及

- Lalamove API 下单参数、费用展示、重试策略、取消订单。
- 已发货后的物流轨迹、状态回调、物流异常处理详情。
- 订单拦截处理任务详情页。
- 订单指派完整流程。
- 出库单详情、库存流水详情、面单打印、费用结算和对账。

## 5. 列表页设计

### 5.1 整体骨架

列表页以参考图「发货」为主，采用标准移动页结构：顶部浅青背景区 → 搜索区 → 状态页签 → 二级筛选 → 发货订单列表 → 底部统一发货栏 / 底部主导航。

- 页面逻辑尺寸按 `375 x 812` 设计，左右安全边距 `12px`。
- 页面背景使用 `--app-bg #F5F7F8`，顶部导航和搜索区可叠加浅青背景 `--app-primary-soft #DDF8F2`。
- 列表卡片白底，圆角 `8px`，卡片间距 `8px-10px`，轻阴影 `--app-shadow-card`。
- 页面内容下方需为底部统一发货栏和 iPhone 安全区预留高度，避免最后一张卡片被遮挡。
- 页面中不放说明性大段文字，规则说明收敛到按钮、状态、弹窗和 toast。

### 5.2 顶部导航与搜索区

**顶部导航**

| 元素 | 规格 |
| ---- | ---- |
| 返回图标 | 左侧，24px 触控区，黑色线性图标 |
| 页面标题 | 居中「发货」，16px / 600，颜色 `--app-text` |
| 右侧区域 | 默认留空；后续可放扫码或更多图标 |

**搜索区**

| 元素 | 规格 |
| ---- | ---- |
| 搜索框 | 白底或弱灰底胶囊，圆角 `16px-18px`，高度约 34px |
| 左侧图标 | 搜索图标，18px，颜色 `--app-text-muted` |
| placeholder | 「请输入订单号/联系人/任务ID」，12px `--app-text-muted` |
| 搜索按钮 | 主色胶囊按钮，文字「搜索」，高度与输入框一致，宽度约 64px |

交互：

- 点击搜索框进入输入态；输入后点击「搜索」按订单号、联系人、任务ID 查询。
- 搜索条件与状态页签、配送筛选可叠加。
- 清空搜索后恢复当前页签下的默认列表。

### 5.3 状态页签与时间排序

状态页签参考 UI 图中的横向 Tab：

```text
全部   待打包   待发货   已发货   已完成   时间↕
```

| 状态 | 用途 | 默认展示 |
| ---- | ---- | ---- |
| 全部 | 展示当前仓库发货链路相关订单 | 可进入 |
| 待打包 | 打包前状态，只用于推荐和链路回看 | 可筛选，不可直接发货 |
| 待发货 | 本页核心作业列表 | 默认重点页签 |
| 已发货 | 查看已完成发货确认的订单 | 可筛选 |
| 已完成 | 查看履约闭环订单 | 可筛选 |

视觉规格：

- 当前页签：文字 16px / 600，底部主色短下划线，颜色 `--app-text`。
- 未选页签：文字 16px / 400，颜色 `--app-text-secondary`。
- 页签可横向滚动，右侧「时间」固定或靠右显示。
- 「待发货」列表默认按用户下单时间升序；点击「时间」切换升序/倒序，箭头激活方向使用 `--app-primary`。

### 5.4 配送类型筛选

二级筛选使用胶囊按钮组：

```text
[ 全部 ]   [ 即时配送 ]   [ 物流发货 ]
```

| 状态 | 样式 |
| ---- | ---- |
| 选中 | 深色底 `#1F2329` + 白字；或主色弱底 + 主色文字，按参考图优先使用深色胶囊 |
| 未选 | 白底，文字 `--app-text-secondary`，无边框或极浅边框 |

交互：

- 筛选只影响当前状态页签下的订单列表。
- 切换配送筛选时保留搜索条件和排序方向。
- 已选订单若不在新筛选结果中，可保留底部已选数量，但列表内不展示；点击统一发货时仍需校验。

## 6. 订单卡片设计

### 6.1 卡片容器

发货订单卡片参考 UI 图中的白色业务卡片，分为主订单卡片和推荐订单紧凑列表两种形态。

| 元素 | 规格 |
| ---- | ---- |
| 卡片背景 | `--app-card #FFFFFF` |
| 卡片圆角 | `8px` |
| 内边距 | `10px-12px` |
| 卡片间距 | `10px` |
| 阴影 | `0 4px 12px rgba(31, 35, 41, 0.06)` |
| 分隔线 | `--app-border #EEF0F2`，用于卡片内上下区分 |

### 6.2 待发货卡片结构

```text
[勾选] [预约单] 联系人 linzhaobin                         待发货
       [商品图] 订单编号: XXXXXXXXXXXXXXXXXXXX
              地址邮编: 5399234
              门店配送: 2小时内送达 | XXXkm
              送达时间选择: XXXXXXX
              商品数量: 1
              下单时间: 2025-02-10 12:00:00
       [订单详情] [订单指派] [联系用户] [确认发货]
       [推荐发货]（可作为次级文字按钮或卡片下方入口）
```

| 元素 | 规格 |
| ---- | ---- |
| 勾选控件 | 20px 圆形选择框，选中为主色圆底 + 白色对勾，未选中为灰色描边 |
| 订单类型标签 | 预约单使用主色弱底，实时单使用橙色弱底，10px / 500 |
| 联系人 | 14px / 600，颜色 `--app-text` |
| 发货状态 | 右上角文字或浅色状态角标，「待发货」使用信息蓝或绿色小圆点 |
| 商品图 | 52-60px，圆角 6px，左侧展示 |
| 字段名 | 12px，颜色 `--app-text-secondary` |
| 字段值 | 12px-13px，颜色 `--app-text` |
| 操作按钮 | 右对齐，次按钮浅灰底，主按钮青绿色底白字 |

按钮布局：

- 首行最多展示 4 个按钮：「订单详情」「订单指派」「联系用户」「确认发货」。
- 「确认发货」为单卡主动作，使用 `--app-primary`，高度 32-36px，圆角胶囊。
- 次按钮使用浅灰底，文字 `--app-text-secondary`。
- 若宽度不足，优先保留「订单详情」「确认发货」，「订单指派」「联系用户」进入更多操作或换行。

### 6.3 已发货卡片结构

已发货状态参考图中简化卡片，保留订单核心信息和后续查看入口：

```text
linzhaobin                                      · 已发货 | 待接单
仓库                         吉隆坡前置仓
地址邮编                     5399234
配送方式                     2小时内送达 | XXXkm
用户预约时间                 XXXXXXX
商品数量                     3（共10件）
下单时间                     2025-02-10 12:00:00
                              [搬货详情] [配送详情]
```

- 已发货卡片不展示勾选控件，避免误选。
- 状态组合采用小圆点 + 文案：`已发货 | 待接单 / 已接单 / 已取货 / 配送中 / 已送达`。
- 订单已发货后主操作降级为查看类按钮：「搬货详情」「配送详情」。
- 已发货状态色以橙色或信息色小面积表达，禁止整卡橙底。

### 6.4 卡片状态色

| 状态 | 建议样式 | 说明 |
| ---- | ---- | ---- |
| 待发货 | 绿色小圆点 `--app-success` 或蓝色描边标签 | 可执行发货 |
| 待打包 | 灰蓝描边标签 | 尚不能直接发货 |
| 待揽货 | 橙色描边标签 `--app-warning` | 推荐可见，不可直接发货 |
| 待接单 | 绿色描边标签 `--app-success` | 推荐可见，不可直接发货 |
| 已发货 | 橙色文字或信息色文字 | 已完成发货动作 |
| 已完成 | 绿色文字 | 履约闭环 |
| 已拦截 | 红橙小标签 `--app-danger` | 禁止发货 |

## 7. 推荐发货展开区

### 7.1 展开位置

点击主订单卡片的「推荐发货」后，在当前卡片下方展开推荐列表，最多展示 5 条。推荐列表属于当前订单卡片的子区域，不新开页面。

```text
[主订单卡片]
  ├─ 推荐订单行 1
  ├─ 推荐订单行 2
  ├─ 推荐订单行 3
  ├─ 推荐订单行 4
  └─ 推荐订单行 5
```

视觉规格：

- 推荐区背景使用极浅青或白底，避免与主卡片断裂。
- 每条推荐订单高度约 52-56px，行内使用细分割线。
- 推荐区不再重复展示商品图和长字段，只保留合单判断必须信息。

### 7.2 推荐订单行结构

```text
[勾选] Liuzhaobin | 5388234        [待发货]        详情 >
```

| 元素 | 规格 |
| ---- | ---- |
| 勾选控件 | 20px 圆形；待发货可选，非待发货禁用灰态 |
| 联系人 + 邮编 | 14px / 500，颜色 `--app-text` |
| 状态标签 | 小型描边标签，10px-12px |
| 详情入口 | 12px `--app-text-muted` + 右箭头 |

状态规则：

- 待发货订单：勾选可用，状态标签使用蓝色或绿色描边。
- 待打包 / 待揽货 / 待接单：可展示为推荐结果，但勾选控件禁用；点击勾选时 toast「该订单未进入待发货，暂不能统一发货」。
- 已拦截订单不建议出现在推荐结果；若后端返回，整行红橙提示并不可选。

### 7.3 推荐区交互

- 再次点击当前主卡「推荐发货」可收起推荐区。
- 点击其他订单的「推荐发货」时，默认收起上一张卡片推荐区，只保留一个推荐区展开，降低页面高度。
- 推荐订单勾选后加入底部已选数量；取消勾选同步移除。
- 推荐订单若已被主列表勾选，不重复计数，行内保持已选态。
- 推荐区顶部可不展示解释文字，避免占用现场作业空间。

## 8. 底部统一发货栏

底部统一发货栏参考 UI 图，固定在底部主导航上方或替代当前页面底部操作区域。

```text
[○]  已选6个                                      [统一发货]
```

| ---- | ---- |
| 容器 | 白底，顶部 `--app-border` 细线，高度 52-56px + 安全区 |
| 左侧勾选 | 20px 圆形，用于全选当前可发货订单 |

## 9. 确认发货弹窗设计

### 9.1 弹窗骨架

确认发货参考 UI 图中的底部弹层，使用底部抽屉形态：

| 区域 | 规格 |
| ---- | ---- |
| 遮罩 | 黑色 35%-45% 透明度 |
| 弹层位置 | 底部弹出，占屏高约 45%-70%，顶部圆角 `12px-16px` |
| 标题 | 「确认发货」或「确定发货」，16px / 600 |
| 表单标签 | 12px-13px，必填项前加 `*` |
| 物流公司按钮 | 小胶囊按钮，高度 28-32px，选中主色底白字 |
| 底部按钮 | 主色胶囊「确定」，高度 40px，居中或全宽 |

弹层上方若需要展示物流公司提示或地图/路线占位，可使用参考图中的灰色占位区；当前需求不展开路线细节。

### 9.2 Lalamove 模式

Lalamove 已对接 API，弹窗结构如下：

```text
提示条：Lalamove不需要填写单号和上传物流图
[路线/地图/接口信息占位区]

确认发货
* 物流公司
[Lalamove] [J&T Express] [XXXXXXX]

[确定]
```

视觉与交互：

- 顶部提示条使用浅蓝信息底，文字 12px，提醒发货人员无需手填单号和上传物流图。
- 选择 Lalamove 时，隐藏或禁用「物流单号」「物流信息上传」字段。
- 点击「确定」后进入 API 下单中状态，按钮显示「提交中」并禁用重复点击。
- API 成功后弹层关闭，列表中相关订单状态刷新为「已发货」或物流初始状态。
- API 失败时弹层保留，toast 或弹窗提示失败原因，允许再次点击「确定」重试。

### 9.3 非 API 物流 / 自营配送模式

J&T Express、其他物流、自营配送按手动更新物流状态处理：

```text
确定发货
* 物流公司
[Lalamove] [J&T Express] [自配送]

物流单号                                      请输入

物流信息
[ + ]
拍照上传

[确定]
```

字段规格：

| 字段 | 规格 |
| ---- | ---- |
| 物流公司 | 按钮组选中态为主色底白字，未选中白底灰边 |
| 物流单号 | 单行输入，右侧 placeholder「请输入」，底部分割线 |
| 物流信息 | 虚线边框上传框，约 `96 x 96px`，中间加号，底部文字「拍照上传」 |
| 确定按钮 | 主色胶囊，居中宽度约 220px 或全宽减左右边距 |

交互：

- 选择非 Lalamove 公司后，展示物流单号与物流信息上传区。
- 物流单号为必填；物流信息上传可按业务配置设置必填或选填。
- 自营配送与其他非 API 物流共用该表单，文案可显示「自配送」或「自营骑手」。
- 点击上传框唤起拍照/相册入口；原型中可用占位图模拟上传结果。

### 9.4 弹窗关闭

- 点击遮罩、返回键或弹层左上角关闭按钮时，关闭弹窗并保留列表已选状态。
- 表单已填写但未提交时，关闭不保存物流信息。
- 提交中状态不允许关闭，避免重复发货或状态不确定。

## 12. 关键交互设计

- **默认排序**：进入「待发货」页签后，订单按用户下单时间升序排列，更早下单的订单在前。
- **多选合单**：主卡片和推荐订单均可勾选；同一订单只计数一次；取消主卡勾选时，若该订单也在推荐区出现，应同步取消。
- **推荐发货**：点击「推荐发货」后按地址经纬度距离和订单状态优先级展示前 5 张推荐订单；推荐结果只辅助选择，不绕过发货资格校验。
- **推荐禁用态**：待打包、待揽货、待接单订单可展示但不可直接勾选发货；禁用态要可见，避免发货人员误以为系统漏单。
- **单卡确认发货**：点击单卡「确认发货」等同于只选择当前订单并打开确认发货弹窗；若当前还有其他已选订单，需弹窗提示「是否仅发当前订单」或默认带入全部已选，原型建议默认带入当前已选列表。
- **物流公司切换**：物流公司按钮组切换时，表单字段即时变化；从非 API 切回 Lalamove 时隐藏物流单号和上传区，但保留未提交输入值到本次弹窗关闭前。
- **提交防重复**：点击「确定」后按钮进入 loading/禁用态；提交完成或失败后恢复。
- **拦截优先**：发货提交前必须实时校验拦截状态；有任一订单被拦截时，本次提交不可继续。
- **已发货只读**：已发货卡片不允许勾选或再次确认发货，只保留搬货详情、配送详情等查看入口。

## 14. 原型落地规则

- 新增发货页面草稿先放 `public/wms-prototypes/_drafts/`，命名建议 `YYYYMMDD-发货-列表与确认弹窗.html`，确认后再按 APP 原型规则合并。
- 正式 APP 原型入口仍只保留 `public/wms-prototypes/APP端HTML原型/WMS-APP端原型.html`，不要直接覆盖正式文件。
- 样式优先复用 APP UI 规范第 9 节 Design Tokens，不新增一套发货专属卡片、弹窗、Tab 样式。
- 若使用参考图中的橙色「统一发货」按钮，必须先 token 化为发货批量动作色；不要在页面级样式里散落硬编码橙色。
- 列表卡片、搜索区、状态页签、胶囊筛选、底部操作栏应复用接单揽货、打包复核已有组件结构，只替换发货字段。
- 推荐发货区应作为订单卡片的局部展开状态实现，不生成一套独立页面。
- 发货弹窗应支持 `lalamove`、`manual-logistics`、`self-delivery` 三类视觉状态，通过类名切换字段显示。
- 状态类建议至少包含：`shipping-pending`、`shipping-selected`、`shipping-recommended`、`shipping-disabled`、`shipping-shipped`、`shipping-blocked`。
- 中英文兼容：按钮文案（确认发货 / Confirm Shipment、统一发货 / Ship Together、推荐发货 / Recommended）需预留英文长度，必要时按钮换行或进入更多操作。
- 页面实现时不写业务说明长文，不用大面积高饱和状态底色，不把推荐规则写成可见说明块；规则只通过可选/禁用/提示反馈表达。
