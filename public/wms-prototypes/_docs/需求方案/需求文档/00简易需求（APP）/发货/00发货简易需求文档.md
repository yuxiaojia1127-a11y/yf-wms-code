# 仓库APP-发货简易需求文档

> 版本范围说明：本文档覆盖发货人员在仓库APP中查看待发货订单、按地址与状态推荐合单、选择多张订单统一发货、选择物流公司并确认发货的流程。完成发货后，系统生成出库单、解冻前序已冻结库存，并将订单状态扭转为「已发货」。Lalamove API 下单细节、API 异常处理、物流轨迹跟踪、已发货后的物流跟踪明细由独立简易需求文档维护，不在本文档范围。

## 2. 业务说明

打包员完成打包后，将包裹放置到发货台。发货人员进入仓库APP「发货」页面，查看当前可发货订单，并根据收货地址、订单状态和发货方式选择一张或多张订单进行统一发货。

当前发货支持**合单发货**模式：发货人员可选择多张订单统一发货。对接物流公司时，多张订单统一发货表现为**一张物流订单对应多个收货点**；在 WMS 内仍需保留每张订单的发货结果、出库单、库存解冻和状态流转记录。

发货完成后，系统对本次发货批次内的每张订单执行：

- 生成对应出库单或出库记录。
- 解冻该订单前序已冻结库存。
- 记录发货人员、发货时间、物流公司、物流单号或物流订单标识。
- 订单状态扭转为「已发货」。

---

## 3. 功能描述

- 支持在仓库APP进入「发货」页面，查看发货任务列表。
- 支持按订单号 / 联系人 / 任务ID 搜索订单。
- 支持按订单状态切换：全部 / 待打包 / 待发货 / 已发货 / 已完成。
- 支持按配送类型筛选：全部 / 即时配送 / 物流发货。
- 「待发货」列表默认按照用户下单时间升序排序，优先展示更早下单的订单。
- 支持发货人员在列表中勾选多张订单，底部展示已选数量并提供「统一发货」主按钮。
- 支持在每张订单下点击「推荐发货」，系统加载前 5 张匹配度最高的推荐订单。
- 推荐订单可展示当前状态，便于发货人员判断是否适合合单；最终确认发货时必须通过发货资格校验。
- 支持查看订单详情、订单指派、联系用户、确认发货等操作入口。
- 支持选择物流公司进行发货，物流公司包含 Lalamove、J&T Express、自营骑手 / 自配送、其他物流等。
- Lalamove 已对接 API，可由 WMS 发起 API 下单；本页只承接物流公司选择与发货动作入口，不展开 API 下单字段和跟踪细节。
- 其他物流未对接 API，发货人员需先到对应物流平台手动下单，再回到 WMS 更新物流公司、物流单号和物流信息。
- 自营骑手 / 自配送按未对接 API 物流处理，发货人员直接在 WMS 更新发货物流状态。
- 操作发货时若订单已被拦截，系统禁止完成发货并提示：「XXX订单已拦截，无法继续发货，请前往拦截订单处理任务」。

## 5. 合单发货规则

| 规则 | 说明 |
| ---- | ---- |
| 支持模式 | 当前仅支持合单发货 |
| 发货批次 | 一次「统一发货」生成一个发货批次，批次内可包含多张订单 |
| 物流订单关系 | 对物流公司而言，一张物流订单可对应多个收货点 |
| WMS 订单关系 | WMS 需要按订单保留独立发货结果、出库单、库存解冻和状态流转 |
| 可选范围 | 待发货列表中的订单可直接勾选；推荐订单需通过发货资格校验后才可参与 |
| 重复选择 | 同一订单在当前发货批次中只能出现一次 |
| 统一确认 | 点击「统一发货」后进入确认发货弹窗，选择物流公司并提交 |

## 6. 推荐发货规则

### 6.1 触发方式

- 在订单卡片点击「推荐发货」。
- 系统以当前订单为基准订单，查询匹配度最高的前 5 张订单。
- 推荐结果在当前订单卡片下方展开，支持查看详情和选择符合发货资格的订单。

### 6.2 匹配范围

推荐候选订单状态包含：

| 状态优先级 | 状态 | 说明 |
| ---- | ---- | ---- |
| 1 | 待发货 | 优先推荐，可直接参与本次发货确认 |
| 2 | 待打包复核 | 地址接近但尚未完成打包，作为临近订单提示 |
| 3 | 待揽货 | 地址接近但仍在揽货阶段，作为临近订单提示 |
| 4 | 待接单 | 地址接近但尚未进入作业，作为临近订单提示 |

### 6.3 匹配排序

| 排序因素 | 规则 |
| ---- | ---- |
| 地址距离 | 根据收货地址经纬度计算距离，距离越近匹配度越高 |
| 订单状态 | 在距离接近时，按「待发货 > 待打包复核 > 待揽货 > 待接单」优先级排序 |
| 推荐数量 | 每次最多返回 5 张订单 |
| 基准订单 | 当前点击「推荐发货」的订单不出现在推荐结果中 |

> 若待发货订单不足 5 张，可用待打包复核、待揽货、待接单等临近订单补充展示，但这些订单不代表本次可直接完成发货。

## 7. 物流公司选择与发货方式

| 物流公司 / 模式 | 是否对接 API | 发货人员操作 | WMS 处理 |
| ---- | ---- | ---- | ---- |
| Lalamove | 是 | 选择 Lalamove 后点击确定；无需手填物流单号和上传物流图 | 发起 API 下单并保存返回的物流订单标识；API 下单细节另行维护 |
| J&T Express | 否 | 到 J&T 平台手动下单，回 WMS 填写物流单号并上传物流信息 | 保存物流公司、物流单号、附件和发货状态 |
| 自营骑手 / 自配送 | 否 | 线下或内部系统安排骑手后，回 WMS 更新物流状态 | 保存自营配送信息和发货状态 |
| 其他物流 | 否 | 到对应物流平台手动下单，回 WMS 填写物流单号并上传物流信息 | 保存物流公司、物流单号、附件和发货状态 |

### 7.1 Lalamove 模式

- 选择 Lalamove 后，弹窗内不展示或不强制填写物流单号、物流图片。
- 点击「确定」后，由系统通过 Lalamove API 创建物流订单。
- API 创建成功后，WMS 保存物流订单标识并完成发货状态更新。
- API 创建失败时，不完成发货，提示失败原因并允许重试。
- Lalamove API 下单字段、费用、失败重试、取消、轨迹回调等需求另行输出。

### 7.2 非 Lalamove / 自营骑手模式

- 发货人员需先在对应物流平台或线下流程完成下单 / 派单。
- 回到 WMS 选择物流公司。
- 填写物流单号；若业务要求，可上传物流信息截图或交接凭证。
- 点击「确定」后，WMS 直接保存物流信息并更新发货物流状态。
- 自营骑手与其他未对接 API 的物流公司使用相同处理方式。

## 8. 发货资格校验与提交

| 场景 | 系统表现 |
| ---- | ---- |
| 所选订单均为待发货、未拦截，物流信息满足要求 | 提交成功，生成发货批次并完成发货 |
| 所选订单存在非待发货订单 | 禁止提交，提示「所选订单中存在未进入待发货的订单，请移除后再发货」 |
| 所选订单存在已拦截订单 | 禁止提交，提示「XXX订单已拦截，无法继续发货，请前往拦截订单处理任务」 |
| Lalamove API 下单失败 | 不完成发货，提示接口失败原因并支持重试 |
| 非 API 物流未填写物流单号 | 禁止提交，提示「请填写物流单号」 |
| 物流信息保存失败 | 保留弹窗已填写内容，提示失败原因并支持重试 |

### 8.1 发货成功后的系统动作

发货提交成功后，系统对每张订单执行：

1. 生成出库单或出库记录。
2. 解冻前序已冻结库存。
3. 记录出库流水、发货时间、发货人员。
4. 记录物流公司、物流单号或物流订单标识。
5. 更新订单状态为「已发货」。
6. 若存在物流状态字段，同步初始化或更新为对应物流状态。

## 9. 任务状态流转

### 9.1 订单作业状态

| 状态 | 触发条件 | 说明 |
| ---- | ---- | ---- |
| 待接单 | WMS 下发揽货任务，尚未被揽货员接单 | 可出现在推荐结果中，不可直接发货 |
| 待揽货 | 揽货员已接单但未完成揽货 | 可出现在推荐结果中，不可直接发货 |
| 待打包复核 | 揽货完成，等待打包复核 | 可出现在推荐结果中，不可直接发货 |
| 待发货 | 打包完成，包裹已放置发货台 | 可被勾选并确认发货 |
| 已发货 | 发货确认成功 | 订单已生成出库单并完成库存解冻 |
| 已完成 | 物流送达或订单履约闭环 | 已发货后的完成态，物流跟踪另行维护 |

状态流转：`待接单` → `待揽货` → `待打包复核` → `待发货` → （确认发货） → `已发货` → `已完成`

### 9.2 物流状态

| 状态 | 说明 |
| ---- | ---- |
| 待接单 | 物流订单已创建，等待物流方或骑手接单 |
| 已接单 | 物流方或骑手已接单 |
| 已取货 | 物流方或骑手已从发货台取货 |
| 配送中 | 订单正在配送 |
| 已送达 | 订单已送达收货点 |

> 已发货后的物流状态跟踪、回调、异常和轨迹详情由独立需求文档维护。本文仅定义发货确认时的初始化和更新边界。

## 10. 关键业务规则

1. **仅支持合单发货**：当前发货模式为多张订单统一发货，不单独设计一单一发的独立流程；单选一张订单也视为一个发货批次。
2. **物流侧一单多点**：多张订单统一发货时，物流公司侧表现为一张物流订单对应多个收货点。
3. **WMS 侧按订单留痕**：即使物流侧合成一张物流订单，WMS 仍需逐订单生成出库单、解冻库存并记录状态。
4. **待发货优先处理**：待发货列表默认按用户下单时间升序排序，优先处理更早下单的订单。
5. **推荐按地址和状态匹配**：推荐发货优先考虑收货地址经纬度距离，同时按待发货、待打包复核、待揽货、待接单的状态优先级展示。
6. **推荐不等于可发货**：推荐结果可包含未进入待发货的订单，但最终确认发货时只能提交满足发货资格的订单。
7. **物流方式差异处理**：Lalamove 通过 API 下单；其他物流和自营骑手由发货人员线下下单或派单后回 WMS 更新物流信息。
8. **拦截订单强校验**：发货提交前实时校验订单拦截状态；任一订单被拦截时，本次发货不可完成。
9. **发货成功不可直接撤销**：发货成功后已生成出库单并解冻库存，如需取消、拦截、物流异常处理，应进入后续异常或物流跟踪流程。
