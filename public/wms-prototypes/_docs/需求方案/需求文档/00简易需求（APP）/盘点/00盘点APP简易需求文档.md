# 仓库 APP - 盘点管理简易需求文档（1.0）

> 文档定位：APP 端盘点管理「简易需求」，用于配合原型给技术人员/AI 进行开发。
> 数据基准：MySQL 库 `wms` 真实表（单一数据源）。盘点单/盘点明细为本期**新增表**，已在文中标注 DDL 草案，正式开发需后端建表。
> 设计基准：参考现有 APP 已上线功能（接单揽货 / 打包复核 / 发货 / 入库）与《2606改仓配端APP UI规范》。盘点采用「任务式作业」范式，对齐 pickup-accept / pickup-work。
> 配套文档：`01盘点APP原型设计说明.md`（待出）。

---

## 1. 基本信息

- 功能名称：盘点管理（APP 端）
- 所属系统：WMS_APP 端 · 仓内作业
- 页面编号：`WMS-APP-PD01`（盘点任务列表）/ `WMS-APP-PD02`（盘点作业页）/ `WMS-APP-PD03`（盘点单详情）
- 盘点粒度：**库房 + SKU 级**（已确认）。即一张盘点单针对一个库房，明细逐 SKU 录实盘数。当前数据库库存维度即「库房+SKU」（`w_wms_warehouse_inventories`），不绑定货位，故本期不做货位级清点。
- 盘点类型：全盘 / 抽盘（动碰盘后置）。抽盘范围按**三级分类**选择（一级/二级/三级），采用左右分栏选择器（详见 6.7）。
- 盘点方式：**明盘**（已确认）。账面数始终显示，仓管员录入实盘后实时显示盘盈/盘亏/一致，不做盲盘隐藏。
- 版本说明：1.0 在 APP 端完成「新建/领取盘点任务 → 逐 SKU 录实盘 → 提交待复核」闭环。**APP 端仓管员只录实盘数，不直接调账**；差异复核与库存调整在 WEB 端由主管完成（权责分离）。**APP 与 WEB 均可新建盘点单**。循环盘点、货位级清点不在本期。

---

## 2. 与 WEB 端 / 数据库的关系

1. 盘点单由 APP 或 WEB 创建，确定库房与盘点范围后，账面数从 `w_wms_warehouse_inventories` **快照**进盘点明细，分配给仓管员。
2. APP 偏「现场快速作业」：扫码定位 SKU、移动端录实盘数、提交；WEB 偏「创建盘点单 / 差异复核 / 调账 / 导出」。**差异复核与调账只在 WEB 端**，APP 不做。
3. 盘点单 / 盘点明细为本期新增表（见 3.1 / 3.2），与现有库存、出入库流水、冻结机制对接。账面数为生成盘点单时的快照，**不随后续库存变动而变**，保证盘点基准稳定。

## 3. 数据模型与字段口径

> 库存现状（核对自数据库 `wms`）：`w_wms_warehouse_inventories` 维度为 `warehouse_id + item_sku_id`，含 `total_quantity`（总=可用+冻结）、`quantity`（可用）、`frozen_quantity`（冻结）、`avg_cost_price`（加权平均成本）、`expiry_date`。**无 position_id，库存不绑定货位。** 当前约 11 库房 / 79 SKU / 31 条库存。

### 3.1 盘点单主表 `w_wms_stocktake_orders`（新增表·DDL 草案）

| 字段 | 库字段 | 说明 |
| --- | --- | --- |
| 盘点单号 | `order_no` | 格式 `PD+YYYYMMDD+4位流水`，系统生成 |
| 库房 | `warehouse_id` | 关联 `w_wms_warehouses`，一张单对应一个库房 |
| 盘点类型 | `type` | 1=全盘 / 2=抽盘 |
| 状态 | `status` | 1=草稿 / 2=盘点中 / 3=待复核 / 4=已完成 / 5=已作废 |
| 盘点范围说明 | `scope_remark` | 抽盘时记录所选三级分类（可多选，存名称列表），可空 |
| 盘点人 | `counter_id` | 分配/领取该盘点任务的仓管员 |
| 创建人 | `creator_id` | 当前登录用户 |
| 账面快照时间 | `snapshot_at` | 生成明细时锁定账面数的时间，Unix 时间戳 |
| 提交时间 | `submitted_at` | 提交待复核时间，可空 |
| 完成时间 | `finished_at` | 复核调账完成时间，可空 |
| 备注 | `remark` | 最长 500 字，可空 |
| 时间戳 | `created_at` / `updated_at` / `deleted_at` | 同其它表，软删除 |

### 3.2 盘点明细 `w_wms_stocktake_items`（新增表·DDL 草案）

| 字段 | 库字段 | 说明 |
| --- | --- | --- |
| 行号 | `line_no` | 按生成顺序 |
| 盘点单 | `stocktake_id` | 关联 `w_wms_stocktake_orders` |
| SKU | `item_sku_id` | 关联 `w_wms_item_skus` |
| 商品 | `item_id` | 冗余存储 |
| 账面数 | `book_quantity` | 生成时从 `w_wms_warehouse_inventories.total_quantity` 快照，APP 只读 |
| 实盘数 | `counted_quantity` | APP 录入，可空（未盘为 NULL） |
| 差异数 | `diff_quantity` | = 实盘 − 账面（盘盈正、盘亏负），系统计算 |
| 盘点状态 | `count_status` | 1=待盘 / 2=已盘 |
| 差异原因 | `diff_reason` | 有差异时选填（破损/过期/错记/被盗/其它） |
| 盘点人 | `counter_id` | 实际录入人 |
| 备注 | `remark` | 行备注，可空 |
| 时间戳 | `counted_at` / `created_at` / `updated_at` | 录入与生成时间 |

### 3.3 明细展示用的商品档案字段（来自档案表，APP 只读展示）

| 展示字段 | 来源 |
| --- | --- |
| 商品名称 | `w_wms_items.item_name` / `w_wms_item_skus.sku_name` |
| 条码 | `w_wms_item_skus.barcode`（扫码定位用） |
| 规格 / 单位 | SKU 规格 / `w_wms_items.unit` |
| 品牌 / 分类 | `w_wms_items.brand_id` → 品牌名 / `category_id` → 分类名 |
| 成本价 | `w_wms_warehouse_inventories.avg_cost_price`（用于差异金额估算，可选展示） |

### 3.4 库存锁定（可选·建议）

盘点期间建议对在盘 SKU 做软锁定，避免盘点过程中库存变动导致差异失真。可复用既有冻结/锁定机制（`w_wms_inventory_freeze_records` 思路、货位「盘点中锁定」概念）。本期原型层面以「盘点中该库房新作业给出提示」演示即可，是否落库为硬锁定由后端定。

## 4. 盘点单状态（状态机）

| 状态 | status | 含义 | 可执行操作 |
| --- | --- | --- | --- |
| 草稿 | 1 | 已创建、账面已快照、未开始盘 | 编辑范围、删除、开始盘点 |
| 盘点中 | 2 | 已领取，正在录实盘数 | 录实盘、暂存、提交待复核 |
| 待复核 | 3 | 已提交，等 WEB 主管复核差异 | APP 只读查看；WEB 复核/驳回 |
| 已完成 | 4 | 复核通过、差异已调账 | 只读查看 |
| 已作废 | 5 | 作废终态 | 只读 |

> 状态流转：草稿(1) → 盘点中(2) → 待复核(3) → 已完成(4)；草稿/盘点中可 → 已作废(5)。
> APP 端推进到「待复核」为止；「已完成」由 WEB 复核调账后回写。被驳回时 WEB 将单退回「盘点中(2)」，APP 可重盘差异行。

## 5. 字段显隐规则（APP 简洁原则）★

延续入库 APP「一屏可扫、信息不冗余、有值才显示」原则。

### 5.1 核心字段（始终显示）

- 任务卡片：盘点单号、状态、盘点类型、库房、进度（已盘 N / 共 M）、有差异条数。
- 商品行：商品名称、账面数（始终显示）、实盘数、盘盈/盘亏/一致标识。
- 详情：盘点单号、状态、库房、盘点类型、盘点人。

### 5.2 条件显示字段（有值才显示）

| 字段 | 显示条件 |
| --- | --- |
| 盘点范围说明 | 抽盘且填写了范围才显示 |
| 差异数 / 差异标签 | 该行实盘 ≠ 账面才显示（盘盈绿、盘亏红） |
| 差异原因 | 有差异且填写了原因才显示 |
| 条码 / 规格 / 品牌 / 分类 | 该 SKU 档案有值才显示 |
| 备注 | 单/行备注非空才显示 |
| 差异金额 | 有差异且有成本价时弱化展示（估算口径） |

### 5.3 规则要点

1. 无值字段不渲染该行，不出现「—」占位。
2. 商品行存在「待盘态（名称+账面数+待录入）」→「已盘一致态（浅绿底+绿色条+一致标）」→「已盘盘盈态（浅绿底+绿色条+盘盈标）」→「已盘盘亏态（浅红底+红色条+盘亏标+原因）」的多态。
3. 详情基本信息行随有值字段动态增减，顺序固定（类型 → 库房 → 盘点人 → 盘点时间 → 范围 → 备注）。

## 6. 关键流程

### 6.1 领取/开始盘点任务
1. 工作台/任务列表看到分配给自己的盘点单（草稿/盘点中）。
2. 点「开始盘点」：草稿(1) → 盘点中(2)，进入盘点作业页。

### 6.2 盘点作业（逐 SKU 录实盘）★
1. 作业页按明细列出待盘 SKU，顶部显示进度（已盘 N / 共 M）。
2. **扫码定位**：扫 SKU 条码命中明细行并聚焦该行（复用入库页 barcode 命中 SKU 逻辑）；扫不中时 toast「条码未匹配到本单商品」。
3. 录入实盘数（步进/键盘），该行 `count_status` 置「已盘」；可随时暂存（写库但不改单状态）。
4. **明盘**：账面数始终显示，录入实盘后该行实时显示盘盈/盘亏/一致（见 6.5）。
5. 全部已盘后「提交盘点」。

### 6.3 提交盘点（生成差异，转待复核）
- 校验：**必须全部行已盘**才可提交；有未盘行则拦截并跳到第一条待盘行。
- 计算每行 `diff_quantity = counted − book`；有差异行要求填差异原因。
- 状态 盘点中(2) → 待复核(3)，`submitted_at` 记录。**此步不改库存。**

### 6.4 复核与调账（WEB 端，APP 只读）
- WEB 主管复核差异：通过则按差异调整 `w_wms_warehouse_inventories`（盘盈增、盘亏减），并按差异生成一条出入库流水（盘盈入/盘亏出），状态 → 已完成(4)；驳回则退回盘点中(2)，APP 可重盘。
- 调账与流水口径以既有出入库流水体系为准，金额按 `avg_cost_price`。

### 6.5 明盘与差异标识
- 明盘：账面数始终显示在每行。
- 录入实盘后实时比对账面：相等显示灰色「一致」标 + 浅绿底 + 绿色左条；实盘 > 账面显示绿色「盘盈 +N」标 + 浅绿底 + 绿色左条；实盘 < 账面显示红色「盘亏 -N」标 + 浅红底 + 红色左条。
- 详情页（PD03）同款配色，与作业页一致。

### 6.6 作废
- 草稿/盘点中单在详情页「作废」，二次确认后 status=5，只读终态。

### 6.7 抽盘范围分类选择（三级分类）
- 抽盘类型下出现「抽盘范围」入口行，收起显示「已选 N 项」摘要。
- 点开底部抽屉，**左右分栏**：左侧竖排一级分类（带已选数量角标）；右侧按二级分组、三级带勾选框，二级标题提供「全选/取消全选」并显示半选提示。
- 顶部搜索框跨三级按名称过滤，结果显示「一级 / 二级」路径。
- 底部「已选 N 项 / 重置 / 确定」，确定后写回；未选分类时默认快照全部。

## 7. 页面与功能点

### 7.0 入口（工作台 + APP 菜单目录）
盘点统一收敛在「盘点」模块下，工作台与 APP 菜单目录两处同步：
- 盘点任务（列表）：进入 `WMS-APP-PD01`。
- 新建盘点单：进入新建流程（APP 支持新建，选库房/类型/抽盘范围 → 账面快照）。
- 接线同入库：`wms-app-page.js` 的 `navigate()` 与 `wms-app-shell.js` 的 `frameUrl()` 增加 `stocktake_task → stocktake-list.html` 等映射。

### 7.1 盘点任务列表页（WMS-APP-PD01）
- 顶部导航：返回 + 标题「盘点任务」+ 右侧「＋ 新建」（APP 支持新建）。
- 搜索：按盘点单号。
- 状态页签：全部 / 待盘点（草稿+盘点中）/ 待复核 / 已完成 / 已作废。**待盘点、待复核页签名后带数量**，如「待盘点（2）」「待复核（1）」。
- 轻量统计条（单行小字，随 tab 切换）：**全部** tab 显示「待盘点 N 单 · 有差异 N 单」；**待盘点 / 待复核 / 已完成 / 已作废** tab 显示「有差异 N 单」。
- 任务卡片：单号、状态标签、盘点类型、库房、进度条（已盘 N/共 M）、有差异条数；按显隐规则。
- 分页：上拉加载更多。

### 7.2 盘点作业页（WMS-APP-PD02）
- 顶部：单号 + 状态 + 进度（已盘 N/共 M）。
- 工具条：扫码定位、搜索 SKU、筛选（全部/待盘/已盘/有差异）。
- 商品明细列表：每行名称+副信息（条码/规格按显隐）、账面数（始终显示）、实盘数输入、已盘标记与盘盈/盘亏/一致配色；有差异行可填差异原因。
- 底部操作栏：进度汇总 + 暂存 + 提交盘点。

### 7.3 盘点单详情页（WMS-APP-PD03）
- 顶部 banner：单号 + 复制 + 状态标签。
- 基本信息卡片（动态行：类型/库房/盘点人/时间/范围/备注）。
- 盘点明细卡片：商品行多态，已盘后亮账面/实盘/差异，盘盈盘亏配色。
- 汇总：盘点 SKU 数、有差异数、盘盈合计、盘亏合计、（可选）差异金额。
- 时间线：创建（账面快照）→ 开始盘点 → 提交待复核 →（WEB）复核完成/驳回。
- 底部操作按状态：草稿/盘点中（继续盘点 / 作废）；待复核（只读）；已完成/已作废（只读）。

## 8. 校验规则

| 校验项 | 时机 | 规则 | 提示 |
| --- | --- | --- | --- |
| 库房 | 新建/提交 | 不为空 | 请选择盘点库房 |
| 盘点类型 | 新建 | 不为空 | 请选择盘点类型 |
| 实盘数 | 实时+提交 | 非负整数，≥0 | 实盘数必须为非负整数 |
| 盘点完整性 | 提交 | 必须所有行已盘 | 还有 N 个商品未盘点 |
| 差异原因 | 提交 | 有差异的行需填原因 | 第 X 行有差异，请填写差异原因 |

> 暂存仅写已录入的实盘数，不做完整性与差异原因强校验。

## 9. 数据情况演示要求（原型必须覆盖）★

原型用样例数据演示不同状态与差异场景，至少包含：

1. **盘点中·明盘**：进度过半，部分行已录实盘、账面始终显示并实时显示盘盈/盘亏/一致；演示扫码定位与录入。
2. **有盘盈盘亏**：提交后/详情页，多行有差异（盘盈绿、盘亏红）+ 差异原因。
3. **全部一致**：无差异单，提交顺畅。
4. **待复核单**：APP 只读，等 WEB 复核。
5. **已完成单**：只读，展示调账后结果与差异汇总、时间线完整。
6. **已作废单**：只读置灰。

每个场景在任务卡片、详情基本信息、商品行三处体现显隐与配色差异。

## 10. 已确认决策 / 需求开放项

已确认：
- 盘点粒度：**库房 + SKU 级**（不做货位级清点）。
- 职责划分：APP 只录实盘数 + 提交待复核；**差异复核与调账在 WEB 端**。
- 账面数为生成盘点单时的快照，不随后续库存变动。

- 盘点单**新建**：APP 与 WEB 均可新建。
- 未盘行提交策略：**必须全部盘完才能提交**。
- 抽盘范围：按**三级分类**（左右分栏选择器，可多选、可搜索）。

待开放：
- 盘点期间库存是否硬锁定（落库冻结）还是仅提示。
- 抽盘范围是否扩展「按品牌 / 按指定 SKU 清单」维度（本期仅按三级分类）。
