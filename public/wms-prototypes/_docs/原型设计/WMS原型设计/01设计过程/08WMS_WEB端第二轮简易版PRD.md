# WMS_WEB端第二轮简易版PRD

## 1. 文档说明

本文为 `WMS原型设计` 第二轮简易版 PRD，承接第一轮 `开放平台 + 主数据 + 入库/库存/出库主链路`，继续补齐 WMS_WEB 端从出库结果之后延伸出的履约中心与物流协同模块。

本轮重点覆盖：

- 履约中心
- 物流协同

本轮文档特别说明：

- 履约中心属于 WMS_WEB 端主链路的正式范围，需要与第一轮出库中心形成闭环。
- 物流协同在需求文档侧拆分为 `WMS_WEB_物流系统`，但在原型阶段继续并入 `WMS_WEB端` 的 `物流协同` 模块呈现。
- 按当前已确认口径，`WMS_WEB_物流系统` 在 WMS1.0 版本不作为优先开发项，因此本轮对物流协同以需求边界、页面占位和接口依赖梳理为主，优先级整体低于履约中心。

本轮不展开以下范围：

- 开放平台
- 主数据
- 入库中心
- 库存中心
- 出库中心
- 售后中心
- 调拨中心
- 仓内作业中心
- 异常中心
- 结算中心

状态口径说明：本文中的业务对象状态、执行结果状态、异常状态统一引用 [15WMS_WEB端状态口径总表.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/原型设计/WMS原型设计/15WMS_WEB端状态口径总表.md)；若本文件局部示例与状态口径总表存在差异，以状态口径总表为准。

## 2. 功能目标

本轮简易版 PRD 的目标是补齐 WMS_WEB 端从“出库处理完成”到“发货履约完成”的业务承接能力，建立以 `shipment_order_id` 为主对象的履约管理视角，并明确物流协同模块的管理边界。

具体目标如下：

1. 建立发货履约单管理视角，统一承接发货履约单的创建结果、履约模式、商品行映射和收货信息展示。
2. 建立履约执行跟踪能力，统一查看拣货结果、出库结果、包裹结果、配拦截、异常通知和单据流水。
3. 建立物流协同管理视角，承接运单、包裹、轨迹、状态回传、面单和物流账单等后台管理需求。
4. 明确履约中心与物流协同、库存中心、出库中心、回调中心之间的依赖和数据边界。
5. 为下一轮履约和物流原型细化提供统一的页面、状态、查询条件和异常处理基线。

## 7. 核心流程

### 7.1 发货履约主链路

1. 第三方电商系统按订单主单和商品行完成履约分组，创建发货履约单。
2. WMS 以 `shipment_order_id` 为主对象受理履约单，并在发货履约单列表中展示。
3. 管理人员在发货履约单详情页查看父订单、店铺、履约模式、商品行映射和收货信息。
4. 履约执行过程中，拣货结果和出库结果回流到履约中心。
5. 如涉及包裹生成、配拦截、异常通知或单据流水，也统一挂载到履约单视角下查看。

### 7.2 物流协同主链路

1. 履约单进入物流承接阶段后，按 `fulfillment_mode` 路由到即时配送或快递配送。
2. 物流协同模块基于 `shipment_order_id` 生成运单，并记录承运方、状态和处理结果。
3. 包裹生成后，运单与包裹、包裹与商品行的映射关系可在后台查询。
4. 配送过程中的轨迹节点持续回流并标准化展示。
5. 状态回传失败时，后台需提供回传日志、失败原因和重试入口。
6. 快递场景可查看面单和物流账单，即时配送场景可展示不适用标识。

### 7.3 履约异常承接流程

1. 当履约单出现配拦截、物流异常、异常通知或单据流水异常时，先在履约中心和物流协同模块可见。
2. 本轮页面只要求可查看和辅助排查，不要求在 Web 端完成完整异常闭环处理。
3. 后续异常中心轮次再承接分派、关闭和责任结果确认。

本章节不再定义独立的 Web 端状态体系，统一引用 [15WMS_WEB端状态口径总表.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/原型设计/WMS原型设计/15WMS_WEB端状态口径总表.md)；以下内容仅用于说明本轮涉及对象的状态使用范围、页面展示位置和理解方式。

| 状态 | 说明 |
| ---- | ---- |

| 对象 | 状态 | 说明 |

### 8.4 包裹与面单状态

| 对象 | 状态 | 说明 |

## 13. 异常处理

| 场景 | 处理要求 |
| ---- | ---- |
| 发货履约单取消失败 | 展示失败原因，不改变原状态 |
| 商品行映射异常 | 在详情页显式提示受影响商品行 |
| 拣货结果缺失 | 履约执行跟踪页提示结果未回流 |
| 运单创建失败 | 运单列表和详情页展示失败原因，并支持重试 |
| 运单取消失败 | 展示失败原因和当前承运状态 |
| 轨迹回传失败 | 在轨迹与回传页展示失败节点和重试入口 |
| 面单不可用 | 即时配送场景展示不适用标识，快递失败场景展示失败原因 |
| 包裹映射异常 | 在包裹列表中提示缺少商品行映射或履约单关联异常 |

## 16. 待确认项

| 编号 | 待确认项 | 说明 |
| ---- | ---- | ---- |
| 1 | 发货履约单状态集是否需要继续细化 | 当前采用简化状态，后续原型阶段可能需要补更多执行中间态 |
| 2 | 履约执行跟踪页是否拆为独立页签型详情结构 | 当前按独立页面处理，也可并入履约单详情页签 |

| 4 | 包裹列表是否在第二轮必须进入原型 | 当前优先级为 P2，可视包裹映射复杂度决定是否后移 |

| 6 | 配拦截记录是仅查看还是允许人工处理 | 当前建议只查看，正式处理动作后续结合异常中心确定 |
