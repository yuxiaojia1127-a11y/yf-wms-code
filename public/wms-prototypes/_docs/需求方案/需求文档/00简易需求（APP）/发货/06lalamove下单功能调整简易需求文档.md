# 仓库APP-Lalamove下单功能调整 简易需求文档

> 版本：v1.0（2026-06-20 初稿，待审核）
>
> 关联文档：[04发货管理-数据设计与API对接需求文档.md](./04发货管理-数据设计与API对接需求文档.md)、[05发货管理原型设计说明.md](./05发货管理原型设计说明.md)
>
> 适用页面：发货管理 > 待发货订单 > 选择 Lalamove > **车型选择/报价下单页（P3）**。本调整仅作用于 Lalamove（在线 API）下单流程，不影响线下物流发货分支。
>
> 数据前提：本文档表名/字段均经当前 MySQL 库核对（2026-06-20）。结论是**三项调整在现有表中均无对应字段，需新增字段/记录**；订单源数据由上游商城同步进入 WMS，新增字段需在订单同步链路一并补充。

## 1. 基础信息

| 项目 | 内容 |
| ---- | ---- |
| 功能名称 | Lalamove 下单功能调整 |
| 所属模块 | 仓库APP > 发货管理 > Lalamove 报价下单页（P3） |
| 页面编码 | `WMS-APP-004-P3`（车型选择/报价下单） |
| 适用角色 | 仓库发货人员 |
| 调整类型 | 功能新增（3 项） |

### 1.1 本次调整点

1. **订单来源标签**：在路线规划的每个收货点（订单）上展示订单来源标签【微信小程序 / H5 / APP】。
2. **位置图查看**：在每个地址后增加查看【位置图】入口（用户下单时上传的地址相关图片），**非必填**，有图才展示。
3. **修改地址（仅对 Lalamove 下单有效）**：核实地址不正确时可修改，调起谷歌地图搜索选择地址；修改**不改原订单地址、不改用户原始地址**，仅**新增一条地址记录**，本次发货按修改后的新地址下单并留痕。修改后产生的这条新地址，**统一定义为新名词「实际发货地址」（Actual Shipping Address）**。
4. **补充覆盖两个页面**：**支付下单页**（确认下单/PlaceOrder）与**发货详情页**（Lalamove 配送状态查询）。两页收货地址展示与下单页一致（有实际发货地址则展示实际发货地址）；每个收货点的备注行统一为「**备注**」。

> **名词定义 · 实际发货地址（Actual Shipping Address）**：发货人员在 Lalamove 下单前，核实并修改后用于本次实际发货的收货地址。它是**订单原收货地址之外新增的一条独立记录**，仅对本次 Lalamove 下单生效，用于 Lalamove 报价/下单的 stop 坐标与发货留痕；不覆盖订单原地址，也不回传修改用户原始地址。未修改地址的订单，其「实际发货地址」即等于订单原收货地址。

## 2. 数据库现状分析

### 2.1 现状结论

| 调整点 | 现有承载 | 缺口 | 处理 |
| ---- | ---- | ---- | ---- |
| 订单来源标签 | WMS 订单/揽货表（`w_wms_picking_orders`）**无来源字段**；`w_pay_orders.action`(web/app/miniapp)、`w_members.from`(pc/app/miniprogram/admin) 为支付/注册来源，非订单渠道 | 缺订单渠道来源字段 | **新增** `order_source`，由上游订单同步写入 |
| 位置图 | `picking_orders` 有收货地址/经纬度，**无地址图片字段** | 缺地址图片 | **新增** `address_images`(JSON)，由上游订单同步写入 |
| 修改地址 → 实际发货地址（留痕） | `w_wms_delivery_orders`/`_items` 记录配送单，**无实际发货地址/留痕结构** | 缺实际发货地址留痕 | **新增** 实际发货地址记录（建议独立表或子表字段，见 §5） |

> 重要：三项均为新增。订单来源与位置图属于**用户下单时产生**的数据，需在「上游商城 → WMS 订单同步」链路补充字段；地址修改属于**WMS 发货时产生**的数据，落在 WMS 配送侧。

### 2.2 现有相关表（参考）

- `w_wms_picking_orders`（订单维度揽货指令）：现有 `receiver_name/receiver_mobile/receiver_address/receiver_postal_code/delivery_point/floor_nit_number/address_lng/address_lat` 等收货字段，是订单来源标签、位置图、原始地址的归属表。
- `w_wms_delivery_orders`（三方配送主表）/ `w_wms_delivery_order_items`（子表，每收货点一条 stop，含 `picking_order_id/order_no/stop_index/provider_stop_id`）：Lalamove 下单数据归属表，是「修改后地址」用于下单与留痕的归属位置。

## 3. 功能需求

### 3.1 订单来源标签

- 在 P3 路线规划每个收货点（订单）卡片**底部操作行、「修改地址」按钮前**展示来源标签：**微信小程序 / H5 / APP**（与「修改地址」同一行，不额外占行；不放在联系人标题行）。
- 数据来源：新增 `w_wms_picking_orders.order_source`（由上游订单同步写入）。
- 枚举建议：`1=微信小程序 2=H5 3=APP`（最终值域以上游商城口径对齐）。
- 标签为展示项，不影响下单逻辑；缺省（无来源）时不展示（不占位）。

### 3.2 位置图查看

- 在 P3 每个地址下方**直接以缩略图行预览**用户下单时上传的地址图片（不再是文字入口按钮）。
- **非必填**：仅当该订单存在地址图片时展示缩略图行；无图不展示。
- 数据来源：新增 `w_wms_picking_orders.address_images`（JSON 数组，存图片 URL），由上游订单同步写入。
- 查看交互：点击缩略图放大预览（可多张，支持左右切换）。位置图为只读，不可在此编辑/上传。

### 3.3 修改地址 → 生成「实际发货地址」（仅对 Lalamove 下单有效）

核心规则（用户明确）：修改地址**只对本次 Lalamove 下单有效**，**不修改当前订单的地址数据，也不修改用户原始地址**，**只新增一条地址记录**（即「实际发货地址」），本订单发货时使用该实际发货地址并留痕。

- 入口：P3 每个收货点提供「修改地址」入口（地址不正确时使用）。
- 调起**谷歌地图地址搜索页**（参考截图「地址搜索」：搜索框 + 地图 + 候选地址列表 + 定位）。
- 选定地址后，将其记为本订单的**实际发货地址**：地址文本、经纬度（用于 Lalamove stop 坐标）。
- 提交后：
  - **不更新** `w_wms_picking_orders` 的原收货地址字段。
  - **不回传**上游商城修改用户原始地址。
  - **新增一条实际发货地址记录**（见 §5），标记其归属订单、订单原地址、实际发货地址、操作人、时间。
  - 本次 Lalamove 报价/下单（`w_wms_delivery_order_items` 对应 stop）使用**实际发货地址的坐标**。
- 留痕展示：改址后在该收货点卡片内**直接分两行上下对比展示**「订单原地址」（弱色）与「实际发货地址」（高亮加粗），无需点击弹窗即可对照；下单按实际发货地址。
- 缺省口径：未修改地址的订单，其实际发货地址即等于订单原收货地址，卡片仅显示一行地址，无需单独记录。

## 4. 页面与交互调整

> 本次涉及三个页面：**P3 车型选择/报价下单页**（4.1，三项调整）、**支付下单页**（4.5，新增覆盖）、**发货详情页**（4.6，新增覆盖）。三页的收货地址展示口径一致：**有实际发货地址则展示实际发货地址，否则展示订单原地址**；每个收货点的备注行统一为「**备注**」（来源 `w_wms_picking_orders.remark`，原型早期占位文案「门牌号收货点」作废）。

### 4.1 P3 车型选择/报价下单页（三项调整）

在 05 文档 P3 基础上，路线规划卡片每个收货点（stop）扩展为：

```text
① Liuzhaobin | 5392000                              ✕ ⠿
   订单原地址  room15, crush cosss, malaysia street …
   实际发货地址 LiveIn @ The Hamilton …      ← 改址后才出现，与原地址上下对比，无弹窗
   [🖼缩略图] [🖼缩略图]                      ← 位置图：有图直接显示缩略图，点击放大
   [微信小程序]  ✎ 修改地址                   ← 来源标签 + 修改地址 同一行（不额外占行）
```

> 已移除原稿中的「门牌号收货点」输入框。

| 元素 | 说明 | 数据 |
| ---- | ---- | ---- |
| 订单来源标签 | 底部操作行、「修改地址」前的小标签，微信小程序/H5/APP；无来源不展示 | `picking_orders.order_source` |
| 位置图缩略图 | 地址下方直接显示缩略图行，点击放大预览；无图隐藏 | `picking_orders.address_images` |
| 修改地址入口 | 操作行文字按钮，点击进入谷歌地图地址搜索 | 写入实际发货地址记录 |
| 实际发货地址 | 改址后在卡片内「订单原地址 / 实际发货地址」上下两行直接对比展示（无标签徽标、无弹窗） | 实际发货地址记录 |

地址搜索页（谷歌地图）：

```text
[app-nav]  < 地址搜索
[search]   🔍 请输入小区/公寓/排屋/写字楼/酒店等     [搜索]
[map]      Google 地图（当前定位蓝点 + POI）           [定位]
[list]     候选地址列表（名称 + 详细地址，点选回填）
```

- 复用 UI 规范组件：`app-nav` + `search-row` + 地图容器 + 候选列表行；主色「搜索」按钮、主色「定位」按钮。
- 选中候选项即回填并返回 P3，对应 stop 在「订单原地址」下方追加「实际发货地址」并刷新报价（坐标变更需重新 Quotation）。

> 标签/按钮中英文：订单来源 = Order Source（WeChat Mini Program / H5 / App）；位置图 = Location Photo；修改地址 = Edit Address；地址搜索 = Address Search；实际发货地址 = Actual Shipping Address。

### 4.5 支付下单页（确认下单 / Place Order）

P3 选好车型与服务后，进入支付下单页做最终确认，「确认订单」触发 Lalamove PlaceOrder 下单。展示字段均来自 `w_wms_delivery_orders` / `w_wms_delivery_order_items` / 配送商配置，无需新增字段：

| 区域 | 内容 | 数据来源 |
| ---- | ---- | ---- |
| 其它信息 | 订单联系号码、wallet 余额 | `delivery_orders.sender_phone`、`delivery_providers.wallet_balance` |
| 订单信息 | 取货点（库房）+ 各收货点：联系人\|电话、收货地址、**备注** | `picking_orders.sender_*` + 各 stop `receiver_*` / `remark`；地址同下单页（有实际发货地址展示实际发货地址） |
| 取货时间 | 立即取货 / Now | - |
| 车型选择 | 车型 | `delivery_orders.vehicle_type` |
| 支付方式 | Wallet + 运费金额 | `delivery_orders.payment_method`、`quote_amount`+`currency` |
| 主按钮 | 确认订单 | 调 PlaceOrder，成功后按 §5/04 文档生成配送单、出库单、订单转已发货 |

### 4.6 发货详情页（Lalamove 配送详情 / 状态查询）

已发货后从「已发货」列表进入，查看 Lalamove 配送状态；下单后/待接单阶段可加骑手小费、确认修改或取消配送。

| 区域 | 内容 | 数据来源 |
| ---- | ---- | ---- |
| 状态时间轴 | 待接单 → 已接单 → 已取货 → 配送中 → 已送达 + 派单时间 | `delivery_orders.delivery_status`(1/2/3/7) + `delivery_order_tracks` 节点（SUBMITTED/ASSIGNED/PICKED_UP/STOP_DELIVERED/ALL_DELIVERED） |
| 加骑手小费 | +RM1.00 / +RM1.50 / +RM2.00 / 自定义金额（调配更多骑手） | `delivery_orders.priority_fee` |
| 车型选择 | 车型 | `delivery_orders.vehicle_type` |
| 配送路线 | 取货点 + 各收货点：联系人\|电话、收货地址、**备注** | 同上；地址同下单页（有实际发货地址展示实际发货地址） |
| 预估运费 | 运费 + 钱包余额 | `quote_amount`+`currency`、`wallet_balance` |
| 底部操作 | 配送取消 / 确认修改 | 取消→调 Lalamove 取消并写 `delivery_status=5`；确认修改→提交小费/改动并重新报价下单 |

> 本期范围：发货详情先支持**查询配送状态**（与 04 文档一致）；完整物流轨迹明细页、取消/改派/异常处理另行输出。

## 5. 数据设计建议

> 支付下单页（4.5）与发货详情页（4.6）**无需新增字段**，全部复用 `w_wms_delivery_orders` 现有字段（`sender_phone` 联系号码、`payment_method` 支付方式、`quote_amount`/`currency` 运费、`priority_fee` 骑手小费、`vehicle_type` 车型、`delivery_mode` 服务模式）+ `w_wms_delivery_order_tracks`（状态时间轴）+ 配送商 `wallet_balance`（钱包余额）。备注取 `w_wms_picking_orders.remark`。新增字段仅订单来源、位置图、实际发货地址三项（见下）。

### 5.1 订单来源与位置图（订单维度，上游同步）

`w_wms_picking_orders` 新增：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `order_source` | tinyint / varchar | 订单来源：1微信小程序 2H5 3APP（值域对齐上游） |
| `address_images` | text(JSON 数组) | 用户下单上传的位置图 URL，非必填 |

> 两字段需在「上游商城订单 → WMS 订单同步」时一并落入；存量订单可为空。

### 5.2 实际发货地址留痕（配送维度，发货时产生）

**推荐方案 A（独立留痕表，最贴合「只新增一条记录」语义）**：新增 `w_wms_actual_shipping_addresses`（实际发货地址记录表）

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `id` | int unsigned | 主键 |
| `picking_order_id` | int unsigned | 关联订单（揽货订单） |
| `order_no` | varchar(64) | 订单号 |
| `delivery_order_id` | int unsigned | 关联本次配送单（下单后回填，可空） |
| `origin_address` / `origin_lng` / `origin_lat` | - | 订单原地址快照（留痕对照） |
| `actual_address` / `actual_lng` / `actual_lat` | - | **实际发货地址**（用于 Lalamove 下单） |
| `actual_delivery_point` / `actual_floor_unit` | - | 实际发货收货点/门牌号（可选） |
| `source` | varchar(20) | 地址来源，如 GOOGLE_MAPS |
| `operator_id` / `created_at` | - | 操作人 / 时间 |

- 下单时：若某订单存在最新一条实际发货地址记录，则 `w_wms_delivery_order_items` 对应 stop 取该实际发货地址坐标；否则取 `picking_orders` 原地址（即实际发货地址=原地址）。
- **不回写** `picking_orders` 原地址、**不回传**上游用户地址。

**备选方案 B**：在 `w_wms_delivery_order_items` 增加 `actual_address/actual_lng/actual_lat/is_address_edited` 字段，把实际发货地址直接挂在本次配送子单上。优点是结构简单；缺点是「只新增一条记录」的留痕语义弱于独立表（一个订单多次改址不易回溯历史）。

> 落库方案（A/B）**交由开发评估决定**，需满足：① 不改订单原地址、② 不改用户原始地址、③ 实际发货地址有独立记录可留痕、④ Lalamove 下单使用实际发货地址。

## 6. 业务规则

1. 三项调整**仅在 Lalamove（在线 API）下单流程生效**；线下物流/自配送不涉及。
2. 订单来源、位置图为**只读展示**，来源于上游订单数据，发货页不可编辑。
3. 实际发货地址为**本次发货级地址**，作用范围仅限本次 Lalamove 报价与下单；不影响订单原数据与用户地址。
4. 实际发货地址坐标变化需**重新报价**（重新调用 Lalamove Quotation），金额随之更新。
5. 实际发货地址留痕需可回看（订单原地址 + 实际发货地址 + 操作人 + 时间）。
6. 合单（多 stop）场景下，每个收货点可独立查看位置图、独立修改地址（各自生成实际发货地址）。

## 7. 校验与提示

| 场景 | 提示 |
| ---- | ---- |
| 无位置图 | 不展示「位置图」入口（不报错） |
| 修改地址未选定就返回 | 保留订单原地址，不生成实际发货地址记录 |
| 实际发货地址未获取到经纬度 | 提示「请选择有效地址」，不可保存 |
| 实际发货地址变更导致重新报价失败 | 提示「报价失败，请重试」，不阻断可重试 |
| 来源字段为空 | 来源标签显示「-」或隐藏 |

## 8. 待确认事项

1. **订单来源值域**：1微信小程序/2H5/3APP 是否与上游商城枚举一致；是否还有其他来源（公众号/支付宝小程序等）——待产品/上游确认。
2. **位置图来源链路**：上游订单是否已采集用户上传的地址图片，WMS 同步是否能拿到——待对接确认。
3. **实际发货地址留痕落库方案**：独立表（方案A）vs 子单字段（方案B）——交开发决定。
4. **谷歌地图**：使用 Google Places/Maps SDK 还是已有地图组件；Key 与配额——待确认。
5. **改址权限**：是否所有发货人员均可改址，是否需审批/记录到操作日志（`w_log_operate`）——待确认。
6. **多次改址**：同一订单允许多次修改时，以最新一条实际发货地址记录为准（方案A 天然支持历史回溯）。
