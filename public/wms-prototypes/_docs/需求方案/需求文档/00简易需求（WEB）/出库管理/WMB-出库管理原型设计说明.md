# WMB-出库管理原型设计说明

## 1. 设计目标

出库管理后台原型面向自营 WMS 业务，围绕出库单、出库明细和出库流水组织页面。

WEB 端用于出库单查询、手动新建出库、过程监控和追溯；仓库 APP 端用于扫码揽货、复核打包和完成发货（完成发货后系统自动生成出库单）。

本文档定义 WEB 端页面结构、导航入口、主视图布局、交互逻辑和模块关系，字段级规则以《WMB-出库管理简易需求》为准。

---

## 2. 角色与使用场景

| 角色 | 使用目标 | 核心关注点 |
| --- | --- | --- |
| 发货员（仓库APP） | 完成发货，触发出库单自动生成 | 实际发货数量与锁定数量是否一致 |
| 仓库管理员 | 手动新建出库单、查询出库结果 | 出库状态、库存扣减是否正常、草稿管理 |
| 订单运营 | 查看销售出库结果与库存扣减情况 | 出库单完成情况、来源单对应关系 |
| 系统管理员 | 追溯和异常排查 | 出库流水、失败原因、幂等处理结果 |

---

## 3. 顶层信息架构

```text
出库管理
├─ 出库单管理
│  ├─ 出库单列表
│  ├─ 出库单详情
│  └─ 新建出库单（WEB 手动）
└─ 出库流水（嵌入详情页 Tab，暂不单独入口）
```

> 1.0 版本出库管理仅含出库单管理一个二级菜单，出库流水作为详情页的子 Tab 展示，不设独立菜单入口。

## 5. 页面框架设计

### 5.1 出库单列表页

**页面定位：** 出库管理核心入口，展示所有出库单并支持查询、筛选、新建和快捷操作。

```text
顶部标题区
├─ 页面标题：出库单管理
├─ 页面编号：WMS-WEB-OUT01
└─ 统计卡片（4 个横排）
   ├─ 今日出库单数（已完成）
   ├─ 今日出库件数（明细合计）
   ├─ 草稿数（未提交 WEB 手动单）
   └─ 本月出库单数（已完成）

筛选区（折叠/展开）
├─ 出库类型（下拉单选）
├─ 出库状态（下拉单选）
├─ 生成方式（下拉单选）
├─ 仓库（下拉单选）
├─ 出库单号（输入框）
├─ 来源单号（输入框）
├─ SKU 编码（输入框）
├─ 创建时间（日期范围选择器）
└─ 操作按钮：[查询]  [重置]

操作栏
└─ [新建出库单]  [导出]（右对齐）

列表区（分页，默认 20 条/页）
├─ 出库单号（蓝色可点击，跳转详情）
├─ 出库类型（Tag 标签）
├─ 生成方式（APP 自动生成 / WEB 手动新建）
├─ 来源单号
├─ 仓库
├─ SKU 种类数
├─ 出库数量
├─ 出库状态（彩色 Tag）
├─ 创建人
├─ 创建时间
└─ 操作列
   ├─ 查看（所有状态）
   ├─ 编辑（仅草稿）
   ├─ 取消（仅草稿）
   └─ 重新提交（仅出库失败）
```

**出库状态 Tag 配色规范：**

| 状态 | 颜色 | 说明 |
| --- | --- | --- |
| 草稿 | 灰色（default） | 未提交，可编辑 |
| 提交中 | 蓝色（processing） | 系统处理中，展示 loading 动效 |
| 已完成 | 绿色（success） | 库存扣减成功，只读 |
| 已取消 | 灰色（default） | 草稿主动取消 |
| 出库失败 | 红色（error） | 库存写入异常，可重试 |

**交互说明：**

- 统计卡片可点击，点击后自动带入对应筛选条件刷新列表（如点击「草稿数」自动筛选出库状态=草稿）。
- 列表支持多列排序，默认按创建时间倒序。
- 「取消」操作需弹出确认对话框：「确认取消该出库单？取消后不可恢复。」
- 「重新提交」操作需弹出确认对话框：「确认重新提交？系统将重新执行库存扣减。」
- 「提交中」状态行所有操作列置灰不可点击。

### 5.2 新建出库单页（WEB 手动）

**页面定位：** 仓库管理员手动创建调拨、报损、其他出库单的操作页。

```text
页面标题：新建出库单
返回链接：← 出库单管理

基本信息区（卡片）
├─ 出库类型（下拉单选，必填）：调拨出库 / 报损出库 / 其他出库
├─ 出库仓库（下拉单选，必填）
├─ 来源单号（输入框，选填，最长 64 字符）
├─ 出库原因（文本域，选填，最长 200 字符）
└─ 备注（文本域，选填，最长 200 字符）

商品明细区（卡片）
├─ 扫码输入框（常驻顶部，自动聚焦）
│  ├─ 左侧：扫码图标
│  ├─ 提示文字：「扫描或输入商品条形码，按回车添加」
│  └─ 扫码结果提示（输入框正下方）
│     ├─ 成功：绿色文字「已添加：{商品名称} {规格}，可用库存 {N}」
│     └─ 失败：红色文字「条码未找到，请检查商品档案」或「条形码格式不正确」
│
└─ 明细表格
   ├─ 序号（自动）
   ├─ 商品条形码（可编辑）
   ├─ SKU 编码（自动填充 / 可手动输入）
   ├─ 商品名称（自动填充）
   ├─ 规格（自动填充）
   ├─ 单位（自动填充）
   ├─ 出库数量（必填，正整数，输入框）
   ├─ 批次号（选填，输入框）
   ├─ 当前可用库存（自动展示，只读，灰色）
   └─ 操作：[删除]（红色文字按钮）

页面底部操作栏（固定底部）
├─ [取消]（返回列表，不保存）
├─ [保存草稿]（仅保存，不扣减库存）
└─ [提交出库]（校验 → 扣减 → 完成，主要操作按钮，蓝色）
```

**扫码交互流程：**

```text
扫码/输入条形码 → 回车
  ├─ 格式校验（6–20 位）
  │  └─ 不符合：输入框下方展示红色提示「条形码格式不正确」，不插入行
  ├─ 条码命中商品档案
  │  └─ 插入新行，自动填充 SKU/名称/规格/单位/可用库存
  │     光标自动定位到该行「出库数量」列
  └─ 条码未命中商品档案
     └─ 插入空行（仅填入条形码）
        展示红色提示「条码未找到，请手动填写 SKU」
        操作人手动填写 SKU 编码、商品名称、出库数量

扫码完成 → 输入框自动清空，等待下一次扫码
```

**提交校验交互：**

- 校验失败时，在对应行高亮错误字段（红色边框），并在行末展示错误图标 + tooltip 说明。
- 顶部展示错误汇总 Banner：「提交失败，请检查以下 N 项错误」。
- 可用库存超出时，在「出库数量」字段下方展示红色提示：「出库数量超过可用库存，剩余可用 {N}」。

### 5.3 出库单详情页

**页面定位：** 查看出库单基本信息、出库明细和出库流水的只读页面，支持从列表页点击「查看」或出库单号跳转。

```text
页面标题：出库单详情
返回链接：← 出库单管理

页面顶部操作区（仅草稿态展示）
├─ [编辑]（草稿态）
└─ [取消出库单]（草稿态，二次确认）

基本信息区（卡片，两列布局）
├─ 出库单号
├─ 出库状态（彩色 Tag）
├─ 出库类型
├─ 生成方式（App自动生成 / WEB手动新建）
├─ 来源单号
├─ 出库仓库
├─ 创建人 / 发货员
├─ 创建时间
├─ 发货 / 提交时间
├─ 出库原因
└─ 备注

失败原因提示区（仅「出库失败」状态展示）
└─ 橙色 Alert 提示框：「出库失败原因：{失败原因}」+ [重新提交] 按钮

Tab 区域（三个 Tab）
├─ Tab 1：出库明细
├─ Tab 2：出库流水
└─（草稿态时 Tab 区域不展示，仅展示基本信息）

Tab 1 — 出库明细
└─ 明细列表
   ├─ 序号
   ├─ 商品条形码
   ├─ SKU 编码
   ├─ 商品名称
   ├─ 规格
   ├─ 单位
   ├─ 出库数量
   ├─ 批次号
   ├─ 解冻锁定数量（APP发货单 / 有预锁单据有值，否则展示「—」）
   ├─ 实扣实物数量
   └─ 库存扣减状态（成功 / 失败，彩色 Tag）

Tab 2 — 出库流水
└─ 流水列表
   ├─ 流水号
   ├─ 流水类型（解冻锁定 / 扣减实物）
   ├─ SKU 编码
   ├─ 商品名称
   ├─ 仓库
   ├─ 批次号
   ├─ 变动数量
   ├─ 操作人
   └─ 操作时间
```

**交互说明：**

- 草稿态详情页顶部展示「草稿」状态提示条（浅黄色 Alert），提示：「当前出库单处于草稿状态，提交后将执行库存扣减。」
- 出库明细「库存扣减状态」为失败时，该行高亮（浅红色背景），并可点击查看失败原因 tooltip。
- 流水类型「解冻锁定」和「扣减实物」用不同颜色区分（蓝色 / 橙色 Tag）。

## 9. 状态与交互全景

### 9.1 出库单状态对应操作权限矩阵

| 状态 | 查看详情 | 编辑 | 取消 | 重新提交 | 提交出库 |
| --- | --- | --- | --- | --- | --- |
| 草稿 | ✅ | ✅ | ✅ | — | ✅ |
| 提交中 | ✅（只读） | — | — | — | — |
| 已完成 | ✅ | — | — | — | — |
| 已取消 | ✅ | — | — | — | — |
| 出库失败 | ✅ | — | — | ✅ | — |

### 9.2 新建出库单页底部操作栏逻辑

```text
点击「取消」
  └─ 若有未保存内容：弹出确认「当前填写内容未保存，确认离开？」
     └─ 确认 → 返回列表，不保存任何内容

点击「保存草稿」
  └─ 基本信息无需完整（出库类型、仓库可为空，草稿允许不完整）
     保存成功 → Toast 提示「已保存为草稿」
     保存失败 → Toast 提示「保存失败，请重试」

点击「提交出库」
  └─ 前端校验（出库类型、仓库必填；明细至少一行；出库数量正整数且≤可用库存）
     校验失败 → 高亮错误行 + 顶部错误 Banner，不请求接口
     校验通过 → 弹出二次确认：「确认提交出库？提交后将立即扣减库存，不可撤销。」
       └─ 确认 → 请求接口 → 按钮 loading 态
            ├─ 成功 → 跳转详情页（已完成）+ Toast「出库成功」
            └─ 失败 → 跳转详情页（出库失败）+ 展示失败原因
```

## 10. 空状态与加载态设计

| 场景 | 展示方式 |
| --- | --- |
| 列表无数据（查询无结果） | 居中展示空状态图 + 文字「未找到符合条件的出库单」 |
| 列表无数据（首次使用） | 居中展示空状态图 + 文字「暂无出库单」+ [新建出库单] 引导按钮 |
| 明细表格无数据（新建页） | 展示「请扫描商品条形码或手动添加商品行」引导文字 |
| 列表加载中 | 表格骨架屏（Skeleton） |
| 提交中 | 出库单状态展示「提交中」+ loading 图标，操作列置灰 |
| 网络异常 | Toast 提示「网络异常，数据已自动保存为草稿」 |

## 11. 原型第一版页面优先级

### 11.1 第一优先级（MVP）

| 页面 | 目标 |
| --- | --- |
| 出库单列表页 | 建立出库主单查询与操作入口，含统计卡片和筛选区 |
| 新建出库单页 | 支持 WEB 手动新建调拨/报损/其他出库，扫码添加商品行 |
| 出库单详情页 | 查看基本信息、出库明细（含解冻/实扣字段）、出库流水 |

### 11.2 第二优先级（后续迭代）

| 页面/功能 | 目标 |
| --- | --- |
| 出库失败详情与重试交互优化 | 失败原因展示、逐行扣减状态追踪 |
| 出库流水独立菜单入口 | 支持跨出库单的流水汇总查询与导出 |
| 导出功能细化 | 支持导出明细行数据，按条件导出 |

## 12. 设计约束与注意事项

1. **销售出库不可手动新建**：新建出库单页的出库类型下拉仅包含「调拨出库 / 报损出库 / 其他出库」，销售出库由 APP 自动生成，不开放 WEB 手动入口。

2. **出库单不可撤销**：已完成的出库单只读，明细与流水不可删除；如需修正，需通过后续版本的反向单据（退库/库存调整）处理，原型中不提供「反向冲销」入口。

3. **APP 自动生成单的状态差异**：APP 生成的出库单不经过「草稿」态，列表中「编辑」和「取消」操作对该类出库单不显示，仅展示「查看」。

4. **库存实时性**：新建页「当前可用库存」字段在 SKU 填充后从库存中心实时查询展示，提交时再次服务端校验，前端仅做参考展示，以服务端校验结果为准。

5. **幂等提示**：若来源单号已有对应已完成出库单，系统在提交时应给出提示「该来源单号已存在出库单 {OUT-XXXXXXXXX}，是否继续？」，由操作人二次确认后方可提交（不直接阻断，由后端幂等逻辑处理）。

6. **字段宽度适配**：出库单号（`OUT-YYYYMMDD-NNNNNN`）、流水号等较长字符串列建议设置最小宽度，必要时截断并 tooltip 展示完整内容。
