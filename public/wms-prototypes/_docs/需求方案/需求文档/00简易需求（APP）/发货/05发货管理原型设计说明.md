## 1. 设计目标与原则

1. **复用既有 APP 组件**：发货列表与接单揽货（`pickup-accept.html`）同骨架——`app-nav` + `search-row` + `tab-row` + `filter-row` + `card task-card` 列表 + `bottom-bar`。只替换字段与动作，不新增 Tab/卡片/弹窗样式。
2. **数据驱动渲染**：物流公司按钮、配送状态文案、报价金额、钱包余额均由后端数据驱动（见 04 文档表字段），原型用样例 JSON 模拟，不写死。
3. **状态轻量表达**：作业状态、配送状态用文字/小圆点/浅色标签，禁止整卡高饱和底色（UI 规范 3.4）。
4. **一屏可扫 + 单一主动作**：每页只保留一个最强主动作（统一发货 / 确认 / 确认订单），主按钮统一主色 `--app-primary`。
5. **中英文兼容**：按钮文案按 02 文档口径（Shipping / To Ship / Ship Together / Carrier / Tracking No. 等），预留英文变长。

## 4. P1 发货管理列表页

### 4.1 骨架（复用 pickup-accept 结构）

```text
[app-nav]      < 发货管理
[search-row]   🔍 请输入订单号/联系人/邮编        [搜索]
[tab-row]      待发货   已发货   已完成
[filter-row]   [全部] [即时配送] [物流发货]
[list]         订单卡片 …
[bottom-bar]   ○ 已选0个                     [统一发货]
```

| 区域 | 组件类 | 规格/说明 |
| ---- | ---- | ---- |
| 顶部导航 | `app-nav` | 高 44px，左返回，居中标题「发货管理 / Shipping」 |
| 搜索区 | `search-row`>`search-box`+`search-btn` | 胶囊输入框 + 主色「搜索」按钮；placeholder「请输入订单号/联系人/邮编」 |
| 状态页签 | `tab-row`>`tab on` | 待发货(默认) / 已发货 / 已完成；当前项主色下划线 |
| 配送筛选 | `filter-row`>`chip on` | 全部 / 即时配送 / 物流发货；当前项深色胶囊 |
| 列表 | `card task-card` | 订单卡片，待发货态可勾选 |
| 底部栏 | `bottom-bar` | 仅「待发货」页签显示；全选 + 已选数量 + 统一发货 |

### 4.2 数据来源（对齐 04 文档）

- 列表数据 = `w_wms_picking_orders`，页签映射 `status`：**待发货=4 / 已发货=5 / 已完成=6**。
- 配送筛选映射 `delivery_type`：全部 / 1即时配送 / 2物流发货。
- 搜索匹配 `order_no` / `receiver_name` / `receiver_postal_code`。
- 待发货默认按下单时间升序。

## 5. P2 确认发货弹窗（底部抽屉）

### 5.1 骨架与物流公司动态渲染

参考截图「确认发货」底部弹层（UI 规范 8.8）：遮罩黑 35-45%，弹层顶部圆角 12-16px。

```text
确认发货                                              ✕
* 物流公司
[Lalamove] [自配送] [Ninjavan] [J&T express] [Grab] [DHL] [Lalamove-test]
────────────────────────────────────────────
（按所选物流公司类型切换下方表单：模式A / 模式B）
[确定]
```

- **物流公司按钮组由 `w_wms_delivery_providers`（`status=1`）动态渲染**，文案取 `name`，不写死按钮。
- 每个按钮携带 `is_offline` 标识决定分支：**`is_offline=2`（在线API，如 Lalamove）→ 模式A**；**`is_offline=1`（线下手动，如 J&T/自配送/其他）→ 模式B**。
- 选中态主色底白字，未选白底灰边（28-32px 小胶囊）。
- 必填星号 `*` + `--app-danger` 色。

### 5.2 模式 A — Lalamove（在线 API）

- 选中 Lalamove 后，弹窗**不展示物流单号、物流信息上传**字段。
- 顶部信息条（浅蓝 `--app-info` 弱底，12px）：「Lalamove不需要填写单号和上传物流图 / Lalamove does not require a tracking number or shipping proof.」
- 点击「确定」→ **进入 P3 车型选择/报价下单页**（截图「车型选择」流程），而非直接发货。
- 说明：Lalamove 需先报价选车型再下单，故拆出独立页 P3；非 Lalamove 在弹窗内即可完成。

### 5.3 模式 B — 线下物流 / 自配送

```text
确定发货
* 物流公司
[Lalamove] [自配送] [J&T express] …
────────────────────────────────────────────
物流单号                              请输入物流订单号
────────────────────────────────────────────
物流信息
[ + 上传 ]
[确定]
```

| 字段 | 来源/落库 | 规格 |
| ---- | ---- | ---- |
| 物流单号 | 落库方式见 04 文档 §9（复用 `provider_order_id` 或新增字段，开发决定） | 单行输入，必填，placeholder「请输入物流订单号」 |
| 物流信息 | `w_wms_delivery_orders.logistics_images`（JSON 数组） | 虚线上传框 ~96×96px，加号 + 「上传」；可传多张 |
| 确定 | - | 主色胶囊，提交校验后发货 |

- 自配送与其他线下物流共用此表单，文案按所选 `name` 显示。
- 提交成功：按 04 文档 §5 生成配送主子单 + 出库单 + 解冻库存 + 状态扭转，回 P1 刷新。

### 5.4 弹窗交互

- 切换物流公司时表单即时切换（A/B 模式）；从 B 切回 A 隐藏单号与上传区，保留本次未提交输入到关闭前。
- 点击遮罩/关闭：关闭并保留列表已选状态；已填未提交不保存。
- 提交中：「确定」loading 禁重复点击。

## 6. P3 Lalamove 车型选择 / 报价下单页

对应截图「车型选择」。承接 P2 选 Lalamove 后的报价下单（04 文档 §4.4）。

### 6.1 页面结构

```text
[app-nav]   < 车型选择
[card]  路线规划（当前为最优路线）              长按拖动调整顺序
        ① test 5kmStore | 11111111
           Jalan Tuanku 4, Taman Salak Selatan, 57100 …
        ② Test-ios-piao | 123456789           （合单时多 stop）
           Falalaa Desserts • Kuchai Lama …
        [推荐 ●]   [+ 继续添加订单]
[card]  取货时间                              立即取货 >
[card]  车型选择
        [摩托车 ✓]  [4X4]  …  （横向滑动）
[footer] 服务类型（Wallet余额: MYR 521.90）
        [Regular 常规配送            MYR 6.9 ✓]
        [确认订单]
```

### 6.2 区块说明（对齐 04 字段）

| 区块 | 数据/落库字段 | 说明 |
| ---- | ---- | ---- |
| 路线规划 | 取货点=`picking_orders.sender_*`；各 stop=各订单 `receiver_*`/`address_lat/lng`，顺序写 `delivery_order_items.stop_index` | 单发1个收货 stop；合单 N 个；「推荐」开启=最优路线 |
| 取货时间 | - | 立即取货（本期固定，预约另议） |
| 车型选择 | `delivery_orders.vehicle_type` | 摩托车/4X4 等，来源 `providers.cities_data` 能力缓存 |
| 服务类型 | `delivery_orders.delivery_mode`（REGULAR/PRIORITY/POOLING） | 默认 Regular 常规配送 |
| 钱包余额 | `providers.wallet_balance` + `wallet_currency` | 展示「Wallet余额: MYR 521.90」 |
| 报价金额 | `delivery_orders.quote_amount` + `currency` | 选车型/服务后实时报价（Quotation 接口） |
| 确认订单 | 写 `provider_order_id`/`provider_quotation_id`/各 `provider_stop_id`/`delivery_status=1`/`share_link` | 调 PlaceOrder；成功写 SUBMITTED 轨迹，回 P1 |

### 6.3 交互

- 进入页先按 §6.2 入参调 **Quotation 接口**取报价，渲染金额；切换车型/服务类型重新报价。
- 「推荐」开关切换最优/手动顺序；长按拖动调整 stop 顺序并刷新报价。
- 「确认订单」→ loading → 调 PlaceOrder：
  - 成功：toast「发货成功」，每张订单生成出库单/解冻库存/状态→已发货，回 P1，已发货卡片配送状态显示「待接单」。
  - 失败：不发货、不扭转状态，toast 失败原因，允许重试（04 文档 §4.4）。
- 余额不足/报价失败：禁用「确认订单」并提示。

## 11. 原型落地规则（强约束）

1. 草稿先入 `public/wms-prototypes/_drafts/`，确认后并入 `APP端HTML原型/`；正式入口仅 `WMS-APP端原型.html`。
2. 严格复用 UI 规范第 9 节 Tokens 与现有 APP 组件，不新造卡片/弹窗/Tab 样式，不散落硬编码颜色。
3. 物流公司按钮、配送状态、车型、报价、钱包余额一律走样例数据驱动渲染（对齐 04 表字段），不写死。
4. 弹窗支持 `lalamove`(模式A) / `manual-logistics`(模式B) 两类视觉态，按所选物流公司 `is_offline` 切换字段。
5. 卡片状态类至少含：`shipping-pending`(待发货可选) / `shipping-selected`(已选) / `shipping-shipped`(已发货只读) / `shipping-blocked`(已拦截)；配送状态文案另由数据渲染。
6. 不写业务长文、不用大面积高饱和底色；规则通过可选/禁用/toast 表达。
7. 与 01 文档冲突时，UI 流程以 01 为准，数据/状态/API 字段以 04 + 本文档为准。
