# 入库管理后台原型设计（自营版大框架）

## 1. 设计目标

入库管理后台原型面向自营WMS业务，围绕入库单、收货任务、质检任务、上架任务、入库差异和入库流水组织页面。

Web端用于入库计划、过程监控、异常处理和追溯；APP端用于扫码收货、质检登记和上架确认。

本阶段定义页面结构、导航入口、主视图和模块关系，不展开字段级和交互细节。

## 2. 角色与使用场景

| 角色 | 使用目标 | 核心关注点 |
| --- | --- | --- |
| 采购人员 | 查看采购到货入库进度 | 到货是否收齐、差异是否处理 |
| 收货员 | 执行到货收货 | 扫码、数量、批次、效期、SN |
| 质检员 | 登记质检结果 | 正品、次品、拒收、待处理 |
| 上架员 | 执行上架落位 | 推荐库位、货位校验、上架数量 |
| 仓库管理员 | 管理入库全过程 | 入库状态、差异、异常、库存入账 |
| 系统管理员 | 处理系统异常 | 流水失败、任务卡滞、数据异常 |

## 8. 原型第一版页面优先级

### 8.1 第一优先级

| 页面 | 目标 |
| --- | --- |
| 入库单管理 | 建立采购、退货、调拨入库主单入口 |
| 收货管理 | 支持待收货、收货中、收货异常管理 |
| 上架管理 | 支持待上架、上架中、上架异常管理 |

### 8.2 第二优先级

| 页面 | 目标 |
| --- | --- |
| 质检管理 | 支持正品、次品、拒收、待处理质检结果 |
| 入库差异 | 支持多收、少收、错品、破损差异处理 |
| 入库流水 | 支持入库过程和库存入账追溯 |

## 9. 大框架结论

入库管理后台原型按“入库主单 + 仓内作业任务 + 差异追踪”设计：

1. 入库单管理承接采购、退货、调拨等入库来源。
2. 收货管理承接到货扫码、数量确认、批次效期和SN采集。
3. 质检管理承接正品、次品、拒收和待处理结果。
4. 上架管理承接推荐库位、货位校验和库存入账。
5. 入库差异承接多收、少收、错品、破损和效期异常处理。
6. 入库流水承接入库过程和库存变化追溯。

第一版原型先完成入库单管理、收货管理和上架管理，再补充质检管理、入库差异和入库流水。
