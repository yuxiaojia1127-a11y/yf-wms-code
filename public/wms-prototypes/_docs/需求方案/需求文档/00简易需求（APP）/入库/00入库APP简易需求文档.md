# 仓库 APP - 入库管理简易需求文档（1.0）

> 文档定位：APP 端入库管理「简易需求」，用于配合原型给技术人员/AI 进行开发。
> 数据基准：MySQL 库 `wms` 真实表（单一数据源），不以历史 WEB 1.0 需求文档为准。
> 设计基准：参考现有 APP 已上线功能（接单揽货 / 打包复核 / 发货 / 现有入库原型）与《2606改仓配端APP UI规范》。
> 配套文档：[01入库APP原型设计说明.md](./01入库APP原型设计说明.md)

---

## 1. 基本信息

- 功能名称：入库管理（APP 端）
- 所属系统：WMS_APP 端 · 仓内作业
- 页面编号：`WMS-APP-IN01`（列表）/ `WMS-APP-IN02`（新建/编辑）/ `WMS-APP-IN03`（详情）
- 适用范围：采购入库、退货入库、调拨入库、其他入库
- 版本说明：1.0 在 APP 端完成「入库单查看 + 新建 + 草稿编辑 + 提交入库 + 作废」闭环，与 WEB 端入库管理保持同一套数据与状态口径。不涉及收货任务、质检任务、上架任务。

---

## 2. 与 WEB 端 / 数据库的关系

1. APP 与 WEB 共用同一套入库单数据（`w_wms_inbound_orders` + `w_wms_inbound_order_items`），状态、单号、库存入账口径完全一致。
2. APP 偏「现场快速作业」：扫码加货、移动端录入、提交入账；WEB 偏「批量与导入导出」。导入 Excel / 导出 Excel / 下载模板等批量能力仍只在 WEB 端，APP 不做。
3. 本文档所有字段以数据库为准。数据库未落地的字段（入库类型）单独标注为「需求新增字段」，原型按 UI 字段展示，正式开发时需后端补字段。**来源单号本期不做**（库表无字段，已确认去掉）。

## 3. 数据模型与字段口径

### 3.1 入库单主表 `w_wms_inbound_orders`

| 字段 | 库字段 | 说明 |
| --- | --- | --- |
| 入库单号 | `order_no` | 格式 `RK+YYYYMMDD+4位流水`，系统生成 |
| 库房 | `warehouse_id` | 关联 `w_wms_warehouses`（库表只有「库房」一级，无「仓库+库房」两级） |
| 入库时间 | `inbound_at` | Unix 时间戳，**允许用户设置历史时间** |
| 状态 | `status` | 1=草稿 / 2=已入库 / 3=已作废 |
| 备注 | `remark` | 最长 500 字，可空 |
| 创建人 | `creator_id` | 当前登录用户 |

### 3.2 入库单明细 `w_wms_inbound_order_items`

| 字段 | 库字段 | 说明 |
| --- | --- | --- |
| 行号 | `line_no` | 按插入顺序 |
| SKU | `item_sku_id` | 关联 `w_wms_item_skus` |
| 商品 | `item_id` | 冗余存储 |
| 数量 | `quantity` | 必须 > 0 |
| 单价 | `unit_price` | ≥ 0，入账后永不修改 |
| 总金额 | `total_amount` | = 数量 × 单价 |
| 有效期 | `expiry_date` | **库表已建字段**，可空（按 SKU/批次效期管理） |

### 3.3 明细展示用的商品档案字段（来自档案表，APP 只读展示）

| 展示字段 | 来源 |
| --- | --- |
| 商品名称 | `w_wms_items.item_name` / `w_wms_item_skus.sku_name` |
| 条码 | `w_wms_item_skus.barcode` |
| 规格 | SKU 规格 |
| 单位 | `w_wms_items.unit` |
| 品牌 | `w_wms_items.brand_id` → 品牌名 |
| 分类 | `w_wms_items.category_id` → 分类名 |

### 3.4 需求新增字段（库表未落地，原型按 UI 字段处理）

| 字段 | 处理方式 |
| --- | --- |
| 入库类型 | 采购/退货/调拨/其他。已确认「数据库为主 + 增加入库类型」，正式开发需主表加字段 |
| 批次号 / 生产日期 | 需求侧字段，库表当前仅有 `expiry_date`，本期以「有效期」为主，批次/生产日期列为后续扩展 |

> 来源单号已确认本期去掉，不在原型与字段中出现。

## 4. 入库单状态（以数据库为准）

| 状态 | status | 含义 | 可执行操作 |
| --- | --- | --- | --- |
| 草稿 | 1 | 已创建未提交 | 编辑、删除、提交入库 |
| 已入库 | 2 | 库存已入账 | 查看、作废 |
| 已作废 | 3 | 已作废 | 仅查看 |

> 说明：历史 WEB 1.0 文档中的「提交中 / 入库失败」状态在数据库中不存在，本期不实现；提交失败按前端 toast 重试处理，不落库为独立状态。

## 5. 字段显隐规则（APP 简洁原则）★

APP 强调「一屏可扫、信息不冗余」。**所有非核心字段遵循"有值才显示、无值不占位"原则**，避免出现一排「—」。

### 5.1 核心字段（始终显示）

- 列表卡片：入库单号、状态、入库时间、商品数量（种类数 + 件数）、合计金额。
- 商品行：商品名称、数量、金额。
- 详情：入库单号、状态、库房、入库时间。

### 5.2 条件显示字段（有值才显示该行/该标签）

| 字段 | 显示条件 |
| --- | --- |
| 入库类型 | 类型不为空时显示（默认采购入库，一般都有） |
| 备注 | 备注非空才显示备注卡片/行 |
| 品牌 / 分类 | 该 SKU 档案有品牌/分类才在商品行副信息中显示 |
| 规格 / 单位 | 有值才显示 |
| 条码 | 有条码才显示条码标签 |
| 有效期 | 该明细行填写了有效期才显示有效期标签 |
| 单价 / 金额 | 单价 > 0 才强调金额；单价为 0（如初始化/盘盈）时金额弱化或不展示价格 |

### 5.3 规则要点

1. 无值字段不渲染该行，不显示占位符「—」「无」。
2. 商品行因此存在「极简态（仅名称+数量）」到「完整态（名称+品牌+分类+规格+单位+条码+单价+有效期）」的连续多态。
3. 详情页基本信息卡片的行数随有值字段动态增减，但顺序固定（类型 → 库房 → 入库时间 → 备注）。
4. 原型必须演示同一组件在不同数据完整度下的呈现（见第 9 节）。

## 6. 关键流程

### 6.1 新建入库单
1. 工作台/列表点「＋ 新建」进入新建页。
2. 选择入库类型、目标库房；入库时间默认当前，可改为历史时间；可填备注。
3. 扫码或「选择商品」加入商品行；逐行填数量、单价、（可选）有效期。
4. 「保存草稿」→ status=1；「提交入库」→ 校验通过后 status=2，库存入账，进入成功页。

### 6.2 编辑草稿
1. 列表/详情中草稿单点「编辑」，复用新建表单并回填数据。
2. 可改全部字段、增删商品行。
3. 再次「保存草稿」或「提交入库」。

### 6.3 提交入库
- 校验：库房必选、至少一行商品、每行数量 > 0。
- 通过后库存按行入账，生成入库明细，状态→已入库。

### 6.4 作废
- 已入库 / 草稿单在详情页点「作废」，二次确认后 status=3。
- 作废为只读终态，不可恢复（原型层面演示确认弹窗+状态变更即可）。

### 6.5 删除草稿
- 仅草稿支持「删除」（软删除 `deleted_at`），二次确认。

### 6.6 扫码加货逻辑
- 扫码命中 SKU：加入商品行。**重复扫描同一 SKU 时，弹确认「该商品已存在，新增一行 / 累加到已有行」**（对齐 WEB 行为，不静默累加）。
- 扫码未命中：toast「条码未匹配到商品」，不加行（本期不做未知条码手填，简化处理）。

## 7. 页面与功能点

### 7.0 入口（工作台 + APP 菜单目录）
入库的两个独立入口统一收敛在「入库」模块下，工作台与 APP 菜单目录两处同步：
- 入库单（列表）：进入 `WMS-APP-IN01`。
- 新建入库单：进入 `WMS-APP-IN02`。
- 「其他」模块不再重复放「新建入库单 / 入库记录」，避免一处功能多个入口（入库记录与入库单为同一列表页）。

### 7.1 入库单列表页（WMS-APP-IN01）
- 顶部导航：返回 + 标题「入库单」+ 右侧「＋ 新建」。
- 搜索：按入库单号。
- 状态页签：全部 / 草稿 / 已入库 / 已作废（对应 status）。
- 筛选入口（右侧筛选图标 → 底部抽屉）：入库类型、库房、入库时间范围。
- 轻量统计条：今日入库单数、草稿数（简洁，单行小字，不做大卡片）。
- 列表卡片：单号、状态标签、入库类型、库房、入库时间、**商品数量行（格式「N（共 M 件）」，N=SKU 种类数、M=总件数，置于入库时间下方）**、合计金额；备注按显隐规则。卡片底部仅保留合计金额（不再重复「种·件」）。
- 分页：上拉加载更多（避免全量渲染）。

### 7.2 新建 / 编辑入库单页（WMS-APP-IN02）
- 基本信息卡片：入库类型（胶囊，文案用短词「采购 / 退货 / 调拨 / 其他」避免换行；列表与详情仍显示完整「采购入库」等）、目标库房（选择抽屉）、入库时间（可选历史，时间选择）、备注。
- 商品明细卡片：扫码添加、选择商品（抽屉搜索）；商品行支持数量步进、单价输入、有效期选填、删除。
- 底部操作栏：种/件/合计金额 + 保存草稿 + 提交入库。
- 编辑态：标题「编辑入库单」，回填数据；其余同新建。

### 7.3 入库单详情页（WMS-APP-IN03）
- 顶部 banner：单号 + 复制 + 状态标签。
- 基本信息卡片（按显隐规则动态行）。
- 入库明细卡片（商品行多态，按显隐规则）。
- 金额汇总（种/件/合计）。
- 入库流水/时间线：创建 → 提交入库（已入库）/ 作废（已作废）。
- 底部操作按状态：草稿（编辑 / 删除 / 提交入库）；已入库（作废）；已作废（无操作）。

## 8. 校验规则

| 校验项 | 时机 | 规则 | 提示 |
| --- | --- | --- | --- |
| 入库类型 | 提交 | 不为空 | 请选择入库类型 |
| 目标库房 | 提交 | 不为空 | 请选择目标库房 |
| 商品明细 | 提交 | 至少一行 | 请至少添加一条入库商品 |
| 入库数量 | 实时+提交 | 正整数，≥1 | 入库数量必须为正整数 |
| 单价 | 实时 | ≥ 0 | 单价不能为负 |
| 有效期 | 选填 | 日期格式合法 | 有效期格式不正确 |
| 入库时间 | 提交 | 不晚于当前时间 | 入库时间不能晚于当前时间 |

保存草稿仅要求至少一行商品，其余字段宽松。

## 9. 数据情况演示要求（原型必须覆盖）★

原型需用样例数据演示「字段有/无」的不同呈现，至少包含以下场景：

1. **完整信息单**：采购入库 + 有备注，多行商品且含品牌/分类/规格/单位/条码/有效期/单价。
2. **极简信息单**：其他入库（如初始化/盘盈）+ 无备注 + 单价为 0 + 商品行仅名称与数量、无品牌/分类/有效期。
3. **部分字段单**：退货入库 + 无备注；部分商品行有有效期、部分没有。
4. **草稿单**：可进入编辑，演示编辑回填与底部「删除 / 提交入库」。
5. **已入库单**：只读，底部仅「作废」。
6. **已作废单**：只读，无操作，状态标签置灰。

每个场景在列表卡片、详情基本信息、商品行三处都应体现显隐差异。

## 11. 验收要点

- 列表可按状态页签、单号搜索、类型/库房/时间筛选查看入库单，支持上拉加载。
- 新建：可选类型/库房、可设历史入库时间、扫码或选货加行、填数量/单价/有效期、提交入账。
- 重复扫码弹「新增一行/累加」确认。
- 草稿可编辑回填、可删除、可提交。
- 已入库可作废，作废为只读终态。
- 字段显隐规则生效：无值字段不渲染、不出现「—」占位。
- 原型覆盖第 9 节全部数据场景。
