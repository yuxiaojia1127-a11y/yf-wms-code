# WMS 系统 - 组合商品履约简易需求文档（1.0）

> 文档定位：WMS 侧「组合商品履约」简易需求，用于配合原型给技术人员/AI 进行开发。
> 数据基准：WMS 库存与履约一律按 SKU + 仓库 + 仓位 + 批次 + 状态管理，**不新增组合库存**。
> 设计前提：组合 BOM 在电商系统下单时已展开为 SKU 行，并随行携带 `combo_group`、`combo_atomic`。WMS 不持有组合 BOM 主数据。
> 配套文档：[01电商系统-组合商品管理简易需求文档.md](./01电商系统-组合商品管理简易需求文档.md)

---

## 1. 基本信息

- 功能名称：组合商品履约（WMS）
- 所属系统：WMS · 订单发货履约 / 库存中心 / 仓库 APP 作业
- 适用范围：含组合商品的发货履约单的预扣、备货、复核、出库、缺货处理与逆向退货
- 版本说明：1.0 在不新增组合库存的前提下，按 SKU 完成组合商品的可行性判定、履约、缺货归属与逆向收货，组合关系仅通过订单行标签 `combo_group`/`combo_atomic` 体现。

---

## 2. 核心原则

1. **WMS 只按 SKU 数量履约**，价格是订单层属性，WMS 不参与金额计算。
2. **不持有组合 BOM 主数据**：WMS 把同一 `combo_group` 的订单行聚合，即可就地「重建」该份组合实例的履约需求，无需查电商 BOM。
3. **原子单元是「单份组合实例」**（一个 `combo_group`），不是订单行，也不是「组合×N」整体。
4. **作业层按 SKU 聚合（高效），台账层按订单行归属（可追溯）**——两者不冲突。

---

## 3. 订单行字段（来自电商展开后下发）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `order_line_no` | 是 | 上游订单行号 |
| `sku_code` | 是 | WMS SKU 编码 |
| `quantity` | 是 | 该行 SKU 数量 |
| `combo_group` | 是 | 组合实例标识；`null`=单买，有值（如 `A#1`）=属于某份组合实例 |
| `combo_atomic` | 是 | 该行所属组合是否原子（整组成败）；单买行为 false |
| `combo_code` / `combo_name` | 否 | 仅用于作业/展示，标明组合来源 |
| `unit_price` | 否 | 清关/计费用，WMS 不据此履约 |

> `combo_group`、`combo_atomic` 为**接口必填**：缺失会导致 WMS 丢失原子性，无法做缺货可行性判定与退款归属。

WMS 按 `combo_group` 聚合即可重建实例需求，例如：

```
combo_group="A#1" (atomic) 聚合得到 → 该份组合需 SKU1×3 + SKU2×2
combo_group=null  → 单买 SKU1×2
```

## 4. 库存分配与可行性判定（履约核心算法）

### 4.1 总流程

```
1) 按 combo_group 把订单行分组，重建各组合实例需求 + 单买行需求
2) 对每个原子组合实例做「可行性判定」：所有组件库存是否都够配齐 1 份
     - 任一组件不足 → 该实例整组不可履约，零占用（不锁定任何组件）
     - 全部够      → 该实例可履约，整组锁定/预扣
3) 剩余库存按 shortage_priority 分配给其余可行实例与单买行
     - 默认 shortage_priority = 保组合优先（组合实例先于单买行分配）
4) 单买行按可用量尽量满足，不足部分按行缺货
5) 不可履约的组合实例 / 缺货的单买行 → 进缺货处理（第 5、6 章）
```

### 4.2 瓶颈组件决定可履约份数

一份组合能否履约，取决于最紧缺的组件。可履约份数 = 各组件 `⌊可用量 / 单份需求⌋` 取最小值。

### 4.3 关键规则

- **原子组合不可行则零占用**：不能把库存塞进一个注定凑不齐的原子组合，否则白占库存还饿死其他可履约行。
- **组合优先**：当组件有的紧缺有的富余，优先把紧缺组件喂给组合，先保住能凑齐的份数；尤其当某组件只被组合消耗时，不保组合会导致其彻底闲置。
- **`shortage_priority` 可由货主配置**（保组合 / 保单买），默认保组合。

### 4.4 算例（与设计评审口径一致）

**算例一**：组合A×1 = SKU1×3+SKU2×2，单买 SKU1×2；SKU1 库存=2。
- 组合A 需 SKU1×3 > 2 → 整组不可履约，零占用。
- 单买 SKU1×2 ← 用可用 2 个满足。
- 结果：**发单买 SKU1×2；组合A 整组缺货（退组合价，SKU1×3+SKU2×2 不发，SKU2 不占用）**。注意不是「退 3 个 SKU1」。

**算例二**：组合A×2 = (SKU1×3+SKU2×2)×2，单买 SKU1×2；SKU1 库存=3，SKU2 库存=2。
- A#1：需 SKU1×3(有3)+SKU2×2(有2) → 可履约，扣后 SKU1=0、SKU2=0。
- A#2：SKU1 剩 0 → 不可履约，零占用。
- 单买：剩 0 → 缺货。
- 结果：**发组合 A#1 一份（SKU1×3+SKU2×2）；A#2 整组缺货 + 单买 SKU1×2 缺货**。

**算例三**：同上但 SKU1 库存=3，SKU2 库存=5。
- 可履约份数 = min(⌊3/3⌋, ⌊5/2⌋) = min(1,2) = 1，瓶颈是 SKU1。
- 结果：**发组合 A#1 一份；A#2 整组缺货 + 单买 SKU1×2 缺货；SKU2 富余 3 个留库不动**。

## 5. 缺货处理（WMS 在揽货阶段发起）

### 5.1 缺货归属

当共享 SKU 部分短缺时，WMS 按 `shortage_priority` 先确定短缺归属哪条行/哪份组合，再带明确信息发起沟通：

- 默认「保组合完整」：短缺优先归给单买行；组合实例尽量整发。
- 若短缺导致某原子组合实例凑不齐 → 该实例整组判为缺货（按其 `return_policy` 走整组换/退）。

### 5.2 缺货沟通流程（WMS → 电商 → 客户）

```
揽货发现某 SKU 短缺
   ↓ WMS 按 shortage_priority 判定短缺归属（哪条单买行 / 哪份组合实例）
   ↓ 生成缺货异常，附来源（单买 / 组合 combo_group）
   ↓ WMS 发起沟通，给出选项：
       · 换同 SKU 其他批次 / 换其他 SKU
       · 退该行（单买行 → 退该行价）
       · 归属组合且 atomic → 整组换/退（该份组合的所有组件一起）
   ↓ 客户确认 → WMS 执行换货/部分取消 → 电商侧按所定行/组合的固化价退款
```

### 5.3 可揽货数的两个口径

缺货界面需同时展示，避免运营误判：

- **物理可拣数**：SKU 实际库存可拣数量。
- **可履约份数/数量**：考虑组合原子性后真正能成交的数量。原子组合凑不齐时，组件物理库存虽在，但对该组合「可履约数 = 0」。

## 6. 正向履约作业（备货/复核/出库）

1. **作业层按 SKU 聚合**：同一 SKU 跨多条行（含单买 + 多个组合实例）合并为「SKU 总数一起拣」，物理上无需区分哪件给哪行，效率最高。
2. **台账层按 `order_line_no` / `combo_group` 归属**：出库回执按订单行回传，聚合拣货不销毁行级归属。
3. **组合分组提示**：APP 与 Web 作业界面按 `combo_group` 聚合展示同组 SKU（"以下 N 件属于组合『xx』，请一起拣/核"），可给推荐拣货顺序。
4. **同仓约束**：组合实例的组件 SKU 标记同仓优先/不可跨仓拆分，避免组合被拆仓发。
5. **复核与出库**：口径沿用现有「复核 = 打包出库数量」，组合不改变三数量（预扣/复核/出库）口径。

---

## 7. 逆向退货

| 场景 | 判断归属方式 | WMS 动作 |
| --- | --- | --- |
| 客户签收后退货 | 物理 SKU 不可区分 → 由客户/客服在售后界面选「退哪一行/哪份组合」，系统据 `order_line_no`/`combo_group` 确定 | 按 SKU 收货入库，回传实收数量，不算金额 |
| 揽货缺货发起的退/换 | WMS 按 `shortage_priority` 判定（见第 5 章），非客户选 | 执行换货/部分取消，回传结果 |

退货颗粒度遵循组合的 `return_policy`：

- `atomic`：组合内组件必须整组退（如组合的 SKU1 + SKU2 一起），退款 = 组合成交价；不允许只退组合里的某个组件。
- `splittable`：可按组件退，退款 = 该组件固化分摊价。

WMS 全程按 SKU 收货，`combo_group` 仅用于辅助核对组件是否齐套。

---

## 8. 订单跟踪与统计

1. **销售订单跟踪**（只读）按 `combo_group` 折叠展示，展开看各 SKU 的预扣/复核/出库三数量，与现有口径一致。
2. WMS 侧只产出 SKU 级出库流水；通过 `combo_group` 可反查「某 SKU 有多少来自组合售卖」。组合销量统计在电商侧完成。

---

## 9. 不在范围

| 不在范围项 | 说明 |
| --- | --- |
| 组合库存模型 | 不新增，库存仍按 SKU 管理 |
| 组合 BOM 主数据 | WMS 不持有，靠订单行 `combo_group` 重建 |
| 组合独立入库 / 条码 / 拆包 | 不做 |
| 退款金额计算 | 由电商售后系统按快照计算，WMS 不参与 |
| 组合定价 / 折扣分摊规则 | 电商侧职责 |
