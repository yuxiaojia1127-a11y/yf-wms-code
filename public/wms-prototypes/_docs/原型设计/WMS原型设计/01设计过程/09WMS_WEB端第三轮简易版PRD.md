# WMS_WEB端第三轮简易版PRD

## 1. 文档说明

本文为 `WMS原型设计` 第三轮简易版 PRD，承接前两轮已完成的 `开放平台 + 主数据 + 入库/库存/出库主链路` 与 `物流中心 + 物流协同`，继续补齐 WMS_WEB 端中的售后中心与调拨中心。

本轮重点覆盖：

- 售后中心
- 调拨中心

本轮特别说明：

- 售后中心本轮仅覆盖 WMS 侧承接后的仓储处理能力，不包含第三方电商系统或客服系统中的售后申请发起能力。
- 调拨中心本轮聚焦调拨单管理和结果追踪，不展开调拨建议、自动补货或复杂审批流。
- 本轮页面以后台管理视角为主，不替代 APP 端的一线执行页面。

本轮不展开以下范围：

- 开放平台
- 主数据
- 入库中心
- 库存中心
- 出库中心
- 物流中心
- 物流协同
- 仓内作业中心
- 异常中心
- 结算中心

状态口径说明：本文中的业务对象状态、执行结果状态、异常状态统一引用 [15WMS_WEB端状态口径总表.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/原型设计/WMS原型设计/15WMS_WEB端状态口径总表.md)；若本文件局部示例与状态口径总表存在差异，以状态口径总表为准。

## 2. 功能目标

本轮简易版 PRD 的目标是补齐 WMS_WEB 端中“逆向仓储处理”和“仓库间库存移动管理”两类核心管理能力，形成售后退货和调拨协同的后台视角。

具体目标如下：

1. 建立退货单管理视角，统一承接退货入仓、退货确认、退货取消、退货详情和质检结果查看。
2. 建立调拨单管理视角，统一承接调拨单创建、确认、状态跟踪和差异查看。
3. 明确退货和调拨与入库中心、出库中心、库存中心之间的依赖关系。
4. 为后续 APP 执行端和异常中心补齐退货、调拨的执行与异常闭环提供输入基线。
5. 控制第三轮范围，只解决“后台管理和跟踪”的需求，不提前展开过多仓内执行细节。

## 7. 核心流程

### 7.1 退货管理主链路

1. 上游系统创建退货入库单，并传入履约店铺信息。
2. WMS 受理退货单后，在退货单列表中展示待处理状态。
3. 管理人员进入退货单详情页查看退货商品、来源单据、收货信息和处理进度。
4. 仓内执行完成退货收货与质检后，质检结果回流到详情页展示。
5. 退货单形成最终处理结论，如回库、报损或其他处理结果。

### 7.2 调拨管理主链路

1. 上游或后台创建调拨单，明确调出仓库、调入仓库和商品数量。
2. WMS 受理调拨单后，在调拨单列表中展示状态。
3. 管理人员进入调拨单详情页查看调拨时间线、出库结果、入库结果和在途状态。
4. 如出现少发、少收、破损或批次差异，则在详情页中记录差异结果。
5. 调拨完成后，库存中心同步反映调出和调入结果。

### 7.3 退货与调拨协同说明

1. 退货和调拨在 Web 端均以“管理与跟踪”视角呈现。
2. 现场收货、质检、调拨出入库执行由 APP 端或仓内执行端承接。
3. 本轮页面需要明确查看结果和状态，但不要求在 Web 端完成所有现场操作。

## 8. 状态流转

本章节不再定义独立的 Web 端状态体系，统一引用 [15WMS_WEB端状态口径总表.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/原型设计/WMS原型设计/15WMS_WEB端状态口径总表.md)；以下内容仅用于说明本轮涉及对象的状态使用范围、页面展示位置和理解方式。

### 8.1 退货单状态

| 状态 | 说明 |
| ---- | ---- |
| 待受理 | 退货单已创建，待 WMS 受理 |
| 已确认 | 退货单已入仓受理 |
| 处理中 | 已进入收货或质检处理过程 |
| 已完成 | 退货处理完成，并形成最终处理结论 |
| 已取消 | 退货单已取消 |
| 异常 | 退货过程中存在收货、质检或结果异常 |

### 8.2 质检结果状态

| 状态 | 说明 |
| ---- | ---- |
| 待质检 | 尚未形成质检结论 |
| 可回库 | 退货商品可重新入库 |
| 报损 | 退货商品不可回库，需报损处理 |
| 部分异常 | 部分商品或数量存在异常，需要人工确认 |

### 8.3 调拨单状态

| 状态 | 说明 |
| ---- | ---- |
| 待确认 | 调拨单已创建，待确认处理状态 |
| 待出库 | 调出方待执行出库 |
| 在途 | 调拨货物已离开调出仓，待调入仓接收 |
| 待入库 | 调入方待完成收货入库 |
| 已完成 | 调拨处理完成 |
| 已取消 | 调拨单已取消 |
| 异常 | 调拨过程中存在差异、破损或状态异常 |

## 13. 异常处理

| 场景 | 处理要求 |
| ---- | ---- |
| 退货单查询为空 | 保留筛选条件并展示空数据页 |
| 退货质检结果缺失 | 详情页展示“待质检”状态，不擅自推断处理结论 |
| 退货处理结果冲突 | 在详情页提示当前结果异常，留待后续异常中心处理 |
| 调拨单在途超时 | 在调拨详情中突出超时风险标记 |
| 调拨出入库结果不一致 | 显式展示差异项和受影响数量 |
| 调拨单取消失败 | 返回失败原因，不改变原状态 |

## 15. 模块依赖与协作

| 模块 | 依赖对象 | 依赖说明 |
| ---- | ---- | ---- |
| 售后中心 | 上游退货单来源 | 退货单由上游系统创建，WMS 负责承接仓储处理 |
| 售后中心 | 入库中心 | 退货回库结果会影响入库结果和库存变化 |
| 售后中心 | 库存中心 | 回库或报损会影响库存数量和状态 |
| 调拨中心 | 出库中心 | 调拨调出结果依赖调拨出库执行结果 |
| 调拨中心 | 入库中心 | 调拨调入结果依赖调拨入库执行结果 |
| 调拨中心 | 库存中心 | 调拨完成后影响调出仓和调入仓库存 |
| 售后中心/调拨中心 | 异常中心 | 当前只展示异常来源，完整异常闭环留待后续轮次 |

## 16. 待确认项

| 编号 | 待确认项 | 说明 |
| ---- | ---- | ---- |
| 1 | 退货单详情与质检页是否维持合并页 | 当前按一个页面处理，后续如信息量过大可拆分详情页和质检结果页 |
| 2 | 退货处理结论是否需要细化更多类型 | 当前仅收敛为回库、报损、部分异常等口径 |
| 3 | 调拨单是否需要在 Web 端支持创建入口 | 当前页面清单更偏查询和跟踪，创建入口可后续确认 |
| 4 | 调拨状态是否需要增加“待确认收货”等更细粒度状态 | 当前先采用简化状态集 |
| 5 | 换货链路是否作为售后中心下一轮补充 | 当前第三轮不纳入范围 |
| 6 | 调拨差异是否需要在本轮提供处理动作 | 当前建议只查看差异记录，正式处理动作后续结合异常中心确定 |

## 17. 测试关注点

| 类别 | 测试点 |
| ---- | ---- |
| 退货管理 | 退货单状态、质检结果、处理结论是否一致展示 |

| 调拨管理 | 调拨单状态、在途标记、时间线是否正确 |
| 调拨差异 | 少发、少收、破损、批次差异是否可见且可追溯 |
| 权限 | 售后、调拨、仓库角色是否只看到授权页面和数据 |
