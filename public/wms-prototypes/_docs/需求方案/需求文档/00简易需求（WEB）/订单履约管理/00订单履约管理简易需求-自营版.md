# 订单履约管理简易需求（自营版）

## 1. 基本信息

- 功能名称：订单履约管理
- 所属系统：WMS_WEB端 / WMS_API
- 页面编号：`WMS-WEB-FUL01`
- 所属模块：订单履约管理
- 文档定位：自营业务版
- 适用范围：发货指令接收、履约单管理、销售渠道履约仓校验、揽货单拆单、即采即销仓履约、复核打包合单、退款拦截、履约异常、履约结果回传

## 2. 核心结论

### 2.1 WMS管理对象

| 对象 | 主键/编码 | 管理口径 | 作用 |
| --- | --- | --- | --- |
| 发货指令 | 外部发货指令号 | 上游销售系统下发的原始履约请求 | 承接销售订单、补发单等发货来源 |
| 销售渠道履约仓配置 | 销售渠道 + 仓库 | 渠道可履约仓库范围 | 定义销售渠道可使用的前置仓、即采即销仓、仓库优先级和服务范围 |
| 履约单 | 履约单号 | WMS内部履约主单 | 管理订单校验、仓库确认、出库生成和状态回传 |
| 履约明细 | 履约单号 + SKU | 履约商品明细 | 记录应发SKU、数量、仓库、批次要求和履约结果 |
| 揽货单 | 揽货单号 | 按仓库拆分后的揽货执行单 | 承接履约明细分配结果，按履约仓库下发揽货接单任务 |
| 出库单 | 出库单号 | 仓库出库执行单 | 承接揽货单并进入揽货接单、库存锁定、揽货、复核、发货流程 |
| 合单复核 | 合单复核号 | 打包复核合单作业 | 将同一订单、同一仓库、同一配送方式的揽货结果合并复核打包 |
| 包裹 | 包裹号 | 发货包装单元 | 记录箱号、重量、物流单号和包裹状态 |
| 物流单 | 物流单号 | 运输单据 | 记录承运商、运单号、发货时间和轨迹结果 |
| 即采即销履约 | 即采即销单号 | 即采即销仓采购揽货作业 | 前置仓库存不足且SKU支持即采即销时，分配到即采即销仓履约 |
| 换货记录 | 换货记录号 | 缺货换货处理 | 记录原SKU、替换SKU、消费者确认结果和差额说明 |
| 退款拦截 | 拦截记录号 | 退款订单履约拦截 | 退款发生后停止前置仓和即采即销仓继续揽货履约 |
| 履约异常 | 异常单号 | 履约过程异常 | 记录SKU异常、库存不足、仓库不可用、出库失败、回传失败 |
| 履约回传 | 回传记录号 | 对上游系统的结果同步 | 回传接收、取消、发货、异常等履约结果 |

### 2.2 核心规则

1. 自营版订单履约管理只处理自营业务的发货指令，不支持外部商家入驻与库存隔离。
2. 发货指令进入WMS后，先生成履约单，再按销售渠道履约仓配置进行揽货单拆单。
3. 履约单负责业务编排，揽货单负责仓库分配，出库单负责仓内执行。
4. WMS必须校验销售渠道配置的履约仓库，只允许在该销售渠道可用履约仓范围内分配库存。
5. WMS优先选择可一次满足全部商品的前置仓，并优先选择距离收货地址较近的前置仓。
6. 单一前置仓无法全部履约时，WMS按库存可用量将商品拆分到其他可履约前置仓。
7. 所有前置仓库存不足时，支持即采即销的SKU可分配到该销售渠道配置的即采即销仓。
8. 同一发货指令可拆成多张揽货单；每张揽货单只对应一个履约仓库。
9. 同一SKU是否允许按数量拆分，由销售渠道或SKU履约规则控制。
10. 同一订单、同一仓库、同一配送方式的多张揽货单可在复核打包环节合单。
11. 跨仓揽货单默认不做物理合单，分别生成包裹和物流结果。
12. 即采即销仓采购揽货无货时，需进入消费者确认流程，支持换货、部分退款备注或整单退款拦截。
13. 同一发货指令不得重复生成有效履约单，需按外部发货指令号进行幂等控制。
14. 履约完成以出库发货确认为准。
15. 履约异常必须记录异常原因、处理结果和回传状态。

## 3. 业务目标

订单履约管理用于承接上游销售系统的发货指令，完成履约校验、履约单创建、履约仓库确认、揽货单拆单、即采即销仓分配、复核打包合单、出库单生成、发货结果追踪和履约结果回传。

系统通过履约单把销售业务指令与仓库出库作业解耦，通过揽货单把同一订单拆分到不同履约仓库，使订单运营可以查看拆单和履约进度，仓库可以通过出库单完成实际作业，上游系统可以接收履约状态、换货、退款备注和发货结果。

## 5. 履约来源

| 来源类型 | 来源单据 | 典型场景 | 处理方式 |
| --- | --- | --- | --- |
| 销售发货 | 销售订单 / 发货指令 | 正常销售订单发货 | 校验后生成履约单和销售出库单 |
| 补发发货 | 补发单 / 售后补发指令 | 漏发、破损、售后补发 | 校验后生成履约单和销售出库单 |

| 手工发货 | 手工发货指令 | 特殊业务人工发货 | 审核后生成履约单和出库单 |

## 6. 状态流程

### 6.1 履约单状态

| 状态 | 含义 | 规则 |
| --- | --- | --- |
| 已接收 | 发货指令已进入WMS | 可进行履约校验 |
| 校验中 | 系统正在校验SKU、仓库、库存和地址 | 不允许重复处理 |
| 拆单中 | 系统正在按履约仓库和库存拆分揽货单 | 不允许重复拆单 |
| 待揽货接单 | 揽货单已生成，等待下发或接单 | 可进入出库管理 |
| 待生成出库 | 揽货单已确认，等待生成出库单 | 可生成出库单 |
| 已生成出库 | 已生成出库单 | 进入出库管理流程 |
| 出库中 | 出库单正在执行 | 接收出库状态回写 |
| 待合单复核 | 同仓多揽货单等待复核打包合单 | 可执行合单复核 |
| 已发货 | 出库单已完成发货确认 | 可回传发货结果 |
| 已取消 | 履约单已取消 | 不再生成出库 |
| 已挂起 | 人工暂停处理 | 释放后继续处理 |
| 异常 | 存在阻断问题 | 进入异常处理 |

### 6.2 揽货单状态

| 状态 | 含义 |
| --- | --- |
| 待下发 | 已完成拆单，尚未下发给履约仓库 |
| 待接单 | 已下发给履约仓库，等待揽货人员接单 |
| 已接单 | 揽货人员已承接 |
| 揽货中 | 仓库正在揽货 |
| 已揽货 | 揽货完成，等待复核或合单 |
| 已取消 | 揽货单取消，不再执行 |
| 异常 | 揽货单存在缺货、换货、退款拦截等异常 |

### 6.3 合单复核状态

| 状态 | 含义 |
| --- | --- |
| 无需合单 | 单仓单揽货单或不满足合单条件 |
| 待合单 | 同仓多揽货单等待合并复核 |
| 合单中 | 复核人员正在合并复核和打包 |
| 已合单 | 已完成合单复核并生成包裹 |
| 合单异常 | SKU、数量、批次、包裹信息不一致 |

### 6.4 即采即销状态

| 状态 | 含义 |
| --- | --- |
| 不涉及 | 订单未分配到即采即销仓 |
| 待采购揽货 | 已分配到即采即销仓，等待采购揽货 |
| 采购揽货中 | 作业人员正在向供应商采购揽货 |
| 已采购揽货 | 采购揽货完成 |
| 无货待确认 | 供应商无货，等待消费者确认处理方式 |
| 已换货 | 消费者同意换货并完成SKU替换 |
| 部分退款待回传 | 消费者同意部分退款，需要告知上游系统 |
| 整单退款拦截 | 消费者不同意换货，整单退款并停止履约 |

### 6.5 回传状态

| 状态 | 含义 |
| --- | --- |
| 待回传 | 履约结果尚未同步 |
| 回传中 | 系统正在同步结果 |
| 回传成功 | 上游系统已确认接收 |
| 回传失败 | 同步失败，等待重试或人工处理 |
| 无需回传 | 该业务不要求同步结果 |

### 6.6 出库关联状态

| 状态 | 含义 |
| --- | --- |
| 未生成 | 尚未生成出库单 |
| 已生成 | 已生成出库单 |
| 出库中 | 出库单已进入仓内作业 |
| 出库完成 | 出库单已发货 |
| 出库异常 | 出库作业存在异常 |
| 出库取消 | 出库单被取消 |

## 7. 关键流程

### 7.1 发货指令接收流程

1. 上游销售系统通过接口或人工方式向WMS下发发货指令。
2. WMS按外部发货指令号进行幂等校验。
3. 系统校验SKU、商品状态、数量、仓库、地址、发货方式等基础信息。
4. 校验通过后生成履约单和履约明细。
5. 校验不通过时生成履约异常。

### 7.2 履约校验流程

1. 系统校验发货指令明细中的SKU是否存在且启用。
2. 系统校验发货数量是否大于0。
3. 系统校验销售渠道是否存在有效履约仓配置。
4. 系统筛选销售渠道可用前置仓和即采即销仓。
5. 系统校验前置仓是否启用、是否覆盖收货地址、是否具备发货能力。
6. 系统校验SKU在候选履约仓的可用库存。
7. 校验通过后，履约单进入拆单中状态。

### 7.3 揽货单拆单流程

1. 系统读取销售渠道配置的履约仓库范围。
2. 系统按收货地址距离、仓库优先级、服务范围和仓库状态筛选前置仓。
3. 系统优先寻找可一次满足全部SKU和数量的前置仓。
4. 存在多个可满足全部商品的前置仓时，优先选择距离收货地址较近的前置仓。
5. 最近前置仓无法满足全部商品时，系统按SKU和数量缺口继续匹配其他可履约前置仓。
6. 若同一SKU允许按数量拆分，系统可将同一SKU数量分配到多个前置仓。
7. 若同一SKU不允许按数量拆分，该SKU必须完整分配到一个履约仓。
8. 所有前置仓均无法满足的SKU，若支持即采即销，则分配到销售渠道配置的即采即销仓。
9. 拆单完成后，系统生成一张或多张揽货单，每张揽货单只对应一个履约仓库。
10. 揽货单生成后，下发给对应履约仓库进入揽货接单流程。

### 7.4 即采即销履约流程

1. 前置仓库存不足且SKU支持即采即销时，系统生成即采即销仓揽货单。
2. 即采即销仓揽货人员接单后，按SKU和数量向供应商采购揽货。
3. 采购揽货成功后，系统记录实揽SKU、数量、采购来源和揽货结果。
4. 供应商无货时，系统将该SKU标记为无货待确认。
5. 消费者同意换货时，即采即销仓揽货人员在WMS中执行SKU换货，记录原SKU、替换SKU、数量和确认结果。
6. 消费者同意部分退款时，WMS记录退款备注并回传或提示上游销售系统处理差额。
7. 消费者不同意换货时，WMS将履约单标记为整单退款拦截，停止所有前置仓和即采即销仓未完成揽货任务。

### 7.5 复核打包合单流程

1. 揽货单完成后进入复核打包环节。
2. 系统判断同一订单下是否存在可合单的揽货单。
3. 同一订单、同一履约仓库、同一配送方式、同一收货信息的揽货单允许合单复核。
4. 不同履约仓库的揽货单默认不做物理合单，分别复核、打包和发货。
5. 合单复核时，复核员扫描多个揽货单或容器，系统汇总应发SKU和数量。
6. 复核通过后生成一个或多个包裹，并记录包裹与揽货单、履约单的关联关系。
7. 复核不通过时生成合单异常，进入履约异常处理。

### 7.6 退款拦截流程

1. 上游销售系统发生退款或取消时，向WMS同步退款拦截指令。
2. WMS按外部发货指令号或履约单号定位履约单、揽货单和出库单。
3. 未接单或未揽货的揽货单直接取消。
4. 已接单未完成的揽货单停止继续揽货，并通知对应前置仓或即采即销仓。
5. 已完成揽货但未发货的任务进入人工异常处理。
6. 已发货的任务不再拦截，回传已发货结果并保留退款拦截失败原因。

### 7.7 出库单生成流程

1. 揽货单拆单完成后，系统按揽货单生成销售出库单。
2. 每张揽货单默认生成一张对应的销售出库单。
3. 出库单继承履约单号、揽货单号、来源单号、仓库、SKU、数量、批次要求和发货信息。
4. 出库单生成成功后，履约单状态更新为已生成出库。
5. 出库单进入出库管理模块，由出库管理执行揽货接单、库存锁定、揽货、复核、打包、发货。
6. 出库管理回写出库状态、包裹、物流和异常信息。

### 7.8 履约结果回传流程

1. 出库单完成发货确认。
2. 系统更新履约单为已发货。
3. 系统生成履约回传记录。
4. 回传内容包含履约单号、外部发货指令号、揽货单号、出库单号、包裹号、物流单号、发货数量和发货时间。
5. 回传成功后记录回传结果。
6. 回传失败时保留失败原因，支持重试和人工处理。

### 7.9 履约异常处理流程

1. 发货指令接收、履约校验、出库生成、出库执行或结果回传环节发现异常。
2. 系统记录异常类型、异常原因、影响单据、处理建议和处理状态。
3. 订单运营或系统管理员处理异常。
4. 异常处理完成后，根据处理结果继续履约、取消履约、挂起履约或重新回传。

## 9. 规则要求

### 9.1 接收规则

- 外部发货指令号必须唯一。
- 重复发货指令按幂等规则处理，不重复生成有效履约单。
- 发货指令必须包含销售渠道、来源单号、SKU、数量、收货信息和发货方式。
- SKU不存在、停用或数量异常时，不生成有效出库单。

### 9.2 销售渠道履约仓规则

- 每个销售渠道必须配置可用履约仓库。
- 履约仓库类型包括前置仓和即采即销仓。
- 前置仓用于优先履约现货库存。
- 即采即销仓用于前置仓库存不足且SKU支持即采即销时承接缺口。
- 销售渠道未配置履约仓库时，履约单进入异常。
- 仓库停用、超出服务范围或不具备发货能力时，不参与拆单。

### 9.3 揽货单拆单规则

- 履约单校验通过后才能执行揽货单拆单。
- 一个履约单可拆成多张揽货单。
- 每张揽货单只对应一个履约仓库。
- 优先选择距离收货地址较近且可一次满足全部商品的前置仓。
- 单仓无法全部满足时，按缺口分配到其他可履约前置仓。
- 同一SKU是否允许按数量拆分，由销售渠道或SKU履约规则控制。
- 不允许数量拆分的SKU，必须完整分配到一个履约仓库。
- 拆单完成后，履约明细需记录揽货单号、履约仓库、分配数量和拆单原因。
- 揽货单生成后，不允许直接修改原始履约明细，只能通过重新拆单、换货或异常处理修正。

### 9.4 即采即销规则

- 只有支持即采即销的SKU才能分配到即采即销仓。
- 即采即销仓必须属于该销售渠道的可用履约仓配置。
- 即采即销揽货单必须记录采购揽货状态。
- 供应商无货时，必须记录消费者确认结果。
- 消费者同意换货时，必须记录原SKU、替换SKU、数量、确认人和确认时间。
- 消费者同意部分退款时，WMS记录退款备注并回传或提示上游销售系统处理。
- 消费者不同意换货时，整单进入退款拦截流程。

### 9.5 合单复核规则

- 同一订单、同一履约仓库、同一配送方式、同一收货信息的揽货单允许合单复核。
- 不同履约仓库的揽货单默认不做物理合单。
- 存在即采即销无货待确认、换货待确认或退款拦截时，不允许合单发货。
- 合单复核必须校验SKU、数量、批次、效期、包裹和物流信息。
- 合单完成后，包裹需记录关联的履约单、揽货单和出库单。

### 9.6 退款拦截规则

- WMS收到退款或取消指令后，必须按外部发货指令号或履约单号定位任务。
- 未接单、未揽货、未发货的揽货单必须停止履约。
- 已发货的揽货单不再拦截，需回传已发货结果。
- 拦截成功或失败都必须记录原因和处理时间。
- 整单退款拦截时，前置仓和即采即销仓都不再继续揽货履约。

### 9.7 出库衔接规则

- 履约单校验通过后才能生成出库单。
- 每张揽货单默认生成一张出库单。
- 出库单取消时，履约单需同步更新出库关联状态。
- 出库单发货完成后，履约单更新为已发货。
- 出库差异需同步回写履约异常。

### 9.8 回传规则

- 履约结果按履约单维度回传。
- 发货回传必须包含履约单号、揽货单号、出库单号、包裹号、物流单号、发货数量和发货时间。
- 换货回传必须包含原SKU、替换SKU和确认结果。
- 部分退款备注必须回传或提示上游销售系统处理。
- 回传失败不影响已完成的仓库作业，但必须保留失败记录。
- 回传失败支持手动重试。

## 10. 异常场景处理

| 异常场景 | 系统处理 |
| --- | --- |
| 发货指令重复 | 按外部发货指令号进行幂等处理 |
| 销售渠道未配置履约仓 | 生成履约异常，阻断拆单 |
| SKU不存在或停用 | 生成履约异常，阻断出库生成 |
| 发货数量异常 | 生成履约异常，阻断出库生成 |
| 指定仓库不可用 | 生成履约异常，等待人工处理 |
| 前置仓库存不足 | 按其他可履约前置仓继续分配，仍不足时判断是否进入即采即销 |
| 即采即销不支持 | 生成库存不足异常，等待换货、部分退款或取消 |
| 即采即销供应商无货 | 进入无货待确认，等待消费者确认换货或退款 |
| 消费者同意换货 | 记录原SKU和替换SKU，继续即采即销履约 |
| 消费者同意部分退款 | 记录退款备注，回传或提示上游销售系统 |
| 消费者不同意换货 | 整单退款拦截，停止所有未完成揽货履约 |
| 退款订单已发货 | 拦截失败，回传已发货结果并保留原因 |
| 合单复核不一致 | 生成合单异常，阻断打包发货 |
| 收货信息缺失 | 生成履约异常，等待补全 |
| 出库单生成失败 | 记录失败原因，支持重新生成 |
| 出库作业异常 | 同步出库异常，进入履约异常处理 |
| 发货数量不一致 | 记录差异并按出库结果更新履约状态 |
| 回传失败 | 记录回传失败原因，支持重试 |

## 11. 验收要点

- 能接收上游发货指令并生成履约单。
- 能按外部发货指令号进行幂等控制。
- 能按履约单号、外部发货指令号、来源单号、销售渠道、履约状态、拆单状态、合单复核状态、即采即销状态、出库关联状态、回传状态、仓库、SKU完成查询。
- 能查看履约单详情、明细、关联出库单、包裹、物流和回传记录。
- 能完成SKU、数量、销售渠道履约仓、库存和收货信息校验。
- 能按销售渠道履约仓配置生成一张或多张揽货单。
- 能优先分配到可一次满足全部商品且距离收货地址较近的前置仓。
- 前置仓库存不足时，能将缺口分配到其他可履约前置仓。
- SKU支持即采即销时，能将前置仓无法满足的缺口分配到即采即销仓。
- 即采即销无货时，能记录消费者确认结果，支持换货、部分退款备注和整单退款拦截。
- 退款拦截后，未完成的前置仓和即采即销仓揽货任务不再继续履约。
- 满足条件的同仓揽货单能执行复核打包合单。
- 跨仓揽货单默认分别复核、打包和发货。
- 能基于揽货单生成销售出库单。
- 出库单状态能回写履约单。
- 出库发货完成后能更新履约状态并生成回传记录。
- 回传失败能记录失败原因并支持重试。
- 履约异常能登记、处理和追踪。
