# WMS-WEB 仓内作业跟踪明细列表简易需求文档

## 1. 基础信息

| 项目 | 内容 |
| ---- | ---- |
| 功能名称 | 仓内作业跟踪明细列表 |
| 所属模块 | 仓内作业 |
| 页面定位 | 承接驾驶舱"今日作业漏斗"中仓内作业跟踪节点的下钻明细页 |
| 页面编码 | `WMS-WEB-030A` |
| 适用端 | WMS-WEB 管理端 |

---

## 2. 业务说明

仓内作业跟踪明细列表用于承接驾驶舱"今日作业漏斗"中仓内作业跟踪分组的节点下钻需求，帮助仓内管理角色聚焦节点积压、超时和责任人分布。

支持节点：

- 待入库
- 待接单揽货
- 待揽货
- 待打包复核
- 待发货
- 已发货

---

## 3. 查询条件

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| 仓库 | 下拉单选 | 默认当前驾驶舱所选仓库 |
| 库房 | 下拉单选 | 根据所选仓库联动，可选：常温主库、冷藏专区、综合库房等 |
| 作业节点 | 下拉单选 | 从驾驶舱进入时自动带入 |
| 渠道类型 | 下拉单选 | 即时配送 / 快递 / 自提 |
| 处理状态 | 下拉单选 | 全部 / 待处理 / 已超时 / 已完成 |
| 关键词 | 输入框 | 模糊匹配：**任务ID** / 原始单号 / 联系人 / 地址编码 |

---

## 4. 列表字段

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| **任务ID** | 文本 | 系统自增编号，3位补零（001、002…），替代原"单号"字段 |
| **原始单号** | 文本 | 原始采购单号或出库单号（PO-/SO- 格式） |
| 作业节点 | 标签 | 当前节点类型 |
| 仓库 | 文本 | 单据归属仓库 |
| 库房 | 文本 | 单据归属库房 |
| 渠道类型 | 文本 | 即时配送 / 快递 / 自提 |
| 当前状态 | 标签 | 已超时 / 待处理 / 已完成 |
| 等待时长 | 数值 | 单位：分钟 |
| 处理人 | 文本 | 当前责任人 |
| 更新时间 | 时间 | 最近一次状态更新时间 |
| 操作 | 按钮 | 查看详情 → 打开右侧详情抽屉 |

**排序规则**：默认按等待时长倒序，超时单优先，每页 10 条。

---

## 5. 详情抽屉

点击"查看详情"后从右侧打开详情抽屉，标题统一为「任务详情」。根据节点类型分两套渲染方案，**底部仅保留「关闭」按钮**，不提供"进入对应页面"。

---

### 方案 A：揽货类任务详情

**适用节点**：待接单揽货、待揽货、待打包复核、待发货、已发货

#### Hero 区

| 元素 | 规则 |
| ---- | ---- |
| 任务类型 | 大标题展示节点名称（如"待接单揽货"） |
| 任务ID | 纯展示，**无复制功能** |
| 原始单号 | 展示 + **复制按钮** |
| 处理状态 | chip，已超时=红 / 已完成=绿 / 其他=橙 |
| chips 行 | 渠道、承诺时效、配送距离 |

#### 任务信息

2×2 grid，4 个字段：

| 字段 | 说明 |
| ---- | ---- |
| 库房 | 归属仓库名称 |
| 预约送达时间 | 承诺送达时间 |
| 商品缺货时 | 橙色文字 |
| 订单备注 | 橙色文字 |

#### 联系人与收货地址

- 联系人行：姓名 + 手机号，**不显示拨号按钮、不显示"收货详情"链接**
- 邮编单独一行
- 地址卡片（从上到下）：
  - 完整地址（shortAddress）
  - 收货点：详细地址（collectionAddress）
  - 楼层/门牌号：**橙色 + font-size: 14px + font-weight: 700**
  - Wechat（有值则显示）
  - WhatsApp（有值则显示）

#### 商品列表

按揽货批次（batch）展示，每批次显示批次标题和揽货单摘要。每个商品行：
- 顶部行：库位 chip + 条码 chip
- 商品行：缩略图 | 商品名（最多2行截断）+ 规格 + 售价/成本价 | 数量（右对齐，橙色）

#### 支付摘要

底部横排：支付金额（大字）/ 总成本价（大字），各带标签。

#### 进度条（渐进显示，按节点状态截止）

| 节点状态 | 显示到 | 字段 |
| ---- | ---- | ---- |
| 待接单揽货 | 下单 | 下单用户、下单时间、付款时间 |
| 待揽货 | 接单 | 接单人员、接单时间 |
| 待打包复核 | 揽货 | 揽货人员、揽货时间 |
| 待发货 | 打包 | 打包人员、打包时间 |
| 已发货 | 发货 | 发货人员、发货时间 |

规则：每种状态展示**到当前节点为止**的所有前置节点，最后一个节点无连接线。

---

### 方案 B：待入库任务详情

**适用节点**：待入库

#### Hero 区

| 元素 | 规则 |
| ---- | ---- |
| 任务类型 | 大标题展示"待入库" |
| 任务ID | 纯展示，无复制 |
| 原始单号 | 展示 + **复制按钮** |
| 处理状态 | chip |
| chips 行 | **不显示**（无渠道/距离 chips） |

#### 任务信息

3 个字段（前两个各占半宽，备注全宽）：

| 字段 | 说明 |
| ---- | ---- |
| 库房 | 月台/收货区名称 |
| 预约到仓时间 | 供应商预约时间 |
| 入库时间 | 实际入库完成时间，未完成时显示 `--` |
| 备注 | 橙色文字，全宽展示 |

**不显示联系人行和地址卡片。**

#### 入库商品

标题格式：`入库商品 N（共N件）`，其中 N 为 SKU 种数，N件为总件数，**均显示在标题后方，右侧无独立计数**。

每个商品行：
- 顶部行：**货位 chip（在前）** + 条码 chip（在后）
- 商品行：缩略图 | 商品名 + 规格 + 有效期 + 售价/成本价 | 数量（右对齐，橙色）

#### 进度条（渐进显示，按节点状态截止）

| 节点状态 | 显示到 | 字段 |
| ---- | ---- | ---- |
| 待入库 | 创建入库单 | 提交用户、创建时间 |
| 到仓待入库 | 到仓确认 | 确认人员、到仓时间 |
| 入库完成 | 入库完成 | 入库人员、完成时间 |

---

## 6. 关键规则

- 任务ID 为系统自增，格式 3 位补零，与原始单号分开存储展示。
- 从驾驶舱进入时，页面自动带入对应节点筛选。
- 揽货类详情与入库类详情为两套独立渲染逻辑，通过节点类型判断分支。
- 所有详情抽屉底部**只保留「关闭」按钮**，不提供业务跳转。
- 处理状态标签：已超时=红色、已完成=绿色、待处理=橙色（列表和详情统一）。
- 地址卡片中楼层/门牌号字段固定样式：橙色、14px、700 字重。
- 进度条按节点状态渐进显示，当前节点即为最后一个可见节点，最后节点无连接线。
