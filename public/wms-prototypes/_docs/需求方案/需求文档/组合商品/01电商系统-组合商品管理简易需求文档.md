# 电商系统 - 组合商品管理简易需求文档（1.0）

> 文档定位：电商运营系统「组合商品管理」简易需求，用于配合原型给技术人员/AI 进行开发。
> 范围说明：本文只覆盖【电商运营后台的组合商品维护】与【下单链路把组合展开为 SKU 行】两件事。消费者端如何展示、加购、下单组合商品的交互细节，由电商系统另行细化，不在本文范围。
> 配套文档：[02WMS系统-组合商品履约简易需求文档.md](./02WMS系统-组合商品履约简易需求文档.md)

## 1. 基本信息

- 功能名称：组合商品管理（电商运营系统）
- 所属系统：电商运营后台 · 商品管理；电商下单链路
- 适用范围：买二送一、加价购、多 SKU 打包折扣等营销组合
- 版本说明：1.0 完成「组合商品创建 / 编辑 / 上下线 / 门店与生效配置 / 组件 SKU 明细维护」闭环，并在下单成交时把组合展开为 SKU 行、固化价格与分组快照后下发 WMS。

---

## 2. 设计总原则（决定整套设计的边界）

1. **组合是营销概念，SKU 是履约实体。** WMS 只关心最终出库的 SKU 和数量，不关心组合的定价与营销规则。
2. **BOM 展开放在电商下单时做。** 组合在下单成交瞬间「塌缩」为多条 SKU 订单行，带分组标签下发 WMS；WMS 不持有组合 BOM 主数据，不卷入组合版本一致性。
3. **展开塌缩掉定价/主数据，但必须保留分组关系与原子性。** 展开 ≠ 拍平成无关联的 SKU 清单。`combo_group`（组合实例标识）和 `combo_atomic`（原子标志）必须随订单行下发，否则 WMS 无法做缺货可行性判定与退款归属。
4. **库存只按 SKU 管理，不新增组合库存。** 不做实体套装库存、组合独立入库/条码/拆包。

## 3. 数据模型与字段口径

### 3.1 组合主表 `combo`

| 字段 | 字段名 | 说明 |
| --- | --- | --- |
| 组合编码 | `combo_code` | 系统生成，唯一 |
| 组合名称 | `combo_name` | 前台展示名 |
| 主图 | `main_image` | 前台展示主图 |
| 展示价 | `display_price` | 组合整体售价（成交价） |
| 状态 | `status` | 草稿 / 上线 / 暂停 / 下线 |
| 生效开始时间 | `start_time` | 可空 |
| 生效结束时间 | `end_time` | 可空 |
| 时段限制 | `time_window` | 可空，按需配置 |
| 门店范围 | `store_scope` | 生效门店或门店集合 |
| 版本号 | `version` | 组件/价格变更即 +1，详见 3.3 |
| 退货策略 | `return_policy` | `atomic`（整组退，默认）/ `splittable`（可按组件退），详见 4 |

### 3.2 组合明细表 `combo_item`

| 字段 | 字段名 | 说明 |
| --- | --- | --- |
| 组合编码 | `combo_code` | 关联 `combo` |
| 组件 SKU | `sku_code` | 关联 WMS SKU 编码 |
| 数量 | `quantity` | 单份组合中该 SKU 的数量，必须 > 0 |
| 折扣分摊价 | `allocated_price` | 该组件在组合中的分摊单价，详见 5 |
| 是否赠品 | `is_gift` | 赠品类组件强制 `return_policy=atomic` |

### 3.3 版本快照规则（重点，避免改组合污染历史单）

1. 组合的组件 SKU、数量、分摊价、展示价发生变更时，`version` 必须 +1。
2. 用户下单成交时，订单固化引用「当时刻的组合版本快照」（含 BOM、分摊价、展示价、退货策略）。
3. 之后再改组合，只影响新订单，**永不回写已成交订单**。退款、退货、缺货判定全部以订单快照为准。

## 4. 退货策略 `return_policy`（与 WMS 逆向口径一致）

| 取值 | 含义 | 适用 |
| --- | --- | --- |
| `atomic`（默认） | 整组退：组合内所有组件必须一起退，退款 = 组合成交价 | 有赠品、有整体折扣的组合（买二送一、加价购）**强制** atomic |
| `splittable` | 可按组件退：退款 = 该组件的固化分摊价 | 仅适用于每个组件都有明确独立分摊价、无赠品的纯打包折扣组合 |

口径要点：
- 默认 `atomic`，只对明确配置过的组合开放 `splittable`。
- 含赠品（`is_gift=true`）的组合不允许设为 `splittable`。
- 退款金额一律取下单时固化的快照价，由电商售后系统计算，WMS 不参与金额。

---

## 5. 下单展开与价格固化（电商侧核心逻辑）

### 5.1 展开规则

下单成交时，把每一份组合实例展开为多条 SKU 订单行：

- **数量为 N 的组合，必须展开成 N 个独立组合实例**，每个实例分配独立的 `combo_group`（如 `A#1`、`A#2`）。原子单元是「单份组合」，不是「组合这一行」。这样才支持「发 1 份退 1 份」的部分履约。
- 单买的 SKU 行 `combo_group=null`。

展开示例（组合 A×2 = (SKU1×3 + SKU2×2)×2，另单买 SKU1×2）：

```
order_lines:
  SKU1  qty=2  combo_group=null   atomic=false   （单买）
  SKU1  qty=3  combo_group="A#1"  atomic=true     （组合A 第1份）
  SKU2  qty=2  combo_group="A#1"  atomic=true
  SKU1  qty=3  combo_group="A#2"  atomic=true     （组合A 第2份）
  SKU2  qty=2  combo_group="A#2"  atomic=true
```

### 5.2 价格分摊与固化

- 把组合展示价按规则（比例/指定）分摊到各组件 SKU 行的 `unit_price`，保证「各组件行金额合计 = 组合成交价」，满足清关/计费。
- 同一 SKU 既被单买又在组合内时，**两条行各自保留独立单价，绝不合并成一行**。例：单买 SKU1 单价 10、组合内 SKU1 分摊价 7，是两条独立订单行。
- 下单后固化：组合版本、BOM、分摊价、展示价、退货策略、`combo_group`、`atomic` 全部写入订单快照。

### 5.3 同仓约束

组合各组件应绑在同一履约单（用户买的是一套，分仓发会破坏组合体验）。展开的组合 SKU 行需标记「同仓优先/不可跨仓拆分」，对 `split_delivery_allowed` 做组合级约束（在调用 WMS 创建发货单接口时体现）。

## 7. 与 WMS 的接口边界

1. 电商通过现有「创建云仓发货单」接口下发，`order_lines` 在原结构上**新增必填字段** `combo_group`、`combo_atomic`，可选展示字段 `combo_code`/`combo_name`。
2. 电商不向 WMS 传组合 BOM 主数据；WMS 靠订单行的 `combo_group` 聚合即可重建该实例的履约需求。
3. 退款金额、退货决策、缺货沟通后的取消/换货退款均由电商侧按快照计算；WMS 只回传 SKU 收发数量。
4. 缺货沟通由 WMS 发起（揽货阶段），电商侧接收 WMS 给出的缺货归属（哪条行/哪份组合）后与客户确认并执行退款。详见 WMS 文档第 5、6 章。
