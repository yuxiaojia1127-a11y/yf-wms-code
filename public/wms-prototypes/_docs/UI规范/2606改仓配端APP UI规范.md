# 2606改仓配端 APP UI 规范

> 提取日期：2026-06-11
> 设计来源：腾讯 CoDesign / 配送端app / `2606改仓配端` 分组
> 适用对象：WMS APP 端移动原型，优先约束仓配端、配送端、仓内移动作业相关页面。
> 说明：本规范基于 CoDesign 检查页可见画板提取。当前右侧标注面板默认未展示完整图层 token，颜色值为可落地近似值；后续如能逐图层读取精确标注，可升级为精确版。

## 1. 适用范围

本规范适用于 APP 端移动工作台和作业执行类页面，包括登录、我的、工作台、选择仓库、接单揽货、揽货详情、发货、待打包、打包复核、订单详情、商品条码管理、购物车和订单结算等页面。

本规范不直接约束 WEB 后台页面。WEB 后台继续使用独立的 `WMS前端UI规范.md`，APP 端需要保持自己的移动端布局、底部导航、触控尺寸、卡片密度和现场作业视觉语言。

| 项目 | 规格 |

| 画板数量 | 30 个 |
| 设计稿尺寸 | `750 x 1624 px` |

## 3. 设计原则

1. 移动作业优先：页面首先服务现场扫码、接单、揽货、复核、发货和结算等高频动作。
2. 信息一屏可扫：列表卡片和详情页字段应保持紧凑，关键状态、数量、金额、动作必须清楚。
3. 主动作明确：每个页面只保留一个最强主动作，主按钮统一使用青绿色。
4. 状态轻量表达：状态不使用大面积高饱和底色，优先使用文字、小圆点、浅色标签或右上角状态文案。
5. 组件复用：工作台卡片、任务卡片、商品行、底部操作栏、弹窗、状态标签必须统一尺寸和样式。
6. 中英文兼容：已有中文和英文画板，组件宽度和按钮文案需要支持英文变长。

## 4. 色彩规范

### 4.1 基础色

| 用途 | 推荐值 | 使用说明 |
| --- | --- | --- |
| 品牌主色 | `#43B8A8` | 主按钮、当前 Tab、选中态、重点图标 |
| 品牌强化色 | `#2FAE9D` | 主按钮按下态、重点确认动作 |
| 顶部浅青背景 | `#DDF8F2` | 登录、工作台、我的等页面顶部渐变起色 |
| 页面背景 | `#F5F7F8` | APP 主背景 |
| 弱背景 | `#F7F8FA` | 列表分组、浅灰区块、输入框底色 |
| 卡片背景 | `#FFFFFF` | 业务卡片、商品行、详情块 |
| 主文字 | `#1F2329` | 页面标题、卡片标题、关键字段 |
| 次级文字 | `#6B7280` | 字段名、辅助信息 |
| 弱提示文字 | `#9CA3AF` | placeholder、弱提示、空状态说明 |
| 分割线 | `#EEF0F2` | 卡片内分隔、底部栏顶线、表单分割 |

### 4.2 状态色

| 状态 | 推荐值 | 使用说明 |
| --- | --- | --- |
| 待处理 / 待接单 | `#68B92E` | 任务待处理、可执行状态 |
| 已接单 / 已完成 | `#2AA7C9` | 已接单、已揽货、已复核等进度状态 |
| 处理中 / 配送中 | `#D99A19` | 等待、进行中、派送中 |
| 异常 / 失败 | `#E85B4A` | 异常、失败、校验错误、金额强调 |
| 信息提示 | `#2F80ED` | 链接、辅助信息状态 |

状态色应控制在小面积使用，禁止整卡大面积铺满高饱和红、黄、蓝。

## 5. 字体规范

字体族：

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif;
```

| 层级 | 字号 | 字重 | 使用场景 |
| --- | --- | --- | --- |
| 页面标题 | `16px` | `500-600` | 顶部栏标题，如工作台、发货、订单结算 |
| 区块标题 | `14px` | `500-600` | 卡片标题、模块标题、商品分组标题 |
| 正文 | `12px-13px` | `400` | 任务字段、商品说明、表单内容 |
| 辅助文字 | `10px-12px` | `400` | 字段名、时间、placeholder、说明 |
| 重点数字 | `18px-20px` | `500-600` | 工作台统计数、金额、数量 |
| 底部 Tab | `10px-11px` | `400-500` | 底部导航文字 |

禁止使用负 `letter-spacing`。APP 字号不随视口连续缩放，优先按组件层级定义。


## 7. 页面结构规范

### 7.1 标准移动页结构

```html
<main class="app-page">
  <header class="app-nav">...</header>
  <section class="app-content">...</section>
  <footer class="app-bottom-action">...</footer>
</main>
```

页面内容应避免大段说明文字。业务说明进入详情字段、弹窗或辅助提示。

### 7.2 顶部导航

- 高度约 `44px`。
- 左侧为返回或关闭图标。
- 中间为页面标题，居中显示。
- 右侧可放扫码、筛选、消息、更多等图标。
- 登录、工作台、我的等首页类页面允许顶部使用浅青绿色渐变背景。

### 7.3 底部导航

- 底部导航固定在页面底部。
- 当前态使用主色 `#43B8A8`。
- 未选中态使用 `#1F2329` 或 `#6B7280`。
- 图标在上、文字在下，适合 2-4 个入口。
- 需要保留 iPhone 底部安全区。

## 8. 组件规范

### 8.1 登录页

- 页面背景以白色为主，顶部可叠加浅青绿色氛围。
- Logo 居中，尺寸约 `56px-64px`。
- 欢迎语居中，正文 14px 左右。
- 输入框使用浅灰胶囊底，左侧图标，placeholder 使用弱文字色。
- 主登录按钮为青绿色胶囊按钮，高度约 `38px-42px`。
- 错误提示使用红橙色小字，靠近输入区域。

### 8.2 工作台卡片

- 工作台顶部使用浅青渐变。
- 仓库/组织切换位于顶部左侧，右侧可放扫码或消息入口。
- 业务模块按白色卡片分组，例如揽单、打包、发货、入库、其他。
- 每张模块卡片包含图标、模块名和关键数字。
- 数字使用 18px 左右，字段名使用 10px-12px。
- 其他入口使用 4 列宫格，图标低饱和彩色，文字居中。

### 8.3 搜索与筛选

- 搜索框使用浅灰胶囊底，左侧搜索图标。
- 搜索按钮使用青绿色胶囊按钮，靠右。
- 顶部状态筛选采用横向 Tab，当前项使用主色下划线或深色胶囊。
- 二级筛选可使用胶囊按钮组，当前项使用深色底或主色弱底。
- 排序筛选放在右侧，文字和图标尺寸保持紧凑。

### 8.4 任务列表卡片

任务列表卡片用于接单揽货、发货、待打包等页面。

- 卡片白底，圆角 `8px`。
- 卡片之间间距 `8px-10px`。
- 左上角显示姓名或任务主体，14px 中等字重。
- 右上角显示任务状态，使用小圆点 + 状态文字。
- 字段区采用两列或左右对齐结构，字段名弱色，字段值深色。
- 时间、单号、库房、配送方式等字段保持 12px 左右。
- 卡片底部右侧放操作按钮，主动作使用青绿色，次动作使用浅灰底。
- 单卡信息过多时优先隐藏次要字段，进入详情页展示。

### 8.5 详情页信息块

- 详情页顶部显示状态和核心订单/任务信息。
- 信息块使用白色卡片，字段名左侧弱色，字段值右侧深色或强调色。
- 金额、异常、差异等关键字段使用红橙强调。
- 商品清单、时间记录、备注等分区独立成卡片。
- 底部固定主操作按钮，如确认揽货、提交、立即支付。

#### 8.5.1 揽货详情默认态

对应 CoDesign 画板：`揽货详情`。

默认态用于展示一个待接单或待处理揽货任务的完整信息，页面结构从上到下保持稳定：

1. 返回区：顶部左侧返回图标，正文区直接展示任务状态。
2. 任务摘要：状态标题、任务 ID、订单号、复制入口、配送时效和距离。
3. 收货信息卡：库房、预约送达时间、商品缺货时、订单备注、联系人、电话、邮编、收货详情入口。
4. 商品清单：显示 `揽货商品: N` 和总件数；商品按揽货批次分组。
5. 金额汇总：支付金额和总成本价并排展示，金额数字加粗。
6. 时间记录：如下单用户、下单时间、付款时间。
7. 底部主按钮：单一青绿色胶囊按钮，例如 `确认接单`。

默认态中的商品卡以只读为主，不展示复杂操作区。商品卡需要包含库位、条码、商品图、商品名、规格、售价、成本价和右侧数量。

#### 8.5.2 揽货详情展开态

对应 CoDesign 画板：`揽货详情-展开`。

展开态用于展示更多收货地址、联系人和商品级作业操作，视觉规则如下：

- 在基础收货信息下增加灰底补充信息块，用于长地址、区县、收货地址、联系方式或其他配送补充字段。
- 补充信息块使用浅灰底 `#F7F8FA`，内部文字保持 10px-12px，长文本允许多行展示。
- 商品清单仍按批次分组，但商品卡从只读态升级为可操作态。
- 可操作商品卡内可出现动作按钮组、数量步进、选中态和局部状态。
- 商品级主动作使用青绿色小按钮；次动作使用浅灰或白底描边按钮。
- 数量步进控件保持小尺寸，按钮触控面积不低于 24px。
- 底部操作栏从单按钮变为组合操作：左侧次动作，中间扫码/识别图标按钮，右侧主动作。
- 中间扫码按钮可使用黑底圆形强调，表示现场作业的高频入口。

展开态不应改变详情页的基础信息层级。新增信息只能作为补充块或商品卡内部扩展，不要打乱任务摘要、收货信息、商品清单、底部操作的顺序。

#### 8.5.3 揽货详情其他情况态

对应 CoDesign 画板：`揽货详情-其他情况`。

其他情况态用于覆盖商品清单中的特殊作业结果和异常组合，不是新的页面结构，而是商品卡片的多态展示集合。

常见形态包括：

- 单商品正常展示：图片、标题、规格、售价、成本价、数量保持默认商品行结构。
- 单商品已选动作：商品卡内出现青绿色小按钮，表示当前选中的作业结果。
- 多商品展开：一个揽货批次下展示多条商品行，子商品之间使用浅灰分隔或轻微留白。
- 替代/换货/退货类动作：动作按钮横向排列，当前动作使用主色，未选动作使用浅灰或白底。
- 数量差异：右侧显示数量步进或数量输入，异常数量旁可出现红色提示。
- 异常提示：使用红橙色小字展示在商品卡下方，不单独占用大卡片。
- 商品组提示：在分组标题右侧可出现橙色或红橙色小标签，提示该组存在特殊状态。

其他情况态的设计重点是“局部异常局部展示”。不要把整个详情页改成异常页，也不要用大面积红色背景。异常、缺货、替换、换货、退货等状态应优先收敛在商品卡内部。

#### 8.5.4 详情页多态落地规则

- 同一个详情页必须复用同一套基础骨架：任务摘要、收货信息、商品清单、金额/时间、底部操作。
- 默认态、展开态和其他情况态通过局部组件状态切换，不应生成三套完全不同的页面样式。
- 商品卡至少支持 `readonly`、`expanded`、`actionable`、`exception` 四类视觉状态。
- 批次标题格式建议保持为 `揽货#N | 第N/共N张揽货单`，辅助文字使用主色。
- 商品数量统一放在卡片右侧，格式使用 `xN` 或小型步进控件，不能同时出现多套数量表达。
- 商品级错误提示使用 `--app-danger`，字号不超过 11px。
- 多操作底部栏中，主动作永远放右侧；扫码类高频动作可居中突出；返回、暂存、任务勾选等次动作放左侧。

### 8.6 商品行

- 商品图片尺寸建议 `52px-60px`。
- 商品标题最多两行，超出省略。
- SKU、规格、条码使用 10px-12px 弱色。
- 价格使用红橙色。
- 数量控件靠右，按钮面积应满足触控。
- 多商品列表需要保留卡片分隔和小间距，避免整页拥挤。

### 8.7 金额与结算栏

- 结算页底部固定白色操作栏。
- 左侧显示合计金额，金额数字使用红橙色。
- 右侧为主按钮，青绿色胶囊。
- 优惠、配送费、税费等明细使用卡片或列表行展示。
- 底部操作栏顶部使用 `#EEF0F2` 细分割线。

### 8.8 弹窗

- 弹窗居中或底部弹出，优先用于确认、异常说明、筛选。
- 背景遮罩使用黑色 35%-45% 透明度。
- 弹窗圆角 `12px-16px`。
- 主按钮青绿色，取消按钮浅灰。
- 文案简短，重点信息使用主文字或红橙强调。

## 10. 后续落地规则

1. 新增 APP 页面必须优先套用本规范，不再临时发明颜色、圆角和卡片样式。
2. 当前 APP 原型改造时，先把本规范转成共享 APP CSS，再逐页替换页面级样式。
3. 正式 APP 原型文件仍只保留在 `public/wms-prototypes/APP端HTML原型/WMS-APP端原型.html`。
4. AI 新生成的 APP 页面草稿应先放入 `public/wms-prototypes/_drafts/`，确认后再合并正式文件。
5. 后续如从 CoDesign 获取到精确图层标注，应校准本文件中的主色、字号、间距、圆角和阴影 token。

## 11. 当前提取限制

- CoDesign 当前检查页可见画板可访问，但右侧标注面板默认显示为空，未能一次性导出完整 token。
- 本文件的颜色值为基于可见页面的近似落地值，足以指导当前原型统一视觉。
- 如需要百分比更高的视觉还原，应继续逐个点击关键图层，补充精确的 fill、font、radius、shadow、spacing 数据。
