## 2. 使用原则

| 原则 | 说明 |
| ---- | ---- |
| 先校验主状态 | 先验证对象主状态能否正确流转，再验证节点状态和结果状态 |
| 页面与后台双校验 | 同时验证列表筛选、详情标签、时间线、操作按钮与后台结果是否一致 |
| 终态必须可回溯 | 已完成、已取消、异常等终态必须可在日志、时间线或结果记录中追溯 |
| 异常必须可拦截 | 非法流转、重复提交、前置条件不满足时必须阻断并给出明确提示 |
| 状态总表优先 | 如本矩阵示例与状态口径总表存在差异，以状态口径总表为准 |

## 3. 页面通用状态测试矩阵

| 场景 | 前置条件 | 触发动作 | 预期状态流转 | 预期页面表现 | 关键校验点 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 默认加载 | 用户具备模块权限且接口正常 | 进入列表页或详情页 | 进入默认页面状态 | 展示最近数据、默认筛选、生效标签 | 不应误展示空态或失败态 |
| 条件筛选 | 页面已有数据 | 输入筛选条件并查询 | 默认 -> 筛选中 | 列表数据按条件刷新 | 筛选条件与结果总数一致 |
| 空数据 | 当前条件无记录 | 查询 | 默认/筛选中 -> 空数据 | 展示空状态文案和清空筛选入口 | 不应残留旧列表数据 |
| 加载失败 | 接口超时或服务异常 | 进入页面或刷新 | 默认 -> 加载失败 | 展示失败提示和重试入口 | 不应误写业务状态 |
| 无权限 | 用户无模块或上下文权限 | 进入页面 | 默认 -> 无权限 | 展示权限说明，不展示业务数据 | 操作按钮全部禁用或隐藏 |
| 操作成功 | 目标对象满足操作条件 | 执行保存、确认、重推等动作 | 操作反馈 -> 操作成功 | 消息提示成功，列表或详情刷新 | 成功后状态和按钮权限同步变化 |
| 操作失败 | 参数错误或状态冲突 | 提交操作 | 操作反馈 -> 操作失败 | 展示失败原因，保留当前上下文 | 不应写入错误状态 |

## 12. 关键异常拦截测试

| 场景 | 异常条件 | 预期结果 | 关键校验点 |
| ---- | ---- | ---- | ---- |
| 重复完成终态对象 | 已完成/已取消对象再次提交操作 | 阻断操作并提示状态冲突 | 不得重复写入时间线 |
| 非法跳过中间状态 | 直接从待受理跳到已完成 | 阻断流转 | 后端和前端双重校验 |
| 列表筛选与详情状态不一致 | 列表状态与详情标签不同 | 视为缺陷 | 列表、详情、时间线必须一致 |
| 异常恢复后未更新标签 | 异常已处理但页面仍显示异常 | 视为缺陷 | 状态更新后列表和详情同时刷新 |
| 状态回流延迟 | APP 或物流结果已提交，Web 未刷新 | 应提示更新时间或支持刷新 | 延迟展示需可解释、可追溯 |

## 13. 回归优先级建议

| 优先级 | 覆盖对象 | 说明 |
| ---- | ---- | ---- |
| P0 | 入库单、出库单、发货履约单、运单、页面通用状态 | 首批上线和主流程必须覆盖 |
