# 商品管理后台原型设计（整合版）

## 1. 方案结论

- 采用 `一个一级菜单 + 两类角色视图 + 四个核心页面` 的方案
- 不拆两套系统，统一使用一套商品底层数据
- 货主侧聚焦“我的商品”
- WMS侧聚焦“货主商品管理 + 商品识别档案 + 识别异常处理”

## 2. 哪套更合适

### 2.1 对比结论

- [01商品管理后台原型设计-大框架.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/需求方案/需求文档/00简易需求/商品管理/01商品管理后台原型设计-大框架.md) 更适合做第一轮框架定版
- [02商品管理后台原型设计.md](file:///Users/yuxiaojia/Documents/项目/YF/YF-wms-web/YF-wms-web-code/docs/需求方案/需求文档/00简易需求/商品管理/02商品管理后台原型设计.md) 更适合继续细化页面结构
- 最终方案应采用：`01 的工作台框架 + 02 的页面关系和页面级说明`

### 2.2 取舍原因

- `01` 优点：角色、工作台、导航结构更稳，信息架构更清楚
- `01` 不足：还停留在大框架，缺少足够的页面落地说明
- `02` 优点：页面级设计更完整，便于继续画原型
- `02` 不足：相比 `01` 略分散，框架感稍弱

## 4. 角色视图

| 角色 | 默认入口 | 数据范围 | 页面范围 |
| --- | --- | --- | --- |
| 货主用户 | 我的商品 | 本货主 | 我的商品 |
| WMS商品运营 | 货主商品管理 | 全量货主 | 货主商品管理、商品识别档案 |
| WMS商品治理 | 商品识别档案 | 全量识别数据 | 商品识别档案、识别异常处理 |

## 5. 四个核心页面

### 5.1 我的商品

- 面向货主用户
- 目标：维护本货主商品资料、仓储规则、同步状态
- 页面结构：标题区 + 统计区 + 查询区 + 列表区 + 详情/编辑抽屉
- 页面重点：不强调识别治理，只展示必要的识别状态和同步状态

### 5.2 货主商品管理

- 面向 WMS 商品运营
- 目标：查看全量货主商品、追踪同步状态、联查识别结果
- 页面结构：标题区 + 统计区 + 查询区 + 列表区 + 详情抽屉
- 页面重点：增加货主筛选、WMS商品编码、识别商品ID、识别状态

### 5.3 商品识别档案

- 面向 WMS 商品运营、WMS 商品治理
- 目标：查看系统生成的 WMS 商品识别档案
- 页面结构：标题区 + 统计区 + 查询区 + 识别档案列表 + 右侧详情侧板
- 页面重点：一个识别商品ID下关联哪些货主商品、字段差异是什么、是否具备供给关系基础

### 5.4 识别异常处理

- 面向 WMS 商品治理
- 目标：处理条码相同但单位、规格、仓储规则冲突的数据
- 页面结构：标题区 + 统计区 + 查询区 + 异常列表 + 右侧字段对比区
- 页面重点：高亮冲突字段、查看处理记录、形成异常闭环

## 6. 页面关系

| 来源页面 | 触发动作 | 目标页面 |
| --- | --- | --- |
| 我的商品 | 查看/编辑商品 | 商品详情抽屉 |
| 货主商品管理 | 查看商品 | 商品详情抽屉 |
| 货主商品管理 | 点击识别商品ID | 商品识别档案 |
| 货主商品管理 | 点击识别异常状态 | 识别异常处理 |
| 商品识别档案 | 查看关联货主商品 | 货主商品管理筛选结果 |
| 识别异常处理 | 查看商品明细 | 货主商品管理筛选结果 |

## 9. 整合结论

这次整合后，最合适的方案是：

1. 用 `01` 的“三个工作台”思想做整体导航框架
2. 用 `02` 的“四个核心页面”做实际页面落地
3. 原型第一版先画：
   - 我的商品
   - 货主商品管理
   - 商品识别档案
   - 识别异常处理
4. 供给关系管理放到第二阶段，不放进第一版核心画面
