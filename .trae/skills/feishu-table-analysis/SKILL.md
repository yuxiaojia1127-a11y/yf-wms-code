# 飞书表格分析

用于分析飞书表格、飞书多维表格、飞书在线表单结果页等“页面可见但结构化抓取不稳定”的数据页面。

## 何时使用

在以下场景优先调用本技能：

- 用户提供飞书表格链接，要求分析、总结、分类、提炼需求、识别缺口
- 用户说“我浏览器已经打开了这份飞书表格”，希望直接基于当前页面分析
- 普通网页抓取只能拿到页面壳、函数帮助、快捷键、登录按钮等非业务内容
- 需要确认“是否真的能看到真实数据”，不能凭猜测输出结论

## 核心原则

1. 先验证，再分析。
2. 先说明“能看到什么”，再说明“能分析什么”。
3. 如果拿不到真实表格数据，必须明确说明限制，不得自行补全或推测。
4. 如果静态抓取与浏览器实景不一致，以浏览器实景核验结果为准。
5. 分析输出必须区分：
   - 已确认可见信息
   - 推断性判断
   - 无法确认项

## 标准工作流

### 第一步：静态抓取初判

先尝试读取链接页面的静态文本，判断是否能直接拿到表格正文。

重点识别以下信号：

- 只出现标题、工具栏、快捷键、函数说明、登录按钮
- 出现“加载中”“只能阅读”“0 / 0”“查找”“筛选”等外围信息
- 没有明确字段头、没有业务记录行

如果静态抓取已经拿到真实字段和多行业务记录，可以进入分析。

如果静态抓取拿不到真实数据，不要直接下最终结论，进入第二步。

### 第二步：浏览器页面核验

如果用户已在浏览器打开该飞书页面，必须检查当前浏览器页实际渲染结果。

核验目标：

- 页面是否真的显示了真实表格内容
- 是否受登录拦截
- 是否属于动态渲染、虚拟表格、画布渲染
- 肉眼可见内容与 DOM/静态抓取是否不一致

重点观察：

- 当前页标题
- 表头字段
- 可见记录行
- 右上角是否有登录/注册按钮
- 页面是否有权限提示、空白提示、加载失败提示
- 可视截图中是否能直接读到需求/数据明细

### 第三步：判定数据可分析级别

根据抓取结果，把页面分成以下三类：

#### A. 可完整分析

满足条件：

- 能稳定获取字段头
- 能看到多行真实数据
- 能识别主要列含义

处理方式：

- 直接输出结构化分析
- 可继续做分类、优先级、问题归纳、PRD/原型映射

#### B. 可部分分析

满足条件：

- 能看到部分字段头
- 能看到若干行真实数据
- 但不能稳定提取全量表格

处理方式：

- 仅基于当前可见数据做“初步分析”
- 明确声明分析范围仅覆盖当前可见区域
- 不对未看到的行做结论

#### C. 不可有效分析

满足条件：

- 只能看到页面外壳
- 无法确认字段头
- 无法确认真实记录

处理方式：

- 如实说明无法获取真实数据
- 建议用户提供截图、导出文件或更完整的公开链接

## 输出格式

输出时优先使用以下结构：

### 1. 访问结论

- 是否能打开链接
- 是否能看到真实数据
- 是否受登录影响
- 是否受动态渲染影响

### 2. 当前确认可见字段

- 列出已确认的表头字段
- 如果字段不完整，要明确说明“仅当前视图可见”

### 3. 当前确认可见数据

- 列出当前能识别的记录、需求名称、模块、优先级或内容片段
- 明确说明是“当前可见内容”还是“全表内容”

### 4. 分析结论

- 按模块分类
- 按优先级分类
- 按业务主题分类
- 识别重复项、缺口项、依赖项

### 5. 可信度声明

必须明确说明以下之一：

- 本次基于全量可见数据分析
- 本次仅基于当前可见区域初步分析
- 当前无法有效分析真实表格数据

### 6. 下一步建议

- 是否需要用户提供截图
- 是否需要导出 Excel/CSV
- 是否继续基于当前浏览器页滚动查看更多内容

## 禁止事项

- 不得把函数帮助页、快捷键页误判为业务表格正文
- 不得把“浏览器里能看到一点内容”直接说成“已拿到全量数据”
- 不得根据表格标题自行脑补字段或需求内容
- 不得省略“可见范围”和“可信度声明”

## 典型判断句式

### 当静态抓取失败但浏览器可见时

可以这样说：

- 我能打开链接，但静态抓取拿不到真实表格正文。
- 直接检查浏览器页面后，已确认当前页面可见真实数据。
- 这类飞书表格受动态渲染影响较大，肉眼可见内容不等于结构化抓取可见内容。

### 当只能部分看到数据时

可以这样说：

- 我目前只能基于当前屏幕可见区域做初步分析，不能代表整张表全量内容。

### 当完全拿不到数据时

可以这样说：

- 我目前不能确认表格里的真实业务数据，只能看到页面外壳/帮助信息，因此不能负责任地继续分析。

## 推荐分析维度

如果页面可见的是需求类表格，优先从以下维度分析：

- 菜单/模块分布
- 优先级分布
- 端别分布：Web / App / API / 后台
- 业务主题：仓储、物流、风控、商品、售后、营销等
- 重复需求与合并建议
- 与现有功能清单/PRD/原型计划的映射关系
- 可直接进入原型设计的需求
- 仍需补充简易 PRD 的需求

- “分析这份飞书表格”

- “帮我整理这份飞书需求表”

- “把这个飞书高需求表和 PRD 对一下”
